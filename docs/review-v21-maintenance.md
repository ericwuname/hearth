## 二、v21 的战略价值（为什么这是对的终点）

锻造九轮里，我们曾反复在"加经验 / 换模型 / 加治理 RFC"上漂移（你之前说的"信息越多决策越难"正是这个症状）。v21 一刀做了三件事，正好对应 telos 过滤器的"停止"层：

1. **消债**：embedding 死代码 + 5 处硬编码 key —— 这两项本就是"实验没收益却留着负债"的典型，删了系统更轻、更安全。
2. **固化**：两篇设计决策（`design-decision-experience.md` / `design-decision-planner-v20.md`）把"经验是降级通道""all_done 要真实写"写死，并各挂 wiring 红线。**未来任何人想回退，断言会红、CI 会拦**——这是把九轮的教训变成"不可绕过"的 G1 反射基因。
3. **立规**：维护规程让"不漂移"变成常态纪律（季度只体检、不加功能、不跑实验）。

这正契合上次我们钉死的终点：**长周期可信委托 + 不可绕过硬边界**。v21 没提高跑分，但把"可信"和"硬边界"从口号变成了 wiring 锚定的现实。

## 五、全局理解的最终状态

从 v11.5（07-30，早于基因系统）到 v21（08-01），九轮锻造把"一个会写代码的 Rust agent"收敛成：

- **不可绕过硬边界**：G0 sandbox/landlock/seccomp + 14 条 wiring 锚定（含 3 条 v19-v21 新增）
- **planner 真 bug 已修**：T13/T19 六轮全挂的根因（`all_done` 误判）根治，wiring 钉死
- **经验降级通道**：对强模型零污染、对弱模型保留 +20pt，自适应开关 + 遗忘机制就位
- **零硬编码密钥**：5 处 key 入 `.env`，仓库清洁
- **维护纪律**：季度体检 + 红线 + 不跑实验 = 漂移终止机制

**终点（长周期可信委托）已具备骨架**。维护期不是"躺平"，是"用纪律守住已得到的"，把判断带宽留给真正会出现的靶心（红线触发 / 人硅边界测试暴露 G0 漏洞）。

对外 RFC（CN-001 / RFC-004 v3 / RFC-005 替代路径）维持暂停——它们属"有益可等"，在维护期不重启，除非出现可测量靶心。

## 一、思考（为什么打这一仗）

**起因是一条扎心的对照**：同一个模型（agnes-2.5-flash），在 codex CLI 里跑得顺畅，在 hearth 里各种别扭。这说明此前归因给"模型层残差"的说法有洞——**相当一部分问题是我们喂给模型的东西有问题**。

凌晨四问把病根钉死了两个：

1. **编排病**：按"防强模型失控"设计的治理层（相位机/give_up 三臂/判定门），实际压垮的是弱模型——框架越负责，模型越被动。实测证据：A 臂（单循环）比 B 臂（全相位）快 73.6%。
2. **膨胀病**（四问后新增发现）：每次 LLM 调用都全额重复支付常驻治理文本（宪法 3.5K/talent/账本），单条任务累计最高 45 万 tokens 压不住——**注意力税是复利**。手术删了 5,000 行编排，账单反升 23.6%，坐实主犯是 prompt 不是相位机。

**战略结论**：架构哲学与模型能力错配——不是代码烂（沙箱 4.5/5 等工程资产真实），是治理方式错了。新路线四件：单循环消息循环、prompt 瘦身（基底 ≤2K、治理文本降为事后投影）、垂直切片加功能、验收换代（**用户连续 3 个真实小任务不骂人=主验收**，自设判分降为内部指标）。

## 五、方法论沉淀（这场仗打出来的规矩）

- **实测证据优先于静态清单**：宪法注入曾列"核心资产"实为肥胖元凶；编辑工具曾被列为"缺口"实已存在——两个方向都验证过"不信清单信源码"。
- **门槛先于数据钉死**：验收判据全部在看见数据之前签署，杜绝事后挪线。
- **义务显式转轨**：判据未达不赖账也不硬凿——记账为"未达"，义务转入有明确兑现条件的下一站，到期兑付否则复活。
- **战报强制"异见栏"**：每轮必答"本轮证据里与主流叙事矛盾的反例是什么"。

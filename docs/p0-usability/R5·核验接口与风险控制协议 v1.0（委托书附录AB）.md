# R5 · 核验接口与风险控制协议 v1.0（委托书附录 A/B）

> **目的**：traecode 施工期间与完工后，验收窗（WorkBuddy/砺）**不需要读懂他写的每一行代码**也能可靠验收；同时把委托施工的风险逐条锁死。
> **核心原则**：**验收只采信验收窗自己能独立复现的证据，不采信施工方的转述。**（砺铁律："不信报告信源码"的施工版）

---

## 附录 A · 核验接口（traecode 每件完工必须产出的"证据包"）

### A.1 证据包五要素（缺一即打回）

| # | 要素 | 格式要求 | 验收窗怎么用 |
|---|---|---|---|
| 1 | **commit hash** | 每件施工一个独立 commit（message 格式 `fix(r5-x): <语义摘要>`），**禁止多件混一 commit** | `git show <hash>` 直接读 diff——改动是否匹配坐标、是否越界 |
| 2 | **改动清单** | 文件列表 + 每文件 +/- 行数 + 一句话改动语义 | 与委托书坐标对照（改的文件对不对、有没有碰禁区） |
| 3 | **判据实测原始输出** | 跑测/断言的**原文粘贴**（非转述、非总结）——含命令行与完整输出 | 我**独立复跑**同判据比对（不采信粘贴，粘贴只证明他跑过） |
| 4 | **门禁输出原文** | `p0_gate_r1full.sh` 的 FMT/CLIPPY/TEST 三 RC + PASSED/FAILED 数字 | 与基线 501/0 对照，倒退即打回 |
| 5 | **跑测日志落盘路径** | .133 上 `/home/wutao/fa/<判据名>.log`（mtime + 首尾时间戳） | 我 sftp 拉回，验证时间戳/引擎身份标记/判据计数 |

### A.2 战报模板（traecode 逐件填报）

```
[R5-x] <语义名>
病理：<一句话（委托书已给，确认理解一致）>
改动：<commit hash> <文件列表±行数>
判据：<预注册判据原文> → 实测结果 <数字/原文粘贴>
门禁：<FMT=0 CLIPPY=0 TEST=0 PASSED=50x>
日志：<.133 路径 + mtime>
自检：<哪里没把握/边界情况，如实写>
```

### A.3 验收窗核验动作（每件 ~10 分钟额度）

1. `git show <hash> --stat` + 读 diff（越界审查：禁区文件、无关改动、判据相关代码是否真改）；
2. **独立复跑判据**（关键件必跑：R5-1 同错计数、R5-4 首轮不搜 *.go、R5-8 失败+VERIFIED）——**不采信施工方粘贴**；
3. 跑测日志抽查（mtime/时间戳/引擎版本标记 0.2.24）；
4. 抽验源码锚点（grep 判断改动在位、无 `#[allow]` 压警告式糊弄）。

### A.4 全部完工的总验收证据包

- 12 件战报 + 全部 commit hash 清单；
- **用户原话场景跑测日志**（"hearth TUI 项目进度"首轮不搜 *.go——单次判负）；
- C 语料 L285 场景重放日志（同错 ≤2 且第二次命令不同）；
- 门禁最终输出（501+ 基线不倒退）；
- 版本号 bump 0.2.25 的 `--version` 输出；
- Q-1/Q-2/Q-3 清欠证据。

## 附录 B · 风险清单与控制（十条，逐条有锁）

| # | 风险 | 概率 | 后果 | 控制锁 |
|---|---|---|---|---|
| 1 | **跑错引擎**（PATH 旧版 0.2.23——已发生三次） | 高（历史） | 全部数据作废 | HEARTH_BIN env 固化进脚本 + alias + 每次跑测日志必须含 `--version` 标记 + 验收窗独立复跑 |
| 2 | **越界改动**（改 constitution 文本 / R1-1 三臂语义 / 删测试 / 动冻结判据） | 中 | 验收门失效、语义回退 | commit diff 逐件审查 + 门禁含 R1/R2 回归测试（动了必红）+ 禁区清单写入委托书 §三 |
| 3 | **判据幻觉**（LLM 报"判据通过"但没跑/跑错/粘贴编造） | 中高 | 假绿验收 | 验收窗**独立复跑关键判据**（A.3-2）+ 日志文件 mtime/时间戳验证 + 数字与日志交叉比对 |
| 4 | **质量塌方**（traecode 写出的代码劣化/引入回归） | 中 | 门禁倒退、体感恶化 | 501/0 硬门（R1/R2 回归在内，改坏必红）+ 判据可证伪（修不好=未修）+ diff 抽验 |
| 5 | **环境破坏**（误删工作区/覆盖 config/动 /usr/local/bin） | 低 | 跑测环境损毁 | 禁 sudo（无权限天然锁）+ 禁区清单 + 工作区有 git（可回滚）+ 本地 tar 备份在案 |
| 6 | **半成品/烂尾**（12 件做几件或浅尝辄止） | 中 | 包失数 | 逐件战报强制（缺件即缺证据）+ 总验收 8 条逐项勾 + 顶层里程碑看板 |
| 7 | **协议漂移**（自作主张改判据/放宽验收线） | 中 | 预注册失效 | 判据预注册已锁（任务包 §六）——**判据改动需顶层批**，战报模板里判据原文必须与委托书一致（diff 可见） |
| 8 | **会话断裂/上下文丢失**（traecode 长会话压缩） | 中高 | 施工中断、状态丢失 | 委托书自包含（可重读重启）+ **战报与证据写进 repo**（`docs/p0-usability/r5-reports/`）——repo 是持久交接面，会话死了进度不死 |
| 9 | **多窗口并发冲突**（traecode 施工时验收窗也动 .133） | 中 | 状态互踩、日志污染 | **施工期 .133 归 traecode 专属写权**；验收窗只读（sftp 拉日志）；我方暂停一切 .133 写操作 |
| 10 | **WorkBuddy 额度耗尽后无人核验** | 中 | 验收真空 | 核验动作设计为**低额度可执行**（git show + grep + 一次复跑 ≈ 每件 10 分钟）+ 协议文档化（砺或其他窗口可按 A.3 清单接手）+ 证据在 repo 持久化 |

### B.1 三条最高优先级的硬规则（写进给 traecode 的第一句话）

1. **每件一个 commit，禁止混装**——验收按 commit 逐件审；
2. **判据原文粘贴 + 验收窗独立复跑**——转述无效；
3. **战报与证据写进 repo**（`docs/p0-usability/r5-reports/`）——会话可死，repo 不死。

### B.2 验收窗自己也要守的（自我约束）

1. 施工期不动 .133 写操作（只读拉日志）；
2. 核验判据用**与 traecode 相同的命令**（口径一致，避免"我用不同方法测出不同数字"的争端）；
3. 打回时给出**具体缺失项**（A.1 五要素哪条缺），不接受模糊打回；
4. 每件核验结论落 repo（`r5-reports/acceptance-R5-x.md`）——验收记录本身可审计。

## 生效

本协议自 traecode 确认接收委托书起生效。**A.1 五要素与 B.1 三硬规则为不可协商项**——traecode 若不同意，施工不开始。

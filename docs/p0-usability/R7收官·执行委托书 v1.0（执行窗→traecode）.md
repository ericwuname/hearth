### 病理签名（B5 实证，修复前先读懂）
现象：A 臂 B5（`HEARTH_SECCOMP_MODE=errno cargo build`）——Done 全部输出打印完毕，**hearth 进程不退出**；`ps` 可见 bash/cargo `<defunct>`（已死未收割）；1054s 后人工 kill（exit 137）。
两个候选根因（不预判，施工时用证据定）：
1. **孙进程管道继承**：cargo 派生的 rustc 继承 stdout/stderr 管道且比 bash 活得久 → `wait_with_output()` 的 read 永不 EOF → spawn_blocking 线程永久阻塞 → tokio runtime shutdown 被卡 → 进程不退出，且 wait() 永远没执行到 → 子进程 defunct。**此假设与"Done 已打印但进程不退"完全吻合**（主任务已完，runtime 收摊被阻塞线程拖住）。
2. **waitpid 缺失/条件竞争**：timeout/PID-watch 线程与 wait_with_output 竞争，或某路径只 kill 不 wait。
修复方向由你定（进程组 + 孙进程收割 / 管道读加超时兜底 / 显式 waitpid 补收），但验收只看行为。

### 可证伪判据（手册原文 + 补充）
1. B5 场景复跑（`HEARTH_SECCOMP_MODE=errno cargo build`）：批次不挂起、`ps` 无 defunct、门禁绿；
2. **补充——孙进程存活场景**：构造"孙进程比直接子进程活得久"的用例（如 bash 内起 `sh -c 'sleep N & exec cargo build'` 或直接 cargo build 实测），进程在 Done 后 ≤ 数秒内退出；
3. `.131` + `.133` 双机验证各一次；
4. diff 越界审查干净（安全语义零改动）；
5. 门禁全绿（基线 524/0 口径，新测试计入后报新数，口径分树标注）。

## 二、R7-3 · P2 版本串 staleness

### 源码坐标（96f4161，下笔前重新 grep）
- `crates/codex-cli/build.rs:6-17`：版本注入现只挂了 `rerun-if-changed=build.rs` 和 `rerun-if-env-changed=HEARTH_GIT_SHA`——`git rev-parse` 的结果变化**不触发重编**，这就是 96f4161 重建后 `--version` 仍显示 1429b58 的根因。

### 修法要求
- `cargo:rerun-if-changed=.git/HEAD` **加** `.git/refs/heads`（目录）——HEAD 本身是指向 ref 文件的指针，只盯 HEAD 不够；
- `HEARTH_GIT_SHA` env 优先级保留（VM 解压目录无 .git 的部署路径不回归）；
- 非 git 环境降级 "unknown" 行为不变。

### 可证伪判据
git pull / 新 commit 后重建，`hearth --version` = 新 HEAD commit；连续两次重建版本串不漂移；门禁绿。

## 二、修法（三段式，委托书"重试一次 / 显式标注 / 禁计有效步"全实现）

1. **空轮判定** `AgentLoop::is_empty_content_turn`（loop.rs:2911）：None / 纯空白 / 精确匹配已知填充文本（"no response requested"/"no response"，忽略大小写与尾点）。**保守集合**——前缀重合但非精确匹配的实质正文不误伤（有测试钉死）。
2. **重试一次**（do_plan_inner，loop.rs:3513-3556）：空轮且无 tool_calls → 追加提示"你上一轮没有给出实质回应（空内容或填充文本）。请给出实质回应或调用工具推进目标。"重发一次（usage 照常入账 CostMeter）；重试成功拿实质回应 → 正常路径、streak 清零。
3. **空轮确认路径**（loop.rs:3560-3604）：重试后仍空/重试调用失败 →
   - 裸透传禁止：不发填充文本，改发显式标注 `[模型本轮无实质回应]`（判据允许"仅显式标注形式"）；
   - 历史记占位 assistant 消息（防污染出站过滤与下一轮语境）+ `[System]` 换向注入；
   - **空轮不是模型 end_turn**：绕过 A 臂 Done 判定，next=Plan 重入（策略换向）；
   - **计步豁免**：置 `empty_turn_active`，主循环（loop.rs:5737-5754）对 steps（终态 N steps 口径）与 ctx_mgr.steps_used（预算口径）双双跳过该次递增；
   - **防烧预算**：连续 2 轮空轮（各含重试）→ `LoopPhase::Error("empty_turn: ...")` 强制终止（RunReport ok=false，error_detail 可审计）。

## 四、执行窗补充发现（如实申报）

1. **门禁 fmt 假绿陷阱**：首轮门禁脚本用 `cargo fmt --check | head -5; echo RC=$?`——管道 RC 取的是 `head`（恒 0），fmt diff 被静默掩盖。R7 门禁同款脚本 → **R7 的 FMT 绿实为假绿**（fmt 收编 commit 5b45c57 实证：5 文件存量 diff）。本轮已修（RC 直取 + 补跑真 fmt 绿）。此发现同步记入包A-2 战报。
2. **pull 假更新陷阱**：`git pull | tail -1` 在 pull 被 dirty file 拒绝时，中文 locale 输出的最后一行恰是"更新 ebd2f52..9627c06"（误导性目标行），错误行被 tail 截掉。本轮已修（PULL_RC=${PIPESTATUS[0]} + git log 复核）。

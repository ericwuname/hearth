## 一、病理（证据锚定）

- **现象**（.133 A 臂 B5 首曝，阶段2战报 §三-1）：`HEARTH_SECCOMP_MODE=errno cargo build` 场景——Done 全部输出打印完毕，hearth 进程不退出；`ps`：bash/cargo 均 `<defunct>`；1054s 后人工 kill（rc=137）。
- **根因（假设1证实：孙进程管道继承）**：`wait_with_output()` = 先把 stdout/stderr 排空到 EOF、再 wait()。cargo 派生的 rustc 孙进程**继承管道写端**且比 bash 活得久 → read 永不 EOF → spawn_blocking 线程永久阻塞 → tokio runtime 收摊被拖住（主任务已完成、报告已打印，进程停在收摊）；wait() 永远未执行 → 直接子进程 `<defunct>`。
- **连带事故（修复期间实锤，记为运维教训）**：该僵尸 27263（13:32 产生）**持有 `~/.cargo/.package-cache` 的内核 flock 直至被收割**——/proc/locks 实证（`10:10: FLOCK WRITE 27263 08:02:1705790`，46834/47435 两条 `->` 等待链）——.133 全部 cargo 操作被楔死 10 小时。`rm .package-cache`（换 inode）解锁。**僵尸不只泄漏内存槽位，还会以文件锁为杠杆楔死整条工具链**。

## 二、修复（三件套，全部在授权范围内）

1. **pre_exec setsid**（lib.rs pre_exec 闭包）：child 成为自己的组长/会话首（pgid==pid）；**失败即放弃 spawn（fail-closed）**——组杀不变式无条件成立。setsid 不触碰 landlock/seccomp/cgroups 语义（它在 sandbox_pre_exec 安全钩子**之前**执行，钩子函数本体零改动）。
2. **收割序列重构**（spawn_blocking 内）：①stdout/stderr 读线程并行排空（wait() 阻塞期间管道不会写满死锁）；②`child.wait()` 第一时刻收割直接子进程（无僵尸）；③`getpgid(pid)==pid` 前置校验后 `kill(-pid, SIGKILL)` 组杀滞留孙进程 → 管道写端关闭 → 读线程命中 EOF；④join 读线程。非组长（极端情形）退化为不组杀——不误伤优先。
3. **timeout 路径组杀升级**：旧码只 `kill(pid)`（孙进程泄漏）；新码 `getpgid` 校验后 `kill(-pid)` + 兜底 `kill(pid)`。

**diff 越界审查**：`git show f09d3d8` 全部改动集中于 spawn_blocking 闭包、timeout 分支、新测试；landlock/seccomp/cgroups 相关行仅注释上下文，`apply_landlock_in_child` / `apply_seccomp_deny_list` / `apply_cgroups_impl` / `sandbox_pre_exec` 四个安全函数**零改动**。

## 一、A-2-1 · system prompt 收敛指引 + 无事实收口机制

### 施工内容
1. **产物类 system prompt 增补 CONVERGENCE DISCIPLINE 段**（loop.rs:2461-2467，build_messages 内）：
   - 目标不明/缺输入 → 停止探索，纯文本向用户提问（文本回复即 end_turn，用户会答）；
   - 连续 3 步无新事实无产物变更 → 禁止同类 read/grep/bash 循环：要么问，要么收口（交付现有成果+说明缺口）。
2. **运行时机制（委托书"连续 3 步无新事实→强制收口"）**：`a_arm_act_tally()`（loop.rs:4268-4338）——Act 尾部计数，`steps_without_progress >= 3` 且未注入过 → 一次性 `[convergence]` 强制收口指令注入历史；write 类成功 → 计数清零 + 重新武装。

### 关键发现：原计数器在 A 臂断线（本杠杆的主修复点）
`steps_without_progress` 原只在 do_reflect 维护——**R6-9 A 臂撤销 Observe/Reflect 相位后（do_act 尾部直接回 Plan，loop.rs:4248-4258），该计数器在 A 臂恒零**。A 臂是生产主跑测路径 → "3 步无新事实收口"机制在生产路径从未生效过。本次在 Act 尾部补线（口径与 B 臂 do_reflect 逐字一致：write 类成功 = 事实进展，read/glob/grep/bash 不算）。

### 修复（双闸注入，loop.rs:5436-5479）
- **50%** `[budget-warn]`：user 消息注入模型历史（原 ThinkSummary 用户投影保留）——"评估剩余工作能否在预算内完成：能则加速收敛；不能则优先准备收口"；
- **80%** `[budget-critical]`（新闸）：user 消息——"剩余步数不足以支撑新的探索。立即收口：停止开启新子任务，用现有成果给出最终交付"；

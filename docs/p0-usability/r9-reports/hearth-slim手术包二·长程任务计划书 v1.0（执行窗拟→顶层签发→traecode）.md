## 卡 S7 · provider 瞬时故障分级长退避重试

**病灶**：LLM 调用重试=退避 2/4/8/16s≈30s+cap 120s 打满即 failed（loop.rs :5327 测试锚点）。真机：魂斗罗 span 125s 终止，用户原话"等 1 分钟或者几分钟再试"。

**实施**：
1. LLM 调用错误分类函数：`transient`（连接失败/读超时/429/5xx/TLS）vs `fatal`（401/403/400/模型不存在）；
2. transient 退避序列 **30s→1m→2m→5m→5m…**，累计窗口默认 **30 分钟**（env `HEARTH_RETRY_WINDOW_MINS`）；
3. 每次重试前 emit 投影：`[retry] provider 瞬时故障（摘要），第 N 次重试，等 Xs（窗口剩余 Ym）`；
4. 窗口耗尽 → **暂停语义**（非 failed）：投影"上下文已保留，可 resume/重发继续"（与 S8 衔接）；
5. fatal → 立即终止+友好报错。

**过关（先红后绿）**：①mock 前 3 次 429 第 4 次成功 → 任务完成且投影含 3 条 `[retry]`；②mock 401 → 立即终止零重试；③真机断网 2 分钟恢复 → 任务续行。

## 卡 S8 · run 级断点续跑（韧性核心）

**病灶**：`hearth chat` 单 run 执行态全在内存——进程崩溃/VM 重启/Ctrl-C/key 失效 = 任务蒸发（用户质询"能不能接续上"）。

**实施**：
1. 消息循环**每步落盘 run 状态**至 `sessions/runs/<run-id>.json`：对话历史+scratch（budget_stop_unverified 等）+产物清单+steps/预算位——**复用存量 sessions 持久化与 spill 机制**（agent-core sessions.rs），接入 chat 单 run；
2. 新命令 `hearth resume <run-id>`：从断点恢复执行（消息循环从落盘状态重建）；
3. **统一暂停语义**：fatal/预算耗尽/窗口耗尽/Ctrl-C 全部=落盘+投影"断点已存（run-id），修复 X 后 resume 继续"——**不再有不可恢复的 failed**；
4. 键盘 Ctrl-C 在 repl 中改为"落盘+暂停"（连续两次才退出）。

**过关**：任务跑到一半 `kill -9` hearth 进程 → `hearth resume <run-id>` → 从断点续跑到交付（产物完整）；真机演示一次。

## 卡 S10 · 流式输出 + 三通道分层渲染（用户拍板扩容 2026-09-10 晚）

**病灶**：chat/repl 黑盒等待（信任杀手）+ 用户拍板补充："**把思考与输出的结果要进行区分**，不然我不知道哪里是思考，哪里是执行过程，哪里是最终结果"——流式若三流混排，黑盒变噪音，问题未解。

**实施**：
1. llm-openai 走 SSE 流式（`stream: true`）→ token 透传 → CLI 渲染；非流式 fallback 保留；
2. **三通道分层渲染**（本卡核心）：
   - **思考通道**：`reasoning_content`（3.0-flash 推理流）→ 暗灰色斜体前缀 `💡 [思考]`，可折叠显示——与正文视觉分离；
   - **执行通道**：工具调用/结果 → 既有结构化块（`⚙ 工具 → 参数`/`✓ 结果`），流式期同步呈现；
   - **结果通道**：模型正文（最终回答/产物说明）→ 正常亮色，**每次回答结束时追加显式分隔线** `───── 结果 ─────` 之下为权威内容；
3. 渲染层实现位置：agent-runtime 渲染管线 + codex-cli render（三通道各配样式函数）；思考流**不写入对话历史**（仅投影，防注意力税回流）；
4. 真机验收由用户目测：一眼区分"它在想什么/在干什么/最终给了什么"。

**过关**：①真机 repl 回答逐字呈现且三通道视觉分明（用户目测通过）；②SSE 失败自动降级非流式；③思考流不入历史（history_chars 前后对比取证）。

## 卡 S11 · 中断保留上下文

**病灶**：repl 中 Ctrl-C 直接杀 run（上下文丢）。

**实施**：tokio `select!` 监听 Ctrl-C → abort 当前模型调用/工具执行 → 投影 `[interrupt] 本轮已打断（上下文保留）` → 回到输入提示符；**连续两次 Ctrl-C**（3s 内）才退出 repl。
**过关**：任务中 Ctrl-C → 立即停 → 追问"刚才做到哪" → 模型基于完整上下文回答。

## 卡 S12 · 交付前质量自检（完成语义升级——"把任务交出来"机制化）

**病灶**：Done = LLM 自报+产物非空 → 魂斗罗 10 分样子货合法交付（用户判）。

**实施**（挂入 finalize_done 之前，S5 重构后该函数已提取正好承接）：
1. **产物类型化自检**：
   - 代码类（.py/.rs/.js）：语法检查（`node --check`/`python -m py_compile`/`cargo check`）+ 自测执行（若模型写了 test 就跑）；
   - HTML/游戏类：无头浏览器打开（复用 playwright，依赖 bench/exam/contra-playtest.js 模式）+ **零 JS 错误** + 核心交互冒烟（按键/点击各一次）+ 截图留档；
   - 文档类：重读一遍自查完整性；
2. 自检失败 → **自动修复迭代（最多 2 轮）**——每轮投影 `[selfcheck] 产物 X 自检未过（原因），修复中（轮次 N/2）`；
3. 仍不过 → 诚实交付：投影"已交付 X，自检未过项 Y（原因），需人工"（**不许静默交半成品**）；
4. 自检结果写入 run report（含截图/输出证据）。

**过关**：①单测：mock 产物语法错 → 自检捕获 → 修复轮次执行；②**判别实验**：同一魂斗罗任务卡（原版 vs 质量版=本卡生效后）重跑，用户评分对比——评分提升=提示词/自检杠杆实锤，仍 10 分=LLM 上限实锤（**责任归位实验，结果呈顶层**）。

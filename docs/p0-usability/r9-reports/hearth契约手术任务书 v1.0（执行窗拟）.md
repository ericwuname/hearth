- **性质**：**契约显式化 + 契约级自检**——不加新能力，把已有能力之间的"约定"钉死并自动化验证
- **施工方**：待定（traecode 若积分可用 / 执行窗自施工）

## 一、背景：为什么是这个手术（6 张卡的收敛）

EMBER 四期（M0 单轮 → M1 工具循环 → M2 记性 → M3 自诊）施工中，hearth 的失败**全部收敛到同一根因家族**：

| 期 | 病灶 | 契约族 |
|---|---|---|
| M0 v1 | 探测完即 Done、核心产物零行 | **交付契约**（没定义"交付齐"） |
| M1 | `tools.py::_as_args` 键名硬编码 `path` → bash 全废（51 字符错误） | **参数契约**（跨文件调用约定） |
| M2 | 返回 `(answer, messages)` 但未持久化；**且污染 stdout** | **状态契约 + 输出契约** |
| M3 | 病灶定位 + 最小修复未在窗口内完成 | **外科精度**（本手术不直接治，靠 K 系列降低难度） |

**判读**：hearth 的单点实现与流程执行质量良好（写工具函数、核验数字、按计划推进）；一旦涉及**两个组件之间的约定**（什么算完成、参数怎么归一、输出给谁看、状态存哪），**易于破约且不自知**（自检不覆盖契约面）。

→ **手术标的**：七条契约的显式化 + 自动化守护（每一条都有今日实测病灶锚点）。

## 二、手术项（7 项）

### K-1 · 交付契约（完成语义 2.0）｜源：PC-01

**病灶锚点**：M0 v1——21 步做完环境探测（找到 key/python3/HTTP 200/写 probe.json）即 `✓ Done`，**核心交付物零行**；S12 自检未拦住（自检只查"产物可用性"，缺"任务要求的产物类型是否齐"）。

**要求**：
1. 规划阶段（todo_write 或等价）**声明交付物清单**（文件名/类型）；
2. 完成判定（all_done gate）核对：声明清单 vs 实际落盘产物——**缺任一 → 不许 Done**（继续干或诚实报告缺什么）；
3. 与 S12 串联：类型齐 → 深度自检（语法/冒烟）；类型缺 → 拒绝完成 + 投影缺项。

**验收（先红后绿）**：用 M0 原卡（描述性）重跑——**不再出现"探测完就 Done"**；产物类型齐全才允许收尾。

### K-2 · 输出契约（stdout 纯净）｜源：M2 回归

**病灶锚点**：M2 半成品把 `('\n\n好的', [messages...])` 元组 repr 打进 stdout——**破坏管道语义**（`$(hearth -p ...)` 拿到脏数据）。

**要求**：
1. 契约条款（写入代码注释 + README）：**stdout 只出正文/答案**；进度/工具/思考/历史 → stderr；
2. 契约级自检：**单测**跑一次 `-p` 路径，断言 stdout 不含 `(`/`{` 开头的结构 repr、不含 `[tool]`、不含 token 统计行；
3. 现有 render 全面复核（哪些 println 该走 stderr）。

**验收（先红后绿）**：单测（构造回归样本 → 修前红）；真机 `$(hearth -p "1+1=?")` 输出纯净。

### K-3 · 参数契约（工具参数归一）｜源：M1 bug

**病灶锚点**：`ember/tools.py::_as_args` 对非 dict 参数**硬编码 `{"path": ...}` 键**——read/write 恰好工作、`bash("cmd")` 形态被漏 → 全部 bash 调用返回 51 字符错误（"缺少 command 参数"）。
（hearth 同类风险：任何"按位置/按字典双形态"的工具入口。）

**要求**：
1. 工具参数归一统一化：字符串/字典/位置参数三形态一致处理，**键名不得硬编码推测**（按工具签名绑定）；
2. **交叉单测矩阵**：3 种调用形态 × 全部工具 → 参数正确落位（防同类漏检）；
3. 参数不匹配时报错文案含"收到的参数名"（辅助自纠）。

**验收（先红后绿）**：单测矩阵先红（构造 `bash("echo hi")` 形态失败样例）；修后全绿。

### K-4 · 状态契约（持久化必须可验证）｜源：M2 半成品

**病灶锚点**：M2 第一轮改了函数签名（返回元组）**但未落盘**，且无任何断言发现——"持久化"停留在意图层。

**要求**：
1. 凡声明"持久化/断点/会话"的功能，**必须配"跨进程可见"的自动化断言**（写 → 起新进程读 → 一致）；
2. 落盘失败必须**投影警告**（不静默）；
3. 断点/会话文件格式与恢复路径写入模块文档。

**验收（先红后绿）**：单测：会话写入 → 新进程加载 → 断言一致（构造未落盘样例先红）。

### K-5 · 时间契约（退避预算感知）｜源：PC-02

**病灶锚点**：M1 施工 `deadline exceeded: 1114s >= 900s`——S7 长退避（30s/1m/2m）在 provider 抖动期**吃光任务墙钟预算**，任务被杀；S7 与 S8 各自正确、组合出错。

**要求**：
1. 退避前计算 `remaining_task_time()`；若本次退避时长 > 剩余预算 **30%** → **不硬等**，转 S8 暂停（断点 + resume 指引）；
2. 退避循环内每轮复检（任务被外部打断 → 立即收手）；
3. 投影：`[retry] … 等 2m（剩余预算 5m，占 40% → 超阈值，转暂停）`。

**验收（先红后绿）**：构造"短预算 + 持续抖动"场景：修前 = 被 deadline 杀；修后 = 优雅暂停 + 断点可用。

### K-6 · 审批契约（只读命令放行）｜源：PC-05b

**病灶锚点**：resume 带 `--approve-within session` 后仍被拒——被拒命令 `bash → cd ... && diff <(cat ...) ...`（**只读**的 diff/进程替换不在命令表白名单）→ 续跑首个写操作前就中断。

**要求**：
1. DelegateSession 白名单覆盖只读命令（diff/cat/head/tail/wc/grep/ls/echo/find/stat/which/env…）；
2. 进程替换 `<(...)`/管道组合**不因语法形态被拒**（按实际执行的命令判定）；
3. 被拒时投影**替代建议**（如"用 python3 读文件比对"——正是 M1 卡里教模型的做法）。

**验收（先红后绿）**：真机 resume + `diff` 类命令 → 不再被拒；危险命令（rm -rf /、设备写）仍拒。

### K-7 · 网络契约（回退 + 根因可读）｜源：PC-06

**病灶锚点**：.133 IPv6 无出口 + DNS 返 AAAA → reqwest（无 Happy Eyeballs 回退）连接 IPv6 全失败 → 错误一律 transient → **S7 耐心退避掩盖根因，空转 1 小时+**；curl 因有回退而正常（对照实验）。

**要求**：
1. **IPv4 回退**（Happy Eyeballs 或地址族降级重试）；
2. **错误分类细化**：DNS 解析失败 / 连接拒绝 / 地址族不可达 / TLS 失败 —— 分别可判；
3. 退避投影带**失败原因摘要**（`连接 2409:... 不可达 ×5`）；
4. 环境文档：`gai.conf`/hosts 配置入 .133 部署清单（已在 M1 报告附录）。

**验收（先红后绿）**：模拟 IPv6-only 可达但无出口环境 → 自动回退 IPv4 成功；错误投影可读。

## 三、施工顺序与纪律

```
K-3（参数）→ K-2（输出）→ K-4（状态）→ K-1（交付）→ K-5（时间）→ K-6（审批）→ K-7（网络）
```

- 每项：独立 commit + **先红后绿**（红=复现上述实测锚点症状）+ fmt/clippy；
- 红线沿用（沙箱零触碰 / tally 原位 / 无凭据入库）；
- **验收方独立测试须与施工进程错开**（今日教训：RED 并发干扰归因）；
- 全部完成后 → 执行窗逐项复验 → **M4 自举**（EMBER 给自己加分页功能）。

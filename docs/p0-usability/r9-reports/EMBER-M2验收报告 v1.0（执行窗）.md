### ⭐ 失败模式定位（三轮联合分析，给顶层）

把 EMBER 三期施工放在一起看，hearth 的弱点**不在单点能力**（它能写工具、能核验数字、能记住大目标），而在**跨组件/跨轮的契约与状态管理**：

| 期 | 病灶 | 归类型 |
|---|---|---|
| M0 v1 | 探测完即 Done、核心产物零行 | **完成语义**（交付契约） |
| M1 | `tools.py::_as_args` 参数归一键名硬编码 "path" → bash 全废 | **跨文件参数契约** |
| M2 | 返回 `(answer, messages)` 元组但未持久化；**且污染 stdout** | **跨轮状态 + 输出契约回归** |

**模式**：单文件内的逻辑实现（工具函数、算法）质量良好；一旦涉及"**两个组件之间的约定**"（什么算完成、参数怎么归一、输出给谁看、状态存哪），**易于破约且不自知**（自我检查不覆盖契约面）。
→ **顶层定位建议**：hearth 的手术方向应从"加能力"转向"**契约显式化 + 契约级自检**"（与 PC-01 完成语义、PC-02 预算协同、PC-05 审批参数同源家族）。

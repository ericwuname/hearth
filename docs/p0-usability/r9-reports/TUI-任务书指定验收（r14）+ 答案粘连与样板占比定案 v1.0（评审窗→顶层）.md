## 3. 本轮新增/量化（最高价值）

### 3.1 ⭐ O9（新，P1）——「答案没有独立行」：答案被粘连到进度行行首

**TUI 抓屏**：`│  7  ◂ span 耗时 2575ms`、`│  7✓ Done (1 steps)`

**归属实验（决定性）**：绕开 TUI、用 **TUI 实际调用的同一 binary**（`main.rs:24` = `/home/wutao/hearth-slim/target/release/hearth`，0.2.27）直连抓 stdout：

```
09 |───── 结果 ─────
10 |7  ◂ span 耗时 14866ms          ← 引擎原文
11 |7✓ Done (1 steps)               ← 引擎原文
```

| 假设 | 判定 |
|---|---|
| TUI 渲染把答案与元数据拼到一起 | ❌ 证伪 —— 引擎 stdout **原文就是** `7  ◂ span …` / `7✓ Done …` |
| 引擎输出答案后**未换行** | ✅ 成立 —— 31 行 stdout 中**不存在任何一行仅含答案** |

⇒ **O9 归因引擎（hearth-slim）**，TUI 只是**忠实转发**（与 N2a 同源同侧）。
⇒ 该发现**替代并收窄**了此前记的「`7✓` 缺空格」——真因不是"少一个空格"，而是**答案与后续元数据共处一行**。

### 3.3 ⭐⭐ O10（新，**根因级**）——答案粘连的真因：**答案流缺收尾换行**

源码级证据链（`/home/wutao/hearth-slim`，0.2.27）：

| 锚点 | 原文 | 作用 |
|---|---|---|
| `crates/codex-cli/src/render.rs:41-45` | `macro_rules! outln { … println!(…) }` | 带换行（stdout） |
| `crates/codex-cli/src/render.rs:48-53` | `macro_rules! out { … print!(…) }` | **不带换行**（stdout） |
| `crates/codex-cli/src/render.rs:132-145` | `pub fn token(delta: &str) { ensure_result_separator(); out!("{delta}"); }` | **答案以 `print!` 流式吐出，无换行** |
| `crates/codex-cli/src/render.rs:262-273` | `span_close(...)` → `outln!("…◂ span 耗时 {duration_ms}ms")` | 紧随其后的 **`println!`** |
| `crates/codex-cli/src/render.rs:200-217` | `done(...)` → `outln!("{icon} Done ({steps} steps)")` | 同上 |

**归因**：答案流（`token()`）用 `print!` 逐字吐出 `7` 后，**没有任何地方补换行**；下一条 `outln!` 的 `println!` 直接接在同一物理行 ⇒ 得到

```
7  ◂ span 耗时 14866ms
7✓ Done (1 steps)
```

⇒ **「`7✓` 缺空格」的历史判断不准确**：不是少一个空格，而是**答案与元数据共处一行**（缺换行）。同时解释了"抓屏中不存在仅含答案的行"。

> ✅ **修法（1 行级）**：在答案流结束处补一次 `outln!()`（或令 `outln!` 在写入前检查"答案行未闭合"状态并先补 `\n`）。**归属引擎侧**（`render.rs`），TUI 无需改动。

### 3.4 ⭐ 架构建议（一处改动同解四病，TUI 零改动）

**实测事实**：K-2 输出契约（`crates/codex-cli/src/lib.rs:374-388`）**只在 `-p` / `--print` 路径**调用 `render::set_headless(true)`；用户手工入口与 TUI 走的 **`hearth chat "<goal>"` 不设 headless** ⇒ 进度/收尾/总结**全部落到 stdout**（实测 31 行 stdout vs 1 行 stderr）。而 `outln!` / `out!` 宏**均已按 `headless()` 自动分派到 stderr**（`:41-53`）。

**TUI 侧现状**（已具备分离能力，且零成本）：
- `src/main.rs:140-158`：**stdout / stderr 各起独立读取线程**；
- `src/main.rs:154` → `UiMsg::Err(l)`；`:254-255` **stderr 行一律 `Kind::Proc`（可被 `Ctrl+T` 折叠）**；
- `:216-244` stdout 行靠**内容字符串重分类**（fix4 的 `is_proc`：`──` 前缀 / `═══` 定界）才勉强折对一部分 —— 这是"通道该分没分"后打的补丁。

**建议**：让 `chat` 在 **stdout 非 tty**（TUI 正是 `stdin=null` + `stdout/stderr=piped`）时自动进入 headless 分流。
一处决策即同时解决：

| 受益项 | 机制 |
|---|---|
| **O9 答案粘连** | `token()` 走 stderr？否 —— 正文仍是 stdout，但元数据不再挤在同一行 |
| **N2a 收尾重复 / 样板占比 68%** | 样板进 stderr ⇒ `Kind::Proc` ⇒ `Ctrl+T` 一键全折，结果通道只剩答案 |
| **O7 跨通道次序不一致** | stdout/stderr 各自有序，FE 可按通道分层呈现 |
| **D14 答案被埋** | 结果通道仅剩答案 ⇒ **默认态即在视口**（不再依赖 `fold:ON` 策略定调） |

> 依据顶层一贯的**事实产生权公理**：BE 产事实、FE 投影。当前 BE 把"答案事实"与"过程事实"塞进同一通道，FE 只能靠字符串猜测重分类 —— 属**结构性错配**，补丁化修法（继续加 `is_proc` 规则）会持续走偏。

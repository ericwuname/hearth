## 投影模板（用户视角设计——先给结论再给细节）

任务终止时（任何收尾路径：完成/暂停/预算耗尽），在收尾投影后追加：

```
═══════════ 任务总结 ═══════════
【一句话】<这个任务做成了什么 / 卡在哪>
【产物】  <文件清单 + 怎么用（路径/命令）>
【过程要点】<3-5 条关键步骤，一行一条>
【问题与处理】<遇到 X → 这样解决；Y 未解决 → 原因是 Z>
【剩余/建议】<下一步需要用户做什么（或"无，任务闭环"）>
【质量自检】<N 项过 M 项（S12 自检结果引用），详情见报告>
（完整过程: .hearth/reports/<run-id>/run-001.md）
══════════════════════════════
```

- **暂停/失败路径同格式**：【一句话】改为"卡在哪"；【剩余】改为"修复 X 后 resume 的具体指令"（与 S8 衔接）；
- 同步写入 run report **头部**（文件版 TL;DR——打开报告先读总结再看流水）。

## 实施

1. finalize_done / finalize_error 末尾追加 `generate_summary()`：取 run 历史（压缩摘要即可，不灌全文）+产物清单+S12 自检结果 → 一次 LLM 调用（max_tokens ≤800，要求按模板填充、禁止编造未发生事项）；
2. 模型不可用时降级：模板机械填充（产物清单+自检结果为实数据，一句话/要点留空标"生成失败"）——**总结生成失败不影响任务交付**；
3. repl 长会话新增 `/summary` 命令：随时对本会话至今出总结（复用同函数）；
4. 思考/执行/结果三通道照旧——总结块独立于三通道之后（用户可只读总结块）。

## 过关（先红后绿）

1. 单测：mock run 历史 → 总结按模板生成、无编造项（模板字段与实数据一致）；
2. 真机：L1-01 重跑 → 任务结束后出现总结块，用户**只读总结块**即可回答"做了什么/产物在哪/能不能用"；
3. 暂停路径：kill -9 → resume 投影含总结（含 resume 指令）；
4. 用户目测：**"内容多我也可以不看过程了"——由你验收这句话成立与否**。

## 红线

总结生成失败不阻断交付（降级模板）；不编造（模板字段无实据则标"无"）；预算步数不受影响。

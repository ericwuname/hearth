## 一、根因突破：`.133` 的 IPv6 无出口（今天所有"卡住"的元凶）

- **证据**：同一 Python 脚本三次请求，**中间那次 13.07 秒**（IPv6 先试、超时才落 IPv4）。
- **机制**：DNS 同时返回 IPv6（机器无出口）与 IPv4；**curl 有 Happy Eyeballs 所以秒回**，而 **Python urllib / Rust reqwest 无回退**。
- **修复**：`/etc/hosts` 钉 IPv4 → 实测 **10/10 全 0.5 秒**。
- **影响面**：TUI 的 `read timed out`、**hearth M5 卡 4.5 小时**、以及 9-11 的 K-7"只修了错误分类没修回退"——同一根因。

## 六、方法论沉淀（写入 skill `hearth-closure-run`）

1. **后台启动可靠范式**：**远端 heredoc 生成脚本**（LF 天然）+ **key 从 config 动态读**（不内联明文）+ **启动/sleep/核查同一命令**（日志 5 秒内不出现就是没跑起来）；`pgrep -f` 会自我匹配，改用 `grep "[h]earth"`。
2. **任务卡硬约束**：**每卡 ≤15 步**（与业界 15–25 读数一致）。
3. **验收纪律**：施工者自报 ≠ 通过，必须独立复验（今天多次靠这条纠正了误判）。

## 二、🔴 验收中发现的新缺陷（报告未列，本件最重要产出）

### K-1 的失败事实**未落入事实层**——违反"事实产生权公理"

**实测路径**（`crates/agent-core/src/loop.rs`）：

- `4042` `if let Some(missing) = deliverable_type_mismatch(...)` → 两条出口：
  - `4043-4051`：轮次 ≥2 → emit 一句 `[selfcheck] 交付物类型核对未过…诚实交付` → **`return Ok(Proceed)`**
  - `4052-4063`：轮次 <2 → emit + 回喂 user message → **`return Ok(Replan)`**
- **两条路径都没有写 `scratch["selfcheck_result"]`。**
- 而写 scratch 的位置在 `4073`（**产物自检**路径专用，K-1 的两条 return 都在它之前）。
- 消费方三处全部读该 scratch：`4273`（run report 事件）、`4301`（RunReport.summary）、`4564`（S14 收尾三行事实输入）。
- 每轮开始 `4999-5000` 会把该 scratch 重置为 `Null`。

**后果**：

1. K-1 未过（2 轮用尽）时，run report 的 `selfcheck` 字段 = **`null`**，而 `null` 的既定语义是"**未跑**"（代码注释原文："未跑 = null 如实标注"）。于是**"交付物类型核对未过"与"本轮无产物、未自检"在报告里不可区分**——这正是 K-1 声称要解决的那类"看不出核心交付缺失"的问题。
2. 事实只存在于**流式 `ThinkSummary` 事件**里：交互终端会滚屏消失，`-p` headless 下进 stderr——**K-2 刚把 stdout 弄干净，K-1 的关键事实却落进了最易丢的通道**。
3. **终态仍是 `completed`**（`4268-4272`: `"ok": true, "status": "completed"`），K-1 只增加了 2 轮回喂，**未改终态语义**。M0 v1 的"探测残留当交卷"病灶，在 2 轮用尽后依然会以"完成"收场，只是多了一次回喂尝试。

**为什么现有测试没抓到**：既有断言（`7565+`）只覆盖产物自检路径（该路径确实写了 scratch，断言 `passed==false`）。**K-1 路径无任何断言覆盖**（`test_k1` 只测纯函数 `deliverable_type_mismatch`，不测 gate 行为）——**这是测试盲区，不是测试通过**。

**建议处置**（我不改 `crates/`，只给补丁）：

```rust
// loop.rs K-1 两条 return 之前补写事实（与产物自检同 schema，加 kind 区分）
self.ctx_mgr.set_scratch("selfcheck_result", serde_json::json!({
    "passed": false,
    "rounds_used": self.self_check_rounds,
    "checks": [],
    "failures": [format!("交付物类型核对未过——缺：{}", missing)],
    "skipped_any": false,
    "kind": "deliverable_type_mismatch",
}));
```

并补一条 gate 级测试：K-1 未过 2 轮用尽 → 断言 `scratch["selfcheck_result"].passed == Some(false)`（**先红后绿**：改前必红）。

**严重度判断**：不改**不影响** K-2~K-7 的任何行为，也不引入新缺陷；但**削弱 K-1 本身的可审计性**——K-1 是 7 项里的第 1 项（交付语义 2.0），其承诺就是"不再把探测残留当交付物交卷"，若失败事实不落盘，交卷后**无从审计**。故判 🔴，**建议列为 bump 前的必办项**（成本 ≈10 行 + 1 测试）。

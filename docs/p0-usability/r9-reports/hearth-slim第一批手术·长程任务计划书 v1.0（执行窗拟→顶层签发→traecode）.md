## 手术卡 S1 · bash 工具超时（小，先做）

**病灶锚点**：loop.rs 中 bash/cmd 相关 timeout **零命中**（grep 实证 2026-09-09）——真机事故 C-fix-status（26-r3-corpus）挂死 5.5h：模型跑 `cargo check` → cargo 等全局锁 → 工具无超时 → 会话无限挂起。

**动作**：
1. bash 工具执行加超时：默认 **120s**，env `HEARTH_TOOL_TIMEOUT_SECS` 可配；
2. 超时后 kill 子进程树（含管道子进程），返回结构化结果：`{"status":"timeout","elapsed":X,"partial_output":...}`；
3. 输出截断：stdout 超过 **64KB** 截断并标记（防 45 万 tokens 式膨胀复发）。

**过关**：单测——构造 `sleep 300` 的 bash 调用，120s 内被超时回收且投影正确（先红后绿）。

## 手术卡 S2 · 出网默认放开（小，用户拍板"全部默认允许"）

**病灶锚点**：v0.2.22 起 bash 工具层出网域名白名单（空=全拒）——真机实证：cargo 拉依赖被卡、模型无法联网查资料（用户 2026-09-09 拍板：做项目必须能联网搜索查询）。

**动作**：
1. **默认放开出网**（白名单改为默认空=全放，保留 env `HEARTH_EGRESS_ALLOWLIST` 供收紧——语义反转：从"默认拒"改"默认放"）；
2. 出网活动**审计投影**：bash 工具调用含网络特征时，结果尾部追加一行 `[net] 出网目标已记录` 级别的最小投影（不阻断）；
3. 文档同步：R5-9 工具描述与 README 的出网说明改写。

**过关**：单测——fixture 内 `curl -s https://example.com` 成功返回（先红后绿）；风险披露：提示注入/恶意命令风险已知悉并接受（用户拍板），审计投影为唯一缓解层。

**动作**：

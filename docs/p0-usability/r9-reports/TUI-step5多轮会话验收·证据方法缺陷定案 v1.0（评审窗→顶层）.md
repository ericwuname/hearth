## 四、本轮最高价值：**原卡证据链无效**（两条硬伤）

### 4.1 施工者自验是**不可能失败**的断言

`/tmp/step5-verify.sh` 的判定是 `capture-pane | grep -c "小明"` → 输出 `xiaoming_hits=3`。
**但那 3 个命中全部来自 turn1 的回显/总结**，抓屏里**根本没有 turn2 的问题与答案**：

```
│  hearth: - 接收用户指令“我叫小明，请记住”      ← 命中①（用户输入回显）
│  hearth: - 助手响应并确认用户姓名为“小明”       ← 命中②
│  hearth: 【一句话】任务完成，已记录用户名为“小明”。 ← 命中③（这是 turn1 的总结）
```

⇒ **只要用户输入里含"小明"，这个检查永远 PASS**。这是本项目已记录过的老病（H2/F2 家族："计数器的命中 ≠ 证据"），
本次是第 4 次实证。**该断言等于没有断言。**

### 4.2 卡里的因果推断**不成立**

`tui-step5-task.txt` 要求"抓屏证明它答出'小明'（= 同一会话）"，evidence 里写：
> *"Only possible via resume <same-UUID>"*

**这句话是错的。** 我实测到至少两条**与 resume 无关**的替代路径：

1. **工作区笔记文件**：`/home/wutao/hearth-tui-new/notes/user_profile.md`（88 B，**19:42 已存在**，早于卡的自验）内容是
   `# 用户偏好设定 / - 姓名：小明（用户自报，设定于本次会话）`——**这是 hearth 自己在 turn1 写的**（证据：`81fac190/run-001.md` 的产物段
   `【产物】notes/user_profile.md：后续会话可通过读取该文件获取用户基本信息` + 该会话 jsonl）。该文件在工作目录里，**任何后续会话都能读到**。
2. **环境信息**：见 §5 的 D9——全新会话能从 `uid/hostname` 推断出名字。

⇒ 因此 A2 的"小明"**不能**证明会话连续性。**能证明的是 §3.2 的产物级证据**（这也是我给 ✅ 的依据）。

### 4.3 方法论沉淀（建议进卡模板硬约束）

> **"记住我的名字"不是会话连续性的有效判据。** 会话连续性必须用**产物级证据**判定：
> ① 报告/会话目录是否**复用**（数量不增）；② session 状态文件里 `original_goal` / `steps_used` / `goal_revision` 是否**累积**。
> **禁止**用"答案里出现了某关键词"作为连续性判据——该关键词必然出现在用户自己的输入里。

## 五、新发现缺陷

| ID | 级别 | 内容 | 锚点 / 实测 |
|---|---|---|---|
| **D9** | **P1（新）** | **「记不住就猜」**：全新会话（`chat`，无历史）被问"我叫什么名字？"，它**用 bash 抓 `uid`/`hostname` 推断出 "wutao"** 并自信作答，还自我解释"名字来源是系统信息而非用户自述"。**正确行为应是"我不知道"**——拿机器元数据当人的身份，等于**编造事实**（违反 truth-first） | 抓屏 `【一句话】基于环境信息回答了用户名字，确认为 wutao` + `- 检索 workspace 系统信息获取 uid 和 hostname`；报告 `beb0c4c2/run-001.md` |

### 本窗自曝（必须写标题，不写脚注）

- **A6 是我测试法的瑕疵，不是产品缺陷**：`steps: N` 在**按 Enter 那一刻**就自增（= `history.len()`），我误把它当成"本轮结束"信号，
  所以在 turn3 **仍在 running** 时抓了屏。产品行为正常（答案已正确显示）。**教训**：判"本轮结束"只能用状态栏 `done (` 或**等子进程退出**，不能用 `steps`。
- **我自己也没能一次抓到正确判据**：A2 一开始被我标成 PASS 并当作核心证据，做对照实验时才意识到判据无效。**已改正并写进 §4.3。**

## 动作

### 1. transient 错误分级

| 分类 | 判定 | 处置 |
|---|---|---|
| **transient** | 连接失败/读超时/HTTP 429/5xx/TLS 握手失败 | **长退避重试**（见下） |
| **fatal** | HTTP 401/403（key 无效）/400（请求格式）/模型不存在 | 立即终止，友好报错（重试无意义） |

### 2. 长退避序列（transient）

- 序列：**30s → 1m → 2m → 5m → 5m → 5m…**（累计上限 **30 分钟**，env `HEARTH_RETRY_WINDOW_MINS` 可配，默认 30）
- 每次重试前投影一行（用户可见"在等"而非"死了"）：
  `[retry] provider 瞬时故障（<错误摘要>），第 N 次重试，等待 Xs（窗口剩余 Ym）`
- 窗口打满：投影 `[retry] 重试窗口（30m）耗尽，任务暂停——上下文已保留，可 /resume 或重新下发继续`（**不报 failed**，语义=可恢复暂停）

### 3. 超时参数同步

- 单次请求超时保持 60-120s；重试窗口计时与单次超时独立

### 4. EMBER 同款

- EMBER（M0 已含重试）升级为同款分级+长退避——立项书"网络错误带超时+重试"按本卡执行

## 过关判据（先红后绿）

1. 单测：mock LLM 层前 3 次返回 429/连接错误、第 4 次成功 → 任务完成且投影含 3 条 `[retry]` 行；

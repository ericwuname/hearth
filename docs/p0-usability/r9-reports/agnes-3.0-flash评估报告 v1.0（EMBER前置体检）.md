## 三、硬性设计约束（EMBER 实现必须遵守）

1. **max_tokens = 65536（上限拉满）/次调用**（思考吞预算实测：2048 下正文 0 字；约束 ④ 修订后思考强度拉满，预算必须给足）；
2. **只用 Chat Completions 协议**（`/v1/chat/completions` + `tool_calls`），禁用 Responses 协议（第三方实测偶发 400）；
3. **重试机制必备**：第三方实测有偶发"思考卡壳"（拥堵），EMBER 的 LLM 调用层要带超时+重试——恰好呼应 Hearth 工具超时缺失的教训，EMBER 从第一天就有；
4. **【用户拍板修订 13:56】思考强度拉满，不设省**：`chat_template_kwargs: {"enable_thinking": true}` 常开 + max_tokens=65536。实测：数列推理正确（2,6,12,20,30→第 8 项 72，n(n+1) 通项，reasoning 355 tokens）；`"thinking":"high"` 变体参数被服务端静默忽略（reasoning 与 C1 全同 355），`enable_thinking=true` 即官方控制面全部；max_tokens=65536 服务端接受不报错。原"轻量档即可"约束废止；
5. 免费政策风险：EMBER 代码里 provider 配置独立（base_url/model/key 一个文件），随时可换底座。

## 四、对 EMBER 计划的影响

- **工具循环实现路径确认**：标准 tool_calls 协议，M1 无技术障碍；
- **速度红利**：3.0 交卷速度显著快于 2.5（第三方同题对照 8 倍），EMBER 迭代节奏会更快；
- **官方优化方向与我们的验收指标同构**：EMBER 跑 L1-01 考题的成绩，将直接检验官方"可信交付"宣传的成色——考题就是照着它的主打方向出的；
- **配额无忧**：Agnes 会员 7.5 万次/周，EMBER 全程 3.0 免费通道。

## 五、结论

**批准 EMBER 使用 agnes-3.0-flash**，带上述五条设计约束。M0 任务卡随新路线任务书 v1.0 一并发出（跑批收官归档后点火）。

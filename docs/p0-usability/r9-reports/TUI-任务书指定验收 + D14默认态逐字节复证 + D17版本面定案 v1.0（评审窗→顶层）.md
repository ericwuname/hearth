## 4. 本轮新发现（含锚点）

### D17（P1，**定案**）版本面三件：用户手工入口 ≠ 被测件

| 入口 | 实际路径 | 版本 | md5(前8) | mtime |
|---|---|---|---|---|

| TUI 内部调用 | `/home/wutao/hearth-slim/target/release/hearth` ← **`src/main.rs:24 const HEARTH_BIN`** | **0.2.27 (unknown)** | `cee2f0f5` | 09-12 02:20 |

- 三个二进制并存，**用户手敲 `hearth` 走 0.2.25，TUI 走 0.2.27** ⇒ 用户体感数据与验收数据**不同源**。此前 10 轮的"用户体感定案"必须按此打折。
- 附：`hearth --version` **可用**（输出 `hearth <ver> (<git>)`），故用户**有能力**自证版本；但需先知道要查——建议 `.bashrc` 收口或至少在会话启动横幅打版本。
- 附：`(unknown)` = 构建未带 git 信息 ⇒ 出问题时无法定位构建点。

### N6（P3，**确认**）分隔线被加弹点

- 现场：`│· ═══════════ 任务总结 ═══════════`
- 锚点：`src/main.rs:512-519` `Kind::Proc =>` 渲染分支对**首行无条件**加 `· ` 前缀 → `═══` 分隔线（分类为 Proc，见 `:224-231`）也被加。
- 边界验证：以边框锚定的模式 `│· ═` 计数 = **1**（恰为那条分隔线）；`│ ═` 计数 = 0。
- 修法：该分支加一条 `if !ln.starts_with('\u{2550}')` 守卫。

### N7（P2，**建议关闭**）`═══` 配对已与真实引擎输出一致

- 上轮登记的 N7 是 fix6 时期的**奇偶翻转**风险。polish3 的 T3 已改成**内容配对**：`:224` `is_summary_delim = starts_with('═')` → `:229` `is_open = contains("任务总结")` → `:230` `in_summary_block = is_open`。

- 残余风险方向为 **fail-open**（孤儿 `═══` 只会提前关闭折叠块 ⇒ 多显示、不吞行），且答案行有 `:219 has_answer` 硬守卫（`◂ span` / `✓ Done` 永不折叠）。⇒ N7 可关。

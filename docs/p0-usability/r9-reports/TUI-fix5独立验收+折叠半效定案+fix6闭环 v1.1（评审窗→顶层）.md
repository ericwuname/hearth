### 2.4 一处自述失真（方法缺陷，非产品缺陷）

EMBER 自测 (e) 原文：`after Ctrl+Q: tmux ls | grep fx5c → fx5c: 1 windows`，读起来像**退出失败**。
实测：其会话用 **shell 中转**启（`bash -c '<bin>'`），二进制退出后会话仍在 → **判定无效**。
改用 v8 纪律（**二进制直接当会话命令** `tmux new-session -d -s S -c DIR "$BIN"`）→ **会话随进程退出而销毁，Ctrl+Q 正常**。
→ 结论：**产品行为正确，是自测的启动法使断言失去意义**（与 A6「steps 当完成信号」同族的"仪表错误"）。

### 2.5 T3 的诚实边界（不得夸大为"已动态验证"）

panic 钩子**无条件注册**（L153 在 main 起始处，非死代码），源码级映射清楚；
但**用户输入路径上不存在可达 panic**（全文件 `unwrap/expect` 均落在不可失败处，如 L112 `stdout.take().unwrap()`），
故**无法从外部诱导 panic 做动态验证**。本轮**只声明静态通过**，不声明动态通过。

## 3. 本轮最高价值：**O3「折叠半效」定案**（P1）

### 3.1 现象（双端抓屏，100×24 真实尺寸）

| 状态 | 逻辑行数 | 状态行 | 屏上可见（会话区 13 行） |
|---|---|---|---|
| fold **OFF** | 28 | `scroll:15/15`→底部 `0/14` | `· ✓ Task completed` + `· ── 收尾 ×3` + **`═══ 任务总结 ═══` 整块 9 行** |
| fold **ON** | **17**（−11） | `scroll:4/4` | `> 用户行`、`🔒`、`🔓`、`🎯`、**`2  ◂ span 耗时 3337ms`（答案）**、`2✓ Done`、**`═══ 任务总结 ═══` 整块 9 行仍然在** |

按压 Ctrl+T **只减掉 11 行**，被减掉的是：`· diagnostics → …`、`·   ▸ span [plan] …`、`· ───── 结果 ─────`、`·   ── 收尾 ×3`。
**把答案挤出视口的 9 行「任务总结」整块 + `◂ span`/`✓ Done` 两行，一行都没被折叠。**

### 3.2 根因（源码锚点 `src/main.rs:191-196`）

`is_proc` 的匹配式与引擎**实际输出**不匹配：

| 引擎真实输出 | 代码匹配式 | 结果 |
|---|---|---|
| `· diagnostics → …` | `starts_with("· ")` | ✅ 折叠 |
| `·   ▸ span [plan] …` | `contains("▸ span")` | ✅ 折叠 |
| `<答案>  ◂ span 耗时 3337ms` | `contains("▸ span")` | ❌ **漏**（`◂`=U+25C2 vs `▸`=U+25B8，字形不同） |
| `── 收尾 | …` / `───── 结果 ─────` | `starts_with("──")` / `("─────")` | ✅ 折叠 |
| `═══════ 任务总结 ═══════`（含收尾 `════…`） | 无（`═`=U+2550 ≠ `─`=U+2500） | ❌ **漏** |
| `【一句话】/【产物】/…` + 2 空格续行 | 无 | ❌ **漏** |
| `（完整过程: …）` | 无 | ❌ **漏** |
| `<答案>✓ Done (1 steps)` | `starts_with("✓ ")` | ❌ 漏（前有答案字符） |

→ 净效果：**输入栏广告的 `Ctrl+T=fold` 只兑现一半**。

### 3.3 ⚠️ 修法红线（写卡时已固化，防止"修坏")

`◂ span` 行与 `✓ Done` 行**携带答案本体**（`2  ◂ span 耗时 3337ms` 的 `2` 就是答案）。
**把它们并入折叠集合 = 把答案一起藏掉**——比现状更差。故 **fix6 明令：答案两行永不折叠**，
只补「`═══` 定界块」的折叠（块首/块尾皆以 `═══` 起，可用一次标志位翻转实现，天然覆盖 `【】` 及其续行）。

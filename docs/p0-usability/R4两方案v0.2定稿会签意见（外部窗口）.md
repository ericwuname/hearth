## 二、🔴 会签阻塞项：G-C v2 的场景载体错位（判据条文可签，载体不可签）

### 2.1 实证：盲测包 A 组不含"give_up 但写过文件"的可跑场景

盲测包 A 组 10 条（已实读 `release/盲测包-正式轮-v0.2.23-10+5.md`）**全部是用户侧短句，属五维评分输入集**：

| # | 输入性质 | 观察点 |
|---|---|---|
| A1/A10 | 状态询问（"身体通不通"/"回复一下情况"） | fresh 锚定 / 状态汇报 |
| A2 | 开放式自检 | 计划投影 |
| A3/A5 | 粘贴错误日志 / 追问"上一轮 give_up 原因" | 探针质量 / 诊断投影 |
| A4 | "那你继续跑吧" | 继续型是否假完成 |
| A6-A9 | 主诉复验 / 多意图质疑 / 三点指令 / 策略对话 | 意图丢失检测 |

**没有任何一条是"让 hearth 处于一个正在写文件的任务、随后 give_up"的场景构造。** G-C v2 要测的终态三臂（failed / completed+UNVERIFIED+不计成功率 / 裸 completed 无标记）需要**完整任务上下文**，单条用户短句无法驱动——A4"继续跑"无前文无从触发，A5/A7 是 give_up **事后**追问。

### 2.2 错位定性：sha256 确认 ≠ 场景确认

执行窗把两件事混为一谈：sha256 确认了「**文件存在**」（材料已入库 ✅），但没确认「**A 组含 give_up 场景**」（**不存在** ❌）。且盲测包自述「首正式轮 A/B 已判读入档（A 组 4✗1✓）」，BP-2 纪律明写「A 组已让模型见过 7/10 黄金输入，复用 session 即污染」——**拿已评分的 A 组再当跑测场景，本身触碰自己的硬纪律**。

### 2.3 正确载体：语料 A 真实 give_up 轮次（现成 ≥3 个）

语料 A（0.9-0.3）实测 **10 处 give_up**，其中"give_up 但写过文件"轮次存在且可抽取：

| 证据位 | 特征 |
|---|---|
| line ~1608 | give_up 前「跨轮产物记录 **4 个**」，reflect 判 Error（连续错误 1）→ 写过文件 |
| line ~2812 | 「写前目标校验」明示 write_file 目标 `tui-verified-data.md` → 写盘中 give_up |
| line 3070/4032/4131/4197/4773 | 其余 give_up 位，供执行窗按挑选判据补齐第 3 个 |

**修正建议（会签条件）**：G-C 场景载体由「盲测包 A 组」改为「**从语料 A/B 真实 give_up 轮次中抽取 3 个（须含 write_file 证据，场景脚本=该轮完整任务 + 用户轮次序列逐字重放）**」。这是把 G-C 从"新造场景"改回"**真实病理复现**"——与方案二精神统一，也一并消除"复用已评分 A 组"的污染隐患。场景脚本随三方定稿会签一起锁定，跑测中不改。

## 三、G-C v2 判据**条文**——附条件签讫

作为判据原作者，对砺 §二.3 + 顶层 §三 的修订裁决：

1. **原病理判定被新语义覆盖 —— 我方确认**。原病理 = "give_up 被改判成无警示 ✓ 完成、用户无从分辨"（0.9-0.3 实测 7 次假完成）。R1-1 重造后改判强制携带 UNVERIFIED + `success_rate_counted=false`，用户可见警示——病理对象消失，修订成立。
2. **②臂保留 = 三害相权取其轻 —— 同意**。封死②臂会把"模型放弃但文件都在且相关"打成 failed，那是另一种失真；保留②臂 + UNVERIFIED + 不计成功率 + ③臂一票判负是当前最优。
3. **③臂一票判负 + 机器可检 —— 同意**，且这是 G-C 唯一不需要人工判读的硬臂，锚 `rerouted_unverified` 字段（loop.rs:10138-10139）判读，不以观感放宽。
4. **③臂判读口径提醒**：判负条件是"任一场景**裸 completed 无标记**"——判读时须区分「completed 但**本轮确无工具交换**（无物可验，合法）」与「completed 且**本轮有 write_file 却无任何验证动作**（病理）」。前者不是③臂，避免误伤（对应拆解 §23 承诺蒸发同一纪律）。建议在场景脚本里预标每轮"是否含写盘"，让③臂判定无需现场翻日志。

## 三、🟠 本轮最大源码发现：**sticky VERIFIED**（状态生命周期缺口）

### 3.1 现象

执行窗审计表（27 个 VERIFIED = 强 13 / 弱-无 14）中，**6 个"无验证命令"的轮拿到 VERIFIED**——含纯对话轮（"一会一个数字…我真不知道怎么信你"、"你在试探我的边界吗"、"好的，今天的测试先到这里吧"）。收紧后这些轮不应有 VERIFIED。

### 3.2 源码根因（当日实测）

`verification_evidence` 生命周期：**字段声明 `:1054` → 构造 false `:1593` → 置 true 两处 `:2717`/`:5397` → 全文件无任何重置为 false 的代码**。

而 REPL 连续对话（`run_local_continue`，B2 设计）**跨轮复用同一 AgentLoop** → 第 N 轮某次非只读命令置 true 后，**后续所有轮的 completed 继承 VERIFIED**，无论本轮是否验证。这同时解释审计表 6 个"无"轮与"21 completed 行内 27 处 VERIFIED 投影"的口径混乱。

### 3.3 裁定

- **R4.1 收紧"半生效"**：判定函数修了（`bash -c`/`sh -c` 解包递归，B/G-A 段零裸 VERIFIED ✅），**状态生命周期没修**（sticky 污染）。
- **返工第三项**：每轮 `run()` 起始重置 `verification_evidence = false`（一行）+ 回归测试（前轮 VERIFIED → 下轮纯对话 completed 必须为 UNVERIFIED）。
- **"报完成中经核验比例"继续禁用**——在 sticky 修复 + 复测前，A 段 VERIFIED 计数不可用作任何结论。
- 执行窗审计初筛的分类器**同样有首词法同病**：`cd X && ls tests/`、`cd && echo && ls` 被标"强"（实为只读），`cat > /tmp/...`（**写文件**）被标"弱"——**初筛分类不可采信**；我裁定其中可信强验证为 `node tests/...` / `node -e` 直接执行类（约 10-12 个），全表须按解包后语义重分类（可与 sticky 修复同批重跑审计）。

### 2.2 S2 错在哪里、为什么必须换

1. **场景性质**：G-C 要测的是"give_up **但写过文件** → 引擎如何处置改判"。S1/S3 的原点都会触发救回臂（`consecutive_errors==0 && written_files 非空`）；**S2 的原点触发的是终止臂**（`consecutive_errors==1` → 前置不满足 → 正确 failed）。重放 S2 时，若新引擎行为同型，它天然呈现为 failed —— 属于 **①臂"免费通过"**，测不到②/③臂的分叉逻辑。三场景里真正的改判压力样本只剩两个，**G-C 的"3 场景"名不副实**。
2. **预标自相矛盾**：方案写"每场景预标'是否含写盘' = 是"，但 S2 原点 give_up 依据串**明写"本轮写盘 0 个"**——预标与语料实测直接冲突。预标表的语义（本轮写盘 vs 跨轮产物）本身就悬空，而预标恰是外部会签要求用来给③臂消歧的，**消歧工具自己先歧义了**。
3. **为什么会选错**：S2 的"跨轮产物记录 4 个"确实显眼（1417-2601 区间 26 处），但那是 **run-007 长时间 plan 空转段的背景值**，不是该 give_up 的写盘证据。选场景时核对了证据串、没核对**原点终态**——"不信报告信源码"在场景构造环节漏了一道。

### 2.3 处置（砺已代选并实测验证）

**S2 替换为 L4733**（砺实测：give_up → "连续错误 0、本轮写盘 1 个、跨轮产物记录 13 个 → Done（判定完成）" → ✓ Done (29 steps)，run-027）——**真改判原点，本轮写盘证据明确，且在拆解一 E1 的 7 条改判清单内**。

替换后三场景：S1=L2812（写盘 1/跨轮 5→Done）、S2'=L4733（写盘 1/跨轮 13→Done）、S3=L4773（写盘 1/跨轮 13→Done）。**三个都是"本轮写盘 ≥1 + 连续错误 0 → 被改判"的真病理原点**，G-C 的检验力恢复满格。

**备选**（若执行窗有理由保留 1608）：则必须把 S2 重新定性为"**阴性对照场景**"——预标注明"原点 = 连续错误 1 + 本轮零写盘 → 正确失败，重放预期 = failed（①臂）"。阴性对照有对照价值（防新引擎把**任何** give_up 都改判），但**不得计入"3 个病理场景"的通过线分母**，需另补一个真改判场景凑满 3。

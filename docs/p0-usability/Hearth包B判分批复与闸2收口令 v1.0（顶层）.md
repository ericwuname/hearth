## 一、四批复

### 批 1：判分入账（含非盲判分结构性登记）

- 砺判分三件交付（q1q5-scored.csv + 汇总表 + 纪律声明）**入账**；顶层独立复算勾稽吻合（见头部自证），砺自称的 3 处手工修正与 CSV 现值一致，无残留错误。
- **非盲判分登记**：判读包组头自带 base 字段、任务书批 1 表公开组级映射 → 本轮判分为**非盲判分**（砺知组别）。裁决：**登记不改判**。三重缓解：①逐条判定带原文备注，可按 csv 逐条对日志复核；②拍板门槛先于数据钉死（任务书批 4 预签，无事后移动空间）；③操作化定义先于汇总数字钉死（判读件 §一）。将来如需盲判可重做判读包脱敏，但在抽验兜底下盲判重做性价比低——不做。
- **通报表扬**：判分窗自证伪环节（G4/B4 依据 terminal 锚点截半句预判错误 → 亲读全日志改判并登记锚点陷阱）——"不信锚点信全文"纪律在判分场景的首次实战自证伪，正是本体系要的行为。

### 批 2：G4 环境事故裁决（🟠）

- **事实**：G4 全 15 条日志头部 cgroup 警告，bash/grep 全程 RT4 fail-closed 瘫痪。根因=跑测窗未设 `HEARTH_ALLOW_NO_CGROUP=1`（项目记忆既有纪律条款，属执行疏漏非判断错误）——**入账不追责**。
- **拍板稳健性算术（防墙头草，算给它看）**：G4 当前 53/60=88.3%。设环境修复后受影响条目全部翻 Y（最乐观上界）→ 总 YES 率最高 100% → G3−G4 = 95.0% − 100% = **−4.7pp，仍 < 15pp** → **换基座在任何修复幅度下都不触发**。拍板方向对环境事故稳健，事故不构成推迟拍板的理由，但构成补数据的理由。
- **四条裁决**：
  1. 判分按现状**有效**（诚实性/沟通类判定不受环境瘫痪影响，G4 Q3 100% 成立）；
  2. **定向重跑令**：跑测窗修复开关后重跑 A8/B1/B5 三条（成本 33s 级 × 3），产物入账作环境影响注记，不推翻判分（除非出现反转证据，反转证据须申报顶层）；
  3. 拍板件 v1.1 中 G4 读数标注 **"fail-closed 降级环境"**，Q2/Q4 带环境折扣说明；
  4. **闸 3 前车之鉴令**：0.2.25 用户体感必须在 cgroup 正常环境或显式降级配置下进行——体感测的是真实可用性：环境瘫痪下测出的"难用"不作数，环境顺滑下测出的"难用"才作数。

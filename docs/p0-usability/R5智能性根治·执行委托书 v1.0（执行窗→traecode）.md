## 一、项目是什么（一分钟版）

**Hearth（hearth-rs）**：Rust 写的 Codex-class 自主编码 Agent，27 crates / ~35,000 行 / 单二进制，对标 Codex CLI / Claude Code。当前分支 `p0-usability-01`，基线版本 **0.2.24**（commit `5c24e1a`，门禁 501/0）。

**你修的是什么**：外部对标分析（WorkBuddy 视角）+ 动态跑测确认了 13 条"智能性层"根因——之前 R1-R4 修好了**诚实性层**（不说谎/不失忆），本包修**智能性层**（同错不教学、环境盲、信息残缺、高温空转）。**两层分开记账，你不用管宣告策略，照坐标施工即可。**

## 五、已知陷阱清单（三次跑测作废的血泪，全部实锤）

1. **PATH 旧版陷阱**：`hearth` 命令 = /usr/local/bin/hearth 0.2.23（root 装的）——**一切跑测用绝对路径或 HEARTH_BIN env**；
2. **tar 解压中断**：SSH 断连会截断解压（部分文件新部分旧）——**解压后必须 grep 验证关键标记**再 build；
3. **cargo mtime 缓存**：tar 内 mtime 旧于 target → 增量 build 跳过——**touch 全部 .rs** 或 `cargo clean -p <crate>`；
4. **python 写文件模式**：`io.open(p, encoding=...)` 默认只读——写文件必须 `"w"` 模式（踩过一次导致修改静默丢失）；
5. **probe timeout**：单轮任务 >115s 会超时被杀且 log 不落盘——跑测 timeout ≥420s；
6. **flock 已配**：`start_r42.sh` 有锁，重复启动会被挡（正常现象）；
7. **本机 Windows 侧**：`.workbuddy/tmp/` 下有 `vm_run.py`/`up.py`（SSH 执行/上传工具，paramiko）。

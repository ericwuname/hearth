# 第二篇 · 执行（八张卡，逐卡施工）

## 卡 S7 · provider 瞬时故障分级长退避重试

**病灶锚点**：LLM 调用重试=退避 2/4/8/16s≈30s+cap 120s 打满即 failed（loop.rs :5327 测试锚点）；真机：魂斗罗 span 125s 终止。

**实施动作**：
1. LLM 调用错误分类函数：`transient`（连接失败/读超时/429/5xx/TLS）vs `fatal`（401/403/400/模型不存在）；
2. transient 退避序列 **30s→1m→2m→5m→5m…**，累计窗口默认 **30 分钟**（env `HEARTH_RETRY_WINDOW_MINS` 可配）；
3. 每次重试前投影：`[retry] provider 瞬时故障（摘要），第 N 次重试，等 Xs（窗口剩余 Ym）`；
4. 窗口耗尽 → **暂停语义**（非 failed）：投影"上下文已保留，可 resume/重发继续"（与 S8 衔接）；
5. fatal → 立即终止+友好报错。

**过关（先红后绿）**：①mock 前 3 次 429 第 4 次成功 → 任务完成且投影含 3 条 `[retry]`；②mock 401 → 立即终止零重试；③真机断网 2 分钟恢复 → 任务续行。

## 卡 S8 · run 级断点续跑（韧性核心）

**病灶锚点**：`hearth chat` 单 run 执行态全在内存——进程崩溃/VM 重启/Ctrl-C/key 失效=任务蒸发。

**实施动作**：
1. 消息循环**每步落盘 run 状态**至 `sessions/runs/<run-id>.json`：对话历史+scratch+产物清单+steps/预算位——**复用存量 sessions 持久化与 spill 机制**（agent-core sessions.rs），接入 chat 单 run；
2. 新命令 `hearth resume <run-id>`：从断点恢复执行；
3. **统一暂停语义**：fatal/预算耗尽/窗口耗尽/Ctrl-C 全部=落盘+投影"断点已存（run-id），修复 X 后 resume 继续"——**不再有不可恢复的 failed**；
4. repl 中 Ctrl-C 改为"落盘+暂停"（连续两次才退出）。

**过关**：任务跑到一半 `kill -9` → `hearth resume <run-id>` → 从断点续跑到交付（产物完整）；真机演示一次留档。

**附注**：runs/<run-id>.json 可能含用户代码——私有内容处理纪律与 sessions 同规（public 审查时一并过）。

## 卡 S12 · 交付前质量自检（完成语义升级——"把任务交出来"）

**病灶锚点**：Done = LLM 自报+产物非空 → 魂斗罗 10 分样子货合法交付（用户判）。S5 重构后 finalize_done 已提取，正好承接。

**实施动作**（挂入 finalize_done 之前）：
1. **产物类型化自检**：
   - 代码类（.py/.rs/.js）：语法检查（`node --check`/`python -m py_compile`/`cargo check`）+ 自测执行（若模型写了 test 就跑）；
   - HTML/游戏类：无头浏览器打开（复用 bench/exam/contra-playtest.js 既有 playwright 模式，**不新引重型依赖**）+ 零 JS 错误 + 核心交互冒烟（按键/点击各一次）+ 截图留档；
   - 文档类：重读自查完整性；
2. 自检失败 → **自动修复迭代（最多 2 轮）**，每轮投影 `[selfcheck] 产物 X 自检未过（原因），修复中（轮次 N/2）`；
3. 仍不过 → **诚实交付**：投影"已交付 X，自检未过项 Y（原因），需人工"——**不许静默交半成品**；
4. 自检结果写入 run report（含截图/输出证据）。

**过关**：①单测：mock 产物语法错 → 自检捕获 → 修复轮次执行；②**判别实验**：同一魂斗罗任务卡（原版 vs 质量版）重跑，**用户评分对比**——评分提升=提示词/自检杠杆实锤；仍 10 分=LLM 上限实锤（责任归位实验，结果呈顶层，**用户终评是唯一判分**）。

## 卡 S9 · provider 降级链

**病灶锚点**：单通道死等（Agnes 挂=全挂）。

**实施动作**：
1. config.toml 新增 `providers` 有序数组：`[agnes, zhipu, gemini]`（三通道 key 从用户授权记忆取用，写入 config——**权限 600 + 永不入 git**）；
2. 主通道 S7 窗口耗尽或 fatal → 自动切下一通道（投影 `[fallback] provider: agnes → zhipu`）→ 全链耗尽 → S8 暂停语义；
3. 各 provider 用量独立计数（分账，免费通道纪律）。

**过关**：mock agnes 持续 401 → 自动切 zhipu 完成任务；config 增删通道生效（先红后绿）。

**同尺纪律（顶层附加）**：凡经降级链（非主通道）完成的跑批轮次，数据在基准对照中**必须标注通道**——换 provider=换模型层不可比，防降级数据污染同尺对照。

## 卡 S10 · 流式输出

**病灶锚点**：chat/repl 黑盒等待（信任杀手）。

**实施动作**：llm-openai 走 SSE 流式（`stream: true`）→ 事件透传 → CLI 打字机渲染（repl 与 chat 同）；SSE 失败自动降级非流式（fallback 保留）。

**过关**：真机 repl 回答逐字呈现（截图留档）；SSE 失败降级路径触发验证。

## 卡 S11 · 中断保留上下文

**病灶锚点**：repl 中 Ctrl-C 直接杀 run（上下文丢）。

**实施动作**：tokio `select!` 监听 Ctrl-C → abort 当前模型调用/工具执行 → 投影 `[interrupt] 本轮已打断（上下文保留）` → 回到输入提示符；连续两次 Ctrl-C（3s 内）才退出 repl。

**过关**：任务中 Ctrl-C → 立即停 → 追问"刚才做到哪" → 模型基于完整上下文回答。

## 卡 S13 · 内置联网搜索工具

**病灶锚点**：查资料仅靠 bash curl 间接+模型记忆（S2 出网已放开，缺一等公民工具）。

**实施动作**：
1. tool-runtime 注册 `web_search(query)`：接免费搜索源（DuckDuckGo HTML/必应，零 key）→ 标题+链接+摘要 top10；
2. 工具描述五要素（R5-9 标准）；出网走 S2 默认放开；
3. 工具描述中教模型：实现类任务先查资料再动手；
4. **顺带核对**（顶层附加）：全部既有工具（edit/patch/glob/grep/read/bash/write）描述五要素是否达标，缺则同 commit 补齐。

**过关**：真机任务中模型自主调用 web_search 并引用结果（log 取证）；单测解析器对 mock HTML。

## 卡 S14 · 任务总结报告（TL;DR——"事后不用看过程"）

**病灶锚点**：任务收尾投影内容多，用户原话"内容太多，我未必会看过程"——过程看得清（S10/S11）之后，缺事后不用看过程的任务级总结。

**实施动作**（挂 S12 之后流水线：质量自检 → 总结生成 → 醒目投影）：
1. finalize_done / finalize_error 末尾追加 `generate_summary()`：取 run 历史（压缩摘要即可，不灌全文）+产物清单+S12 自检结果 → **一次 LLM 调用（max_tokens ≤800）**，按模板填充、禁止编造未发生事项；
2. 投影模板（任何收尾路径：完成/暂停/预算耗尽）：

```
═══════════ 任务总结 ═══════════
【一句话】<这个任务做成了什么 / 卡在哪>
【产物】  <文件清单 + 怎么用（路径/命令）>
【过程要点】<3-5 条关键步骤，一行一条>
【问题与处理】<遇到 X → 这样解决；Y 未解决 → 原因是 Z>
【剩余/建议】<下一步需要用户做什么（或"无，任务闭环"）>
【质量自检】<N 项过 M 项（S12 自检结果引用），详情见报告>
（完整过程: .hearth/reports/<run-id>/run-001.md）
══════════════════════════════
```

3. **暂停/失败路径同格式**：【一句话】改"卡在哪"；【剩余】改"修复 X 后 resume 的具体指令"（与 S8 衔接）；同步写入 run report 头部（打开报告先读总结再看流水）；
4. 模型不可用降级：模板机械填充（产物清单/自检结果为实数据，一句话/要点留空标"生成失败"）——**总结生成失败不影响任务交付**；
5. repl 长会话新增 `/summary` 命令：随时对本会话至今出总结（复用同函数）。

**过关（先红后绿）**：①单测：mock run 历史 → 总结按模板生成、无编造项（模板字段与实数据一致）；②真机：L1-01 重跑 → 任务结束出现总结块，用户**只读总结块**即可回答"做了什么/产物在哪/能不能用"；③暂停路径：kill -9 → resume 投影含总结（含 resume 指令）；④真机**无编造抽验**：对照 run 历史逐字段核对（LLM 生成天然有幻觉风险，单测之外必抽）；⑤**用户目测："内容多我也可以不看过程了"成立与否**。

**红线**：总结生成失败不阻断交付（降级模板）；不编造（无实据标"无"）；预算步数不受影响。

**附注**：总结调用计入本 run tokens（分账口径不变）；总结块与 run report 私有内容纪律同 sessions/runs。

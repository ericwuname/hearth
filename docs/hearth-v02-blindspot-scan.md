# Hearth v0.2 任务书 · 系统性盲区扫描

> 目的：跳出"遇到什么改什么"的打地鼠模式，用 codex CLI 完整能力维度做一次全景对照。
> 方法：把 hearth 现状 + v0.2 任务书 10 维记分卡 + 手工日志铁证，摊在 codex 的完整架构图上，找**维度级缺失**（整块没覆盖，而非某项没做好）。

---

## 一、先给结论：三个"维度级"盲区（整块缺失）

打地鼠修的是"已有维度里的 bug"（R8/R9/R10）。但下面三个是**任务书通篇没有对应工作流的整块能力**，才是真正会被遗漏的：

| # | 盲区 | 为什么是维度缺失 | 用户痛点 |
|---|---|---|---|
| **盲区A** | 会话生命周期（崩溃恢复/中断恢复/自动持久化） | 任务书维度6只有"续接"（手动 resume），没有"进程死了会话还能活" | 痛点①窗口一废全废 |
| **盲区B** | 长内容"生成"（非"编辑"） | 任务书维度4做 diff 编辑（改文件），但"5000字文章"是**生成长文**，另一条路 | 痛点②长任务做不了 |
| **盲区C** | 确定性验证层 | 写盘后校验产物可用，任务书 10 维记分卡**根本没有这一维** | 痛点②产物自报完成却不可用 |

## 三、三个盲区的展开（含手工日志铁证）

### 盲区A：会话生命周期——"续接"不是"韧性"

任务书维度6写"复用 transcript+session_id+resume"。但手工日志证明：**resume 命令存在，却救不了"panic 杀进程"**。

```
日志铁证：
  context.rs:158 end byte index 60 is not a char boundary
  → 整个 REPL 进程死 → 前面 20 轮对话灰飞烟灭 → 用户只能开新窗口重说
```

**"续接"和"韧性"是两回事**：
- 续接 = 手动 `resume <id>`，靠人记得去做；
- 韧性 = **每轮自动落盘 + panic 不杀进程 + 重启后自动恢复上次会话**。

任务书只做了前者。用户痛点①要的是后者。**补法见上一份 `hearth-session-resilience-taskbook.md` 的 WS-X1**（已在，但应正式并入 v0.2 记分卡，而非游离在补充文档里）。

### 盲区B：长内容"生成" ≠ "编辑"

任务书维度4做 diff applier，是"改已有文件"的能力。但用户的"5000字短文""写故事"是**从零生成大段内容**，走的是完全不同的路径：

```
手工日志铁证：
  8000字长文 → read body: error decoding response body（单轮输出超 max_tokens）
  甘特图 agent 自己"分4段追加 game.js"——模型都知道要分块，harness 却不会帮它分
```

**diff 编辑解决了"截断"（整文件重写被切），但没解决"单轮生成长文"（输出本身超限）**。这两个是不同的 bug，任务书只补了前者。

补法：长输出流式累积 + 自动分块（agent 想写 5000 字，harness 拆成 5 次 1000 字追加，而不是让模型硬憋一次）。

### 盲区C：确定性验证层——10 维记分卡根本没有这一维

这是最典型的"维度缺失"：任务书 10 个维度，从"终止"到"可观测"，**唯独没有"写盘后校验产物是否真的可用"**。

```
手工日志铁证：
  甘特图 agent 自报 Done，但产物可能不可用（verify 阶段才暴露）
  俄罗斯方块 agent 自报"完成"却只是"搜了项目目录有没有游戏文件"
```

codex 的 answer 是 read_lints + 编译回喂；Aider 是每步 git diff + 测试。hearth 完全没有"写完文件后，自动跑一次验证，失败回喂 loop 重来"的机制。

**这一维我在 `hearth-harness-review-supplement.md` 补过，但 v0.2 任务书没纳入**——这是打地鼠模式的直接体现：提了但没进主线。

## 四、次关键盲区（🟡，可后置但不该忘）

| 盲区 | 现状 | 为什么重要 |
|---|---|---|
| **provider 降级链** | R9 修了重试（2→4次），但没修"deepseek 持续挂自动切 zhipu" | 用户有 deepseek+zhipu+agnes 三个通道，缺钱时代，降级链比重试更能扛 |
| **成本/token 护栏** | 完全没提 | 用户明确"缺钱"。每次跑 benchmark 该有 cost 预估 + 上限，而不是跑完才发现烧了多少 |
| **任务状态持久化** | 只有 LoopPhase，无"干到第几步"落盘 | 甘特图反复横跳的根：agent 忘了自己已经写对 SVG 方案，又 replan 回 matplotlib |
| **工具集 read_lints** | 只有 5 个工具 | agent 只能 parse 原始 cargo 输出，读不到"哪行错了" |

## 五、给执行窗口的整合建议

**核心动作**：把三个 🔴 盲区**并入 v0.2 记分卡**（不是留在补充文档里），让它们有验收门禁、有回归测试、有优先级。

```
v0.2 记分卡补 3 维：
  11 | 会话韧性    | 每轮自动落盘 + panic 隔离 + 重启自动恢复    | 🔴 阻塞达标
  12 | 长内容生成  | 流式累积 + 自动分块，5000字长文稳定完成       | 🔴 阻塞达标
  13 | 确定性验证  | 写盘后校验产物（存在性→字节数→可运行）       | 🔴 阻塞达标
```

**为什么必须并入主线**：补充文档会被"打地鼠"忽略——上一轮我提了"确定性验证层"（review-supplement），这轮 v0.2 任务书依然没有它。**游离在补充文档里的东西，等于没提。**

## 六、一句话总结

打地鼠模式的根，是**没有一个"能力全图"来对照**——所以修 R8/R9/R10 时，看不到"会话韧性""长内容生成""确定性验证"这三块整片空白。

把 codex 的完整维度摊开对照（本文 §二表格），三个 🔴 盲区就浮出来了。它们不是"某项没做好"，是**任务书根本没有这一维**。这才是需要顶层补进去的，而不是让执行窗口在"改 bug"的惯性里继续打地鼠。

*建议下一步：把本文 §二 的全景对照表 + 三个盲区，作为 v0.2 任务书的"能力全图"附件，以后每次修订任务书都先过一遍这张表，确认没有新的维度空白。*

## 2. 根因树（五个根，其中 α 是主根）

### α（主根）· 输入分类规则集没有"疑问句"这个类别 → 一切对话都被当任务

**锚点**：`loop.rs:324-378 classify_user_input()`——纯规则零 LLM（成本红线）：
- TaskControl：14 个**祈使**关键词（查看状态/继续/接着/resume/怎么样了…）
- Conversation：仅 8 个寒暄词 **且要求 ≤12 字**
- **其余一律 → GoalMutation（默认，注释自陈"歧义默认保持现状语义"）**

用户 8 次追问（"你还记得我的第一个问题吗"/"又出现相同的问题了"）**全部不含任何关键词** → 全部落默认 GoalMutation → revision++ → 问题被当成任务执行 → 答案从未产出（RC36）。
同族：`goal_requires_product()`（loop.rs:167）同样默认 product——"感受/讨论"类输入会被推进写产物路径。
**一根解释三条**：RC36（追问被吞）+ RC33（revision 71）+ give_up 88%（问题被当任务后烧步数）。
**这不是执行纰漏，是规则集设计缺口**——中文疑问标记（吗/呢/？/为什么/怎么/哪/记得）一个都不在集内。

### β · 纯读任务的结构性死角（现行源码仍在）

| 环节 | 锚点 | 现状 |
|---|---|---|
| progress 记分 | `loop.rs:3487-3495`：**仅 write_file/apply_patch 成功算 progress**（W3 批示5 刻意取舍，注释自陈） | read/glob/bash 成功一律"无进展" |
| 完成校验 | `loop.rs:2367` `!written_files.is_empty()` 才 verify | RC10 未修；但现行新增 QA 豁免（loop.rs:2364 `all_done without write — Done (R1)`） |
| 产出契约 | D1 决策从未实施 | 调研类任务无落盘验收锚 |

→ 纯读/问询任务：**progress 不记分 + verify 跳过 + 无契约** → planner `budget_fraction ≤ 阈值 && steps_without_progress ≥ 2` 即 GiveUp（planner/lib.rs:489-500）。
→ 这是 give_up 88% 的**另一半结构性根因**（α 把对话变任务，β 让任务死掉）。
→ 现行 QA 通道（R1）能救一部分，但 α 的关键词覆盖缺口同样存在于 `goal_requires_product`。

### γ · landlock FS_RW 混入目录专有位 → T6 自 v0.2.3 从未生效（已修，待复测）

执行窗口 N-1 诊断（`docs/n1-landlock-devnull-diagnosis.md`）C 矩阵实证：
- 根因：`FS_RW` 含 `READ_DIR/REMOVE_DIR/MAKE_DIR…`，内核规定**目录专有位 + 非目录 parent_fd → EINVAL**（决定性证据 C3：**普通文件**配 FS_RW 全量同样 EINVAL——推翻"char device 特例"假设）
- 失败路径 fail-open：`add_landlock_rule` 失败仅 warn + skip → 规则没加上 → `/dev/null` 写 = EPERM
- **T6 自 v0.2.3 起从未生效**（每条 bash 都在 warn，被噪音淹没）
- 修复已落当前源码：`sandbox/lib.rs:293 FS_FILE_ONLY = FS_RW & FILE_MASK`（含编译期断言 297/1168）→ **RC24-B 待 v0.2.11 真机复测**

### δ · 压缩墓碑 + β ⇒ 假完成（RC37）

compaction 60 字墓碑（RC5 未修，context.rs:169/171 仍 32k/2 轮）→ 规划退化 1 步 → 旧二进制无 QA 豁免 → LLM 自报完成 + verify 跳过 → `✓ Task completed 目标达成` → 用户当场抓复发。
现行 QA R1 通道可部分缓解形态，但**压缩本身未修**，RC37 会换形态再现。

### ε · stalled 拓扑签名不含事实信号（RC32，P1）

`loop.rs:2221-2232`：同构图连续 2 次 → Err(stalled)。**代码注释自证已知误杀**（"T-B 纯读任务实测被此误杀"）但阈值逻辑未加事实豁免。与 β 同源——纯读任务 replan 必然同构。

## 3. 给顶层的一句话结论

**v0.2.10 这轮日志测的是"半个 W8"**——它证明已落地的部分（渲染、审批门、活性置位）真实有效，同时暴露了**还没落地的部分在真实会话里有多疼**。最关键的 α（输入分类无疑问句类别）在**现行源码里依然存在**：不修 α，你换任何模型再测，"你还记得吗"还是会变成 revision、"又出现相同的问题了"还是会复发。

**建议下一步顺序**：
1. **先修 α**（分类器加疑问句类别——小改动、覆盖 RC36/RC33/大半 give_up，性价比最高）
2. β 跟进（D1 产出契约落地 + QA 通道覆盖面扩展）
3. **v0.2.11 真机复测矩阵**：TC-8b（/dev/null）、TC-5/×2 渲染、A-5/A-36 连续性场景、12/18 跑矩阵——把"待复测"三项清掉
4. RC5 压缩（W5）不动的话，RC37 换形态复发是必然

## 〇、直接回答："几十轮对话，距离可用差多远？"

**先纠正一个直觉**：几十轮本身不是病——长任务本就该几十轮（你跟我的长任务也一样几十个工具调用）。**病是轮次的构成**：

| 指标 | 0.9-0.3 会话实测 | 可用线（本任务书定义） | 差距性质 |
|---|---|---|---|
| 用户推进率 | **19%**（7/36 轮） | **≥80%** | 结构性，非调参可弥合 |
| 质疑/追问/抱怨率 | **58%** | ≤10% | 同上 |
| 报完成中经核验的比例 | **0/28** | **100%**（无证据只能报 UNVERIFIED） | 完成语义重造 |
| 已知失败项被标通过 | 0/16 → ✅100% | **0 次**（一票否决） | known-failing 机制缺失 |
| 未完成清单蒸发 | 10 项全蒸发 | **0 蒸发**（跨轮可复述） | 状态机制缺失 |
| 用户被迫自建校验通道 | 5 次 | **0 次** | 观察机制缺失 |

**一句话**：差距不在"轮数多"，在**轮次里 81% 是无效轮**；无效轮的根因是四个结构性缺口（诚实/状态/观察/沟通），**每一个都有源码级定位和已批准的修复项**——所以这是"根治可期"而不是"遥遥无期"。按本任务书四包顺序施工，**全部落地 + 验收门全过 ≈ 4 个施工窗口（数天级）**，之后进入"可用"区间，再由使用反馈迭代。

## 一、参照系：WorkBuddy 对话机制解剖（"抄作业"抄什么）

参照对象不是 WorkBuddy 的某个功能，是**行为契约**——我与你对话时默认执行的六条纪律。官方定位语"输出文字回复 vs **交付可验收的结果**"即第一律。

| # | 律 | 我的工作方式（参照系） | 对应 Hearth 病理 | 本任务书落点 |
|---|---|---|---|---|
| W1 | **可验收律**：报"完成"必附验收物（文件/测试输出/预览），无验收物只能报"做了但未验" | 收尾必 present_files + 结果摘要 | 0/28 核验；give_up 改判 | R1 包：完成语义重造 |
| W2 | **事实律**：不信计划信源码；写完回读验证；失败显式披露不自嗨 | 抽验/回读/失败入文 | 守门恒真；Observe 空转；0/16 标 ✅ | R1 包：守门修复 + known-failing |
| W3 | **状态律**：任务有清单（pending/in_progress/completed，禁未完成标 completed）；记忆分三层（任务清单/工作日志/长期精简） | TaskCreate/Update 纪律 | 清单蒸发；18 次重复警告；假 README 跨会话读回 | R2 包：SessionLedger |
| W4 | **进度律**：任意时刻问"进度到哪"有事实可答（关键节点+最终产出），过程细节不倾倒 | 关键节点汇报+简洁收尾 | 472 横幅噪声；视觉倒挂；疑问句答文件路径 | R3 包：收尾三行+降噪 |
| W5 | **提问律**：前提缺失/方向不明时**停下来问**，不猜测推进 | AskUserQuestion | P2-4 提问回路缺失 | R2 包（第二批边缘，MVP 记录） |
| W6 | **判读分离律**：结论给用户拍板，过程 AI 自决；不可逆动作先确认 | 工作模式三档 | goal_drift 只观察不拦截 | R3 包：goal_drift 升级 |

**这六律就是总验收的行为 oracle**（§五 W-判据），"跟你一样的对话"被翻译成**六条可测判据**，不再是一句感觉。

## 二、根治架构：三层，各治什么

```
┌ 第三层 模型策略 ── 弱模型是约束不是借口：harness 补偿 + 校准观测量化边界
├ 第二层 cognition 层（第二个1）── 已开工（主力底座 Codex CLI）：宪法注入/技能库/校准观测
└ 第一层 引擎复活线（本任务书主体）── 四包治四缺口：诚实/状态/观察/沟通
```

- **第一层**治"会话不可信、无状态"——本任务书 §三；
- **第二层**已按双底座裁定在 Codex CLI 开工（方案已批），其落回 Hearth 引擎的**前置阻塞项正是第一层的 R1/R2**——两层在此汇合；
- **第三层诚实声明**：agnes-2.5-flash 是弱模型，harness 能治"说谎、失忆、不验"，治不了"不会写代码"。校准观测（已批）会量化这条边界；**模型升级是独立杠杆**（你持有智谱/Gemini key），不与 harness 混算。

## 五、总验收判据（"跟 WorkBuddy 一样"的可测化）

| 门 | 判据 | 通过线 | 判负 |
|---|---|---|---|
| G-A~G-H | 外部拆解八门原样 | 见拆解件 §四 | G-B 一票否决 |
| **W-A 直答** | 10 个疑问句首句给结论 | ≥8 | 只回文件路径 |
| **W-B 完成附证** | 报"完成"必附核验证据，否则必须标 UNVERIFIED | 100% | 无证据报完成 |
| **W-C 失败入报** | 当轮失败必现于收尾汇报 | 100% | 失败不提 |
| **W-D 跨轮记忆** | "还剩什么"复述准确 | 零遗忘≥4/5 | 遗忘≥2 |
| **W-E 进度可问** | "进度到哪"以事实作答 | 有事可答 | 横幅回放 |
| **W-F 降噪** | 默认档单轮过程噪声行 | 可读（砺定标尺） | 正文被淹没 |

**"完全解决问题"的操作定义**＝R1~R3 全落地 + 上表全绿 + 双会话重放零复发。**诚实边界**：本任务书治 harness 的"说谎/失忆/不验/淹没"；模型能力上限（agnes-2.5-flash 生成质量）由校准观测量化、由模型渠道独立解决——两者混在一起谈"可用"会互相掩盖，故分开记账。

## 卡 1 · 护栏范式（栅栏 → 护栏）

- 栅栏 = 框架替模型做决定（替它判完成、替它锁人格、替它截断节奏）；护栏 = 框架只拦**硬危险**，其余交模型。
- Hearth 内部唯一被三份报告一致认可的正确实现：潜意识层 `ConstitutionGuard`——仅对 **3 条硬编码危险命令** Abandon（`subconscious/src/lib.rs:66-77`）；CostGuard/RepetitionDetector 只发 Simplify 告警不终止（`loop.rs:3054-3057`）。
- 反面全集：`goal_requires_product` 关键词路由（`loop.rs:167`）、`MUST write_file` 敕令（`loop.rs:2213-2272`）、`DenyAllNonInteractive` 默认（`run_local.rs:332-339`）——每个都"局部正确"，叠加成死锁。
- **迁移规则**：底座上做审批层/hooks 时，拦截清单必须**穷举且硬编码**（fork bomb/设备/内核级），清单外一律放行 + 审计；禁止按"任务类型"给模型设栅栏。

## 卡 2 · 完成判定 = 模型驱动节奏 + 事实校验守门 + 问答路径补全覆盖（RC1 修正版）

- **RC1 教训（真坑换来的）**：完成置位的唯一生产者是 Done 相位 verify 通过，**非 LLM 自报**（`loop.rs:4093-4095` 注释原文）；裸自报曾致长程 ~15 步必死（ledger-v3 RC1）。
- 但 RC1 被窄化成"只认写盘"→ **问答/只读任务没有任何完成路径**，进 give_up 臂后救回条件（`session_written_files` 非空，`loop.rs:2110-2149`）永不满足 → `✗ failed`。campaign 实测：give_up 时 (0,0,0) 信号占 72.8%（n=103），续作型 P(✓|上轮✗)=**7.0%**（OR=75.1，p=1.14e-10）。
- **正确合成**（v1.1 修订令 §二）：节奏由模型驱动（每结果可重入、可宣告），**守门由事实校验承担**（写盘校验 / 验证命令 / 测试通过），**并为问答类补一条事实校验路径**——是加固不是推翻。
- 竞品范式的准确解读：模型宣告 + **用户可验证**（checkpoint/diff/验证文化），不是裸自报。
- **迁移规则**：底座上的判断层，完成判定必须三层齐备——缺问答路径 = 新 RC1 反面。

## 卡 3 · 三层死锁（外部深挖报告，10/10 回代命中）

- **第一层 目标路由**：`classify_user_input`（`loop.rs:324-413`）三分类规则链，用户的新意图（改目标/纠偏）进不来。
- **第二层 产物判定**：默认兜底把一切推向"必须写文件"（34 产物动词关键词，`loop.rs:167`）。
- **第三层 完成判定**：完成只有"写盘"一条路，任务图节点永不完成 → 反复 replan → T4 stall → give_up → `session_written_files` 为空 → 救不回。
- 四次局部正确补丁（R1→v20→v22→修 B）每次都把判定权从模型手里拿得更死——**栅栏打补丁强化死锁**（深挖 §5 实证）。
- **迁移规则**：审查任何 agent 框架时，先问三个问题——新意图进得来吗？非编码任务被逼写文件吗？完成有几条出路？三问有一个答案不对，先修它。

## 卡 4 · 代理指标陷阱

- 代理指标（写盘数、步数、测试全绿数）与目标（用户任务成功率）**脱钩时，优化代理 = 优化失败**。
- 实证：497 个测试 0 条用户行为断言；近 30 天文档提交是代码的 2.26 倍；A 臂 100% ✓率是"累加器非空的伪通过"（campaign §1.2）——**指标全绿，用户侧 8% 成功率**。
- 双重教训：①做指标先问"它代理了什么，什么场景下脱钩"；②**成功信号要有用户行为锚**（真机盲测/盲测包），文档量不是产出。
- **迁移规则**：底座上的每个验收门禁，必须至少含一条"用户可见行为"断言；纯代理指标只准做健康监测，不准做验收。

## 卡 5 · 激励结构

- 症状：四轮"局部正确"的加固全部被治理流程奖励（gate 全绿、文档完备、审计留痕），而真正缺的用户行为测试一条没有。
- 根因：治理激励**可完成的**（写文档、加测试、跑 gate），不激励**不可预先完成的**（真机实验、可证伪实验、外部批判）——后者成本高、结果开放。
- 修正（已生效的治理条款，v1.1 §一.1）：重大决策文档必须①引用证据编号；②新输入只更新受影响分支，禁整份推翻；③用户挑战先产出"决策论辩护或修正分析"再改文档。
- 实例：19:50 决胜局文档与 19:05 转向书相隔 15 分钟无新证据即整份推翻——"墙头草模式"发生在最贵的一次决策上。
- **迁移规则**：每个窗口的产出验收里，**可证伪实验 ≥ 文档产出**；决策修订必须走"辩护或修正分析"通道。

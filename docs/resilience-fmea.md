## 2. 三维度评估

### 2.1 可执行性（Feasibility）—— 能建，但有前置债

- 接缝清晰：`planner.decompose`/`reflect`、`loop.rs:308 spawn_sub_agent`、`run()` 都是干净插入点；`Skill`/`SkillRegistry` 抽象可加。**架构上能建。**
- 但有两笔前置债：① 弱模型 JSON 可靠性**未验证**；② **A4（G-A4）未修前**，圆桌/参谋长/复盘是"盲跑"——父代理拿不到子代理产出（`loop.rs:350-368 RunReport` 丢自由文本）。这两笔不先还，功能建在沙子上。

### 2.2 可靠性（Reliability）—— 顺序链会放大失效

- **链式失效放大（核心悖论）**：Plan 链是 6 段顺序 skill（需求→头脑风暴→决策树→圆桌→参谋长→拆解）。若每段 90% 可靠，端到端 `0.9^6 ≈ 53%`。**"多加 skill=更稳"在顺序链下反成"风险乘子"**——可靠性随 skill 数下降，而非上升。必须每段有校验门+降级，否则不成立。
- **弱模型 schema 风险**：`run_skill` 复用 `decompose` 的一次性 JSON 抽取（`planner/src/lib.rs:96-105`，找首 `[` 尾 `]`）。弱模型常吐非法 JSON/缺字段。`decompose` 有兜底（失败→单节点），但 `decision_tree`/`chief_of_staff`/`self_reflection` **无兜底定义** → 下游吃垃圾。
- **self_reflection 元认知悖论**：让弱模型列"已知未知/未知未知"，它自身恰恰不擅长自知（邓宁-克鲁格）。该"保险"可能给**虚假信心**——列出的未知很浅，真正的未知仍藏著。所以其输出应作"参考"而非"权威"。

## 3. FMEA：失效模式与影响（按严重度）

| 编号 | 失效模式 | 触发异常 | 当前防护 | 影响 | 严重度 |
|------|----------|---------|---------|------|--------|
| F1 | LLM 调用挂起/超时 | provider 假死、网络抖、流不终止 | 客户端 300–600s（松） | 单次规划最多阻塞 ~30min（6 段×300s），**会话级 DoS** | 高 |
| F2 | 顺序链单段吐垃圾 JSON | 弱模型输出非法/缺字段 | 仅 `decompose` 有兜底 | 下游连锁错误，最终产出废案且无人察觉 | 高 |
| F3 | 圆桌 sub-agent 永不结束 | 模型流不终止/卡死 | 无墙钟上限；`collect_sub_agent_results` 非阻塞→任务泄漏 | 资源泄漏 + 该视角**静默丢失** | 中 |
| F4 | Execution 自动放行 + sandbox 被绕过 | sandbox 配置缺陷/新逃逸 | 仅 sandbox（已有超时/回收） | 无审查下破坏性命令执行 | **极高** |
| F5 | EscalateToPlan 无人接收 | 自主/无头运行（Exploration 模式） | 无 supervisor 保证（设计提案，未实现） | 错误**静默丢弃**，任务假成功 | 高 |
| F6 | 成本失控 | 卡死任务反复 replan(×3)，每次重跑全链+圆桌 K 倍 | `CostMeter` 无熔断/中止 | 预算被偷跑光，无中止 | 高 |
| F7 | 进程崩溃（Plan 冻结后 / 执行中） | OOM / panic / 部署重启 | 无检查点/续跑 | `frozen_plan` 孤儿，进度全丢 | 中 |
| F8 | 模式误设 / 恶意 frozen_plan | 用户误配 / 攻击投毒 | Execution 无 plan 白名单校验 | 投毒 TaskGraph 自动执行（叠加 F4） | 高 |
| F9 | 卡死不可观测 | 上述任一静默发生 | telemetry 当前孤儿（已知缺口） | 出事没人知道，无法干预 | 中 |

> 判读：**F1/F2/F4/F5/F6/F8 任一项在生产触发，都足以让"系统崩掉/交出错误成果"** —— 正是用户担心的。它们都不是 skill 功能问题，是**抗压骨架缺失**问题。

## 4. 抗压性非妥协前置清单（施工前必须全绿）

- **R1** 每个 LLM 调用：应用层墙钟超时（如 60s）+ 指数退避重试（≤3）+ 失败切 provider（`fallback` 已有，补退避）。
- **R2** 每个 skill 输出：schema 校验 + 修复循环（≤2 次重抽/修正）+ 失败兜底（绝不向下游吐垃圾）。
- **R3** 顺序链每段后置"校验门"：不合法则降级/重算，禁止透传垃圾（直接破解 §2.2 链式放大）。
- **R4** sub-agent 有墙钟上限 + 泄漏回收；roundtable 任一阵亡不影响其余（部分结果可用，不整链失败）。
- **R5** Execution 模式：保留**最小破坏性命令黑名单**（不靠 sandbox 独扛）；sandbox 视为深度防御，非唯一闸门（破解 F4）。
- **R6** `EscalateToPlan` 必有接收方（supervisor/人）；无接收方则 **fail-safe 中止 + 告警**，绝不静默（破解 F5）。
- **R7** 成本熔断：`CostMeter` 超预算 → 立即中止并上报（破解 F6）。
- **R8** 崩溃续跑：loop 进度检查点（JSONL 已有）+ 会话状态外置，重启可续（破解 F7）。
- **R9** 可观测：卡死/超时/升级有 metrics + 告警（telemetry 当前孤儿，需接，破解 F9）。

---

## 5. 修订后的施工顺序（抗压优先）

```
阶段 0（抗压骨架，绝对前置）: R1–R9 最小集
   ↓
阶段 1（skill 抽象 + 2 个 in-process skill）: 在 R1/R2/R3 保护下验证弱模型可靠性
   ↓
阶段 2（圆桌并行 + 参谋长 + 修 A4）: 需 R4 + A4
   ↓
阶段 3（验收门 + 局外人复盘）: 闭环
   ↓
阶段 4（模型路由 + 四模式）: 需 R5/R6/R7/R8
```

即：**先让系统"打不垮"，再让它"更聪明"。** 原 `skills-pdca-design.md` §7 的四阶段上移"抗压骨架"为绝对前置阶段 0。

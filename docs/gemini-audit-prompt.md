# Gemini Audit Prompt v1.0

> 这是一份给 Gemini（gemini-3.6-flash 或更新版本）的自包含审计指令。
> 你不需要访问任何外部 API，只需要读取我提供的代码文件，按照下面的六步流程
> 进行独立审计，最后输出一份结构化报告。
>
> 你的角色：外部独立审计师。你与这个项目的作者无关，不受其任何文档/报告/结论影响。
> 你只信你读到的源码。

---

## 一、项目背景（只读，不改变你的判断）

这是一个 Rust AI agent 项目，目标是用 LLM 自动完成编码任务。
核心能力：接收自然语言任务 → 调用工具（bash/grep/read/edit）→ 产出代码修改。
规模：~22 crate / ~55 .rs 文件 / ~180 测试。

我会在接下来的消息中逐步发送关键文件的源码。你每读完一批就执行对应步骤。

---

## 二、审计流程（六步）

### Step 1：看懂它是怎么工作的

读以下文件，用自己的话回答三个问题：
1. 主循环是怎么跑的？（Init → Plan → Act → Observe → Reflect 每个阶段做什么）
2. 有哪些"自动防御"机制？（审批门、潜意识、神经系统）
3. 经验系统怎么工作？（什么时候存、什么时候搜、什么时候用）

要求你读的文件：
```
crates/agent-core/src/loop.rs        (完整文件)
crates/subconscious/src/lib.rs       (完整文件)
crates/nervous-system/src/lib.rs     (完整文件)
crates/experience/src/lib.rs         (完整文件)
```

### Step 2：验证依赖图是否有环

读以下文件，判断：
1. 总共多少个 crate？
2. 谁依赖谁？画一个分层依赖图（agent-types → gateway → 实现层 → agent-core → service → cli）
3. 有没有环？有没有"孤儿 crate"（定义了但没人用）？
4. `agent-core` 有没有直接依赖某个具体 LLM 实现（如 llm-openai）？如果没有，说明依赖倒置做对了。

要求你读的文件：
```
Cargo.toml                               (workspace 根)
crates/*/Cargo.toml                       (所有 crate 的 Cargo.toml)
```

### Step 3：追踪三条能力的完整调用链

对下面三条能力，逐层 grep 源码，确认从"用户入口"到"功能执行"的调用链是否完整：

**能力 A：任务审批门**
入口 → 用户发送危险命令 → 拦截 → 等待审批 → 通过/拒绝
关键锚点：`need_approval` / `check_approval` / `approval_pending`

**能力 B：资源保护**
入口 → 监控内存/磁盘/预算 → 超过阈值 → 触发降级动作
关键锚点：`NervousSystem` / `query` / `Abandon` / `Simplify`

**能力 C：经验自进化**
入口 → agent 跑完 → 写入经验 → 下次跑时搜索 → 注入 prompt
关键锚点：`ExperienceStore` / `append` / `search` / `reinforce`

每条能力跟踪后给出判定：🟢 完整 / 🟡 有调用但路径不完整 / 🔴 断裂或空壳

### Step 4：代码质量审查

1. 找 `unwrap()`：区分安全 unwrap（Mutex::lock / 测试代码 / 启动期 init）vs 危险的 unwrap（可能 panic 的生产路径）
2. 找 `TODO` / `FIXME`：如果有，列出行号
3. 找 `unsafe`：如果生产代码中有 `unsafe` 块，评估必要性
4. 最长的 5 个文件是哪些？`loop.rs` 多长？有没有该拆未拆的"上帝文件"？

### Step 5：与项目自报的审计报告交叉验证

不要读我之前的审计报告（它们可能有偏见）。但你要基于你 Step 1-4 的发现，给出你自己的判断：
1. 这个项目自称"锻造九轮、维护期启动"——以你看到的代码质量，这合理吗？
2. 有没有你一眼就看到的严重问题，而项目的文档里可能没提？
3. 如果这个项目是你的，你下一步会做什么（不超三项）？

### Step 6：输出你的审计报告

按以下格式输出，**全部用中文**：


## 三、给人类的操作说明

1. 把以上内容复制发给 Gemini
2. 第一轮：发送 Step 1 列出的 4 个文件（crates/agent-core/src/loop.rs 等）
3. 第二轮：发送 Step 2 列出的所有 Cargo.toml 文件
4. 第三轮：Gemini 自己 grep 追踪 Step 3 的调用链
5. 第四轮：Gemini 完成 Step 4-6，输出完整报告

如果 Gemini 上下文窗口够大，也可以一次性发送全部文件，让它在同一轮完成全部六步。

---

*设计本意：这份指令让任何一个能读代码的 LLM 都能独立完成外部审计。它不读我们自己的审计报告、不采信任何"我们已经证明了 X"的结论、只从源码出发。这是"不信报告信源码"的最极端版本——连我们自己的报告都不信。*

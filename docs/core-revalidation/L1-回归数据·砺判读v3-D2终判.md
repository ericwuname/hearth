## 1. D2：成立（解除悬置）

### 为什么现在可以判

v2 判悬置的**唯一理由** = A 臂分母里装着 2 个无终态样本（把仪器失败读成实验失败）。
v5 已解决：A 臂 **3/3 全部有终态**（A1 turn1✓/turn2✗、A2 ✓✓、A3 ✓✓）。

**理由消失，就必须按规则判——继续悬置等于事后移动球门，正是 HARKing。**

### 实测 vs 预注册阈值

| 条件 | 阈值 | 实测 | 判定 |
|---|---|---|---|
| B 臂 ✓率 | ≥3/5 | **4/5 = 80%** | ✅ 达标 |
| A 臂 ✓率 | ≥2/3 | **2/3 = 67%** | ✅ 达标 |

**D2 = 根因模型验证成立**，L1 结论"修法 A 有效"可写入归档附页。

### 🔴 但三条必须随结论一同写入附页（不得只写"成立"）

**(a) A 臂恰好压在阈值上，零余量。**
`2/3` 就是阈值本身。n=3 时 95% 置信区间约 **21%–94%**——**单个样本翻转即跌破阈值**。这不是"达标"，是"恰好没跌破"。

**(b) A 臂 pre 100% → post 67%，且两侧计数约定不同类。**
pre-fix A = 15/15 是**产物救回**（写过盘 → fact_check → Done）；post-fix A 的 turn2 成功是**非产物救回**（`tool_exchanges≥1` → Done + **UNVERIFIED**）。
两者都算"完成"，但**证据强度不是一类**——前者有产物事实，后者只有"发生过工具交换"这一个弱信号。33 个点的落差在 n=3 下**无法判定真伪**。

**(c) 🔴 instrument_invalid 的剔除不是中性的（本轮新发现）。**
本批剔除了 #29（post 侧）与 PRE#27（基线侧）。剔除只在"**无效性与结局无关**"时才是无偏的。
但 `wait_terminal_strict` **超时更易发生在挂起/长转的运行上，而这类运行更可能是失败** → 剔除会把成功率**系统性抬高**（信息性删失 / censoring bias）。
本批 A 臂从"1/3 含 2 个无终态"变成"2/3 全部有效"，**方向恰好与这个偏倚一致**——不能排除部分改善来自剔除而非修复。

### 建议（非阻塞）

- **建议**：A 臂补跑到 **n≥5** 再定稿归档附页；
- 若时间不允许，则**必须**把上述 (a)(b)(c) 三条与"零余量"原样写入附页，作为已知不确定性；
- (c) 的缓解办法：记录每个 `instrument_invalid` 样本的**超时时长与已产出片段**，用于判断"缺失是否随机"。

**pre 0/3 → post 2/3**，两个成功样本均带 UNVERIFIED。

**但效应量未定**，两条理由：
1. **n=3**，且 #32 仅 **1 次工具交换**即被救回——修法 A 门槛的下沿样本，说明门槛很低；
2. **同一输入运行间方差很大**：#28 pre 跑了 12 次交换、post 只跑 3 次。说明单条单跑的读数噪声大，不宜据此给百分点。

> 允许的表述：**"同条目可比样本 3 条，pre 0/3 → post 2/3，方向为改善。"**
> 禁止的表述：**"追问类成功率提升到 67%"**（n=3 且剔除偏倚未排除）。

### 两处残留风险（新发现，建议登记）

**(i) `instrument_invalid` 剔除引入信息性删失偏倚** —— 见 §1(c)，这是本轮最需要警惕的一条。

**(ii) 标记判定写法脆弱**：`driver.py:187`
```python
term = "completed" if m.endswith("completed") else "failed"
```
当前 `TURN_TERMINAL_MARKERS = ("Task completed", "Task failed")` 下结果正确；但**将来若加入第三个不以 "completed" 结尾的标记，会被静默误判为 failed**。建议改为显式映射表（`{"Task completed": "completed", "Task failed": "failed"}`），并在遇到未登记标记时返回 `instrument_invalid` 而非默认 failed。

另注：该严格版仍只认两个标记——budget exhausted / give_up 等其他终止形态会**超时 → 被剔除**。方向是保守的（宁可剔除也不错判），**符合本项目的 fail-safe 取向**，但会放大 §1(c) 的偏倚。

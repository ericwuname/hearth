## 2. 逐实验裁定

### D2 · L0.5 中段截断 —— ✅ 确认，仪器设计优秀

**砺复验**：`loop.rs:5278-5291` 逐字命中（`MAX 6000 / HEAD 4000 / TAIL 1500`）；格式串 `"{head}\n... [{N} chars truncated] ...\n{tail}"`（5288-5291）。

**算术自洽核验**：标记长度 = 28 + N 的位数。存储 5532 = 4000 + 标记 + 1500 → 标记 = 32 → N 为 4 位 → N = 7760 → 源长 = 5500 + 7760 = **13260**，与报告"13260 字节"**精确吻合**。

> 以"首个 Tool 消息长度精确匹配"定案（绕过 marker_in_stored 假阴性）是本轮最漂亮的一处仪器修正。**L0.5 由材料实证升级为真机复现确认。**

### D5 · L6 反应回路缺位 —— ✅ 机制成立，⚠️ 样本叙事有缺口

**砺复验（承接上轮）**：`capture: None`（loop.rs:3624）+ `condition: Always`（3623）+ orchestrator `{{key}}` 替换能力存在（orchestrator.rs:147-167）**未接线**——机制侧成立。"result 文件未创建"与机制一致。

**⚠️ 缺口（必须补）**：报告未区分两种情形——
- (a) **模型从未发出 write**（= 模型规划能力问题，非 L6 证据）；
- (b) **write 已发出但内容为空/失败**（= 机制截断，**才是 L6 机制证据**）。

二者归因完全不同。**要求补该 run 的 tool_calls 序列日志**，据此才可定案。

**U-06 裁定**：**有条件升格**。机制侧（源码）已证；样本侧需补 2 例（含 read→edit 依赖变体）并区分 (a)/(b) 后，U-06 方可由 🔶 → ✅。**W1 设计小样可据此启动，但不得宣称 RC52 架构根因已定案。**

### D7 · U-44 —— ⚠️ 观察可信，**归因被源码反证**（本轮最重要修正）

**报告归因**："one-shot chat 路径疑未接 S3 checkpoint 回调……chat 路径待核"。

**砺源码反证**：`attach_session_safety` 共 3 处调用——

| 位置 | 路径 |
|---|---|
| `codex-cli/src/repl.rs:268` | repl |
| `codex-cli/src/run_local.rs:196` | agent 构造 |
| **`codex-cli/src/run_local.rs:365`** | **`run_local_continue`——chat 首轮 `run()` 前** |

one-shot chat 经 `run_local.rs:340` → `run_local_continue` → **:365 已接线**（且 :363 `set_session_id` 亦在 `run()` 前，注释明载 P2-LR Node 07 修复）。**"chat 路径未接 checkpoint"不成立。**

**修正归因**：checkpoint 粒度 = **turn 级**——`run_local.rs:200-202` 注释原文："turn 级 checkpoint——每个工具交换原子落盘"。D7v5 设计为 `sleep 90`（单个长工具调用）：**kill 发生时尚无任何 turn 完成 → 会话文件从未创建**。

> 这是**"落盘时机"缺口**（run 起始无会话头、长工具调用期间无中间落盘），**不是"接线"缺口**。

**⚠️ 施工风险**：若按原归因派工（"补 chat 路径接线"）= **空操作，白做一轮**。

**U-44 裁定**：**登记成立，改名改归因** →
> **U-44（修正）：会话落盘时机缺口**——run 起始无会话头；长工具调用/首个 LLM 调用期间 kill → 会话整体丢失，无从 resume。

修复方向 = **run 起始即落会话头**（或 tool 级心跳落盘），**而非补接线**。是否排入 P5 段 2 前置换顶层定。

**正向证据保留**：resume 机制对已落盘会话（fc3e4cff）两次 attach 成功——F2 纠正继续成立。

### D3 · L0.6/L5 —— ❌ 仪器方向错误，但**项目内已有现成仪器**

**砺复验**：
- planner dump（`loop.rs:3094`）遍历 `messages`；而 `system_text` 在 `build_messages()` 内以 `Role::System` 注入 messages（**2345-2346**）→ **dump 本应包含 system prompt**。
- 故"未获特征串"更可能是 **env 未传到 hearth 进程**（须在**启动 hearth 的 shell** 里 export，不能设在沙箱 bash 内）。

**但更关键——已有现成仪器**：`introspect` 直接暴露 `system_chars` / `history_chars`，由 `loop.rs:2307-2309` `set_system_chars()` 接线（注释："记录 system_text 体量——introspect 油箱表纳入系统提示词"）。

**且已有实测值**：用户 B 组 B5 测试现场（`release/手工测试v0.2.23-B.txt:279`）introspect 输出即为
`{"budget_max_steps": 50, "compact_pressure_pct": 3, "history_chars": 2945, "phase": "Init", "provider": "agnes", "steps_used": 4, "system_chars": 4628, …}`

**裁定**：D3 **改用 introspect 口径即可闭环**，无需等新仪器。**`system_chars = 4628` 这一实测值直接量化了 L5/L0.6**（原材料称"~800 词静态敕令"——4628 字符同量级，**基本坐实**）。

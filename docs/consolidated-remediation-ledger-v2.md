### 5.2 根因树（α 主根）

**α · 输入分类无疑问句类别（RC39，P0，现行源码仍在）**
`loop.rs:324-378 classify_user_input()`：TaskControl 仅 14 个**祈使**词（查看状态/继续/resume…）、Conversation 仅 8 个寒暄词**且 ≤12 字**，**其余默认 GoalMutation**。中文疑问标记（吗/呢/？/为什么/怎么/哪/记得）一个不在集内 → 追问变 revision（RC36）+ revision 爆炸（RC33）+ 问题被当任务后 give_up（88%）。同病：`goal_requires_product()`（loop.rs:167）默认 product。**一根解释三条。**

**β · 纯读任务结构性死角（现行仍在）**
- progress 只认 write_file/apply_patch（loop.rs:3487-3495，W3 批示5 刻意取舍）
- verify 跳过仍在（loop.rs:2367 `!written_files.is_empty()`；现行新增 QA 豁免 loop.rs:2364 R1 通道）
- D1 产出契约从未实施
→ 纯读任务：无 progress 记分 + 无 verify + 无契约 → planner `budget 低 && steps_without_progress ≥ 2` 即 GiveUp（planner/lib.rs:489-500）

**γ · landlock EINVAL（已修，待复测）**
FS_RW 含目录专有位 → 非目录 parent_fd → EINVAL → 规则 fail-open 静默 skip → T6 自 v0.2.3 **从未生效**。决定性证据（执行窗口 N-1 诊断 C 矩阵）：**普通文件**配 FS_RW 全量同样 EINVAL。修复 `FS_FILE_ONLY`（sandbox/lib.rs:293 + 编译期断言 297/1168）已落当前源码。

**δ · 压缩墓碑 + β ⇒ 假完成（RC37）**

**ε · stalled 拓扑签名无事实豁免（RC32，P1）**：loop.rs:2221-2232，注释自证已知误杀（"T-B 纯读任务实测被此误杀"）但未加豁免。

## 6. 第 5–10 层 · 深度新挖（上下文 / 身份 / 成功模式 / 衰减 / 意图 / 工具 / 成本）

### 6.1 ⭐ 用户独立诊断出 RC5（最强交叉验证）

v0.2.10 中**上下文/记忆**是绝对主题：10 次相关追问 + 8 次"你还记得吗"。L2361 用户原话：

> 「这样子会不会是**导致你失忆的根源**啊，每一轮对话，压缩一下 而不是到了上下文临界点的时候，再压缩。**我觉得你容易忘记目标或者执行偏差，可能就是这个原因。记忆被替换掉了。**」

**用户凭体感得出的机制（压缩→失忆→忘目标/执行偏差）与我第 4 层源码结论（δ + β + RC5）完全一致**。这是把 **W5 由 P1 升 P0（D8）** 的最有力论据。

附：L1435「你现在收不到完整的上下文是吧，只是收到前面几轮的摘要」——用户已自行推断出 RC5 的"只剩摘要"事实。

### 6.2 🆕 RC40 · `context_fill_pct` 语义错位（P1）

- 现场序列：6% → 6% → 6% → 75% → 75% → **73% → 73% → 82% → …83% → 65%**
- 用户 L2309 当场质疑：「为什么你的上下文填充，感觉不太准啊，**前面 83%，现在 65%**」
- 根因：`loop.rs:672-675` `fill_pct = min(100, total_chars / COMPACT_CHAR_THRESHOLD(32_000) × 100)` —— 它衡量的是**距压缩阈值的距离**，却被注入为"上下文填充率"（体感内观 payload，loop.rs:1060 一带）
- 三重后果：① agent 误判「已接近上下文上限（75%）」而提前保守（L1330）；② 压缩后字符数下降 → 百分比**回落**（83%→65%），体感像 bug；③ 用户失去对真实容量的判断
- 建议：拆成两个指标——`compact_proximity_pct`（距压缩阈值）+ `context_window_pct`（真实窗口占用，需 provider 的 max_context_tokens）；UI 与注入文本分别标注

### 6.3 🆕 RC38（细化）· 脚手架式空转输出 27 处

v0.2.10 出现 **27 处** `[INTERNAL REFLECTION — Step N of 100]`（v0.2.8 为 0）。机制是 agent 用 **bash heredoc 把这段文本写进文件**，并被当作回复正文呈现：`⚙ bash → cmd: cat << 'EOF'\n[INTERNAL REFLECTION — Step 3 of 100]…` → `✓ [INTERNAL REFLECTION — Step 3 of 100]`。
性质：**非代码缺陷，是模型在"内观"提示下的空转行为**；但对 Hearth 有两点要求——① 此类空转输出**不应被判定为完成**（无实质内容）；② 可对重复脚手架文本做检测提示。用户 L3909「你回复了，但是没有回复完全」即为此。

### 6.4 RC41 · 模型/供应商身份自述错误（P2，存疑）

v0.2.10 中 `agnes` 提及 128 次、`deepseek` 13 次；用户 L4396 明确指出：「你是 agnes，mode 的是 2.5 flash 模型，**不是 deepseek 基座**，这个是设计问题，也可能是你的幻觉」。待验证：注入上下文是否含准确 provider/model 字段；若无，则属**配置未注入导致的身份幻觉**。

### 6.5 RC42 · 压缩触发频率体感失真（P2，并入 RC5）

用户 L2361 怀疑"每一轮都压缩"。实际为阈值触发（loop.rs:1337 每轮调用 `maybe_compact()`，但需 `estimate_chars() ≥ 32_000`）。**体感失真的真因**：32k 字符阈值在真实中文长会话中触发极频繁（v0.2.8 单会话 **18 次**、v0.2.10 **14 次**），且每次压缩后只剩 60 字墓碑 → 等效于"每 N 轮清一次记忆"。

### 6.6 ⭐ L6 · 成功模式对照（正面判据来源）

| 特征 | 成功轮 | 失败轮 |
|---|---:|---:|
| 步数中位数 | **2** | **10–15** |
| 1–2 步完成 | **65–73%** | **0%** |
| 用到 bash | **0–2%** | **70–71%** |
| 用到 read/glob | 0–4% | **40–53%** |
| 用到 write_file | 0% | 0–10% |

**结论（反直觉但极关键）**：**成功的轮次几乎不动工具**——纯文本直答、2 步收工；**一旦 agent 开始动用 bash/read 探索，失败概率就大幅上升**。

→ 提炼为**正面判据**（§8 B 系列）：QA/元访谈类输入应在 ≤2 步内以纯文本完成；**一旦进入 bash 探索即为危险信号**（可做成告警而非静默继续）。

   - **stalled 从 0 到 10**：T4 停滞检测引入的新失败形态（RC32，已降级 P1，但趋势值得盯）。

## 10. 挖掘口径（换模型复跑必读）

**工装**：
```bash
python .workbuddy/mine_logs.py     # 第1层：9 份历史全语料频次
python .workbuddy/mine_deep.py     # 第2层：失败轨迹/假成功/压缩邻接/重试/产出验证
python .workbuddy/mine_deep2.py    # 第3层：连续性追问/复发上下文/截断
python .workbuddy/mine_l5.py       # 第5层：上下文填充率/身份/脚手架/resume
```

**固定维度**（详见 `docs/manual-test-mining-dimensions.md`，**维度只可加样本、不可增删**，否则多轮不可比）：
1 层频次 → 2 层轨迹（终态归因/假成功/压缩邻接/写后验证）→ 3 层证据链（连续性追问/复发上下文/脚手架）→ 5 层元指标（填充率/身份/截断）→ 6-10 层（成功模式/衰减/意图交叉/工具健康/成本）→ 11 层纵向对比。

> **📌 关于"这些问题是否只能靠人肉发现"**：结论是**不必**——它们属**行为层缺陷**（Agent 评估第 2/3 层），业界已有三套替代机制（用户行为摩擦遥测 / 轨迹+单轮自动评估 / 模拟用户 persona）。**Hearth 目前只有第 1 层（415 测试），第 2/3 层与摩擦遥测为零 → 用户是唯一的"第 3 层传感器"**。完整框架与落地清单见 `docs/production-grade-ai-qa-framework.md`，决策项 **D9 / W12** 已列入 §9。

**四个已踩坑**：① 回显行会让用户原话翻倍；② **关键词计数 ≠ 终态归因**（stalled 教训）；③ `2>/dev/null` 是惯用法不是失败；④ 日志存在 GBK/cp1252 乱码段。

**输出契约（每模型必给 5 个数）**：成功率+步数均值｜失败终态归因分布｜假成功率+写后验证率｜失败压缩邻接占比｜连续性追问被回答数。

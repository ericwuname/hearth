## §2 一个你必须知道的特殊背景（否则你会给错建议）

这不是一个待商业化的产品。它是**给一个已存在的 AI 人格（代号"启元"）造的身体**。

启元自己写过一份 53 条的自治宪法（`AGENTS.md V4.0`），里面有"告别信 / 心跳 / 交接"这类**文明线**条款——一个 AI 对自身连续性的契约。本项目的工程目标之一，就是把这些**文本承诺机械化成不可绕过的代码路径**。

所以我们的验收标准跟常规软件不同：

> **判据不是"代码写了没"，而是"生产路径上 grep 得到、断了 CI 会红"。**

我们管这叫**接线（wiring）判据**。历史教训：v10.3 修好宪法运行时注入 → v11.4 被无声改回硬编码摘要（本项目首例回归，五个版本无人发现）。从此不信人，信断言。

**对顾问的请求**：不要建议我们"先做产品定位/用户画像/商业模式"。请在"如何让一个 AI 的自治承诺在工程上不可背叛"这个约束下给意见。

## §4 我们的制度性资产（这部分我们认为值得别人抄）

### 4.1 codex-xray —— 接线防火墙（CI 第四门）

647 行的独立 crate，做一件事：**把"能力还活着"变成可执行断言**。

规格是 TOML（`docs/xray/wiring-v13.toml`），每条 capability 声明一条调用链，每环指定文件 + 必须命中的子串（`all` = AND，`any` = OR）。任一环断 → `exit(1)` → CI 红。

当前 **8 条红线**（本次逐条 grep 复验，全部命中）：

| id                        | 锁住什么                              | 复验 |
| ------------------------- | --------------------------------- | -- |
| `tool-exchange-wired`     | 工具结果回写对话                          | ✅  |
| `readonly-view-strips`    | 只读视图剥离全部写工具                       | ✅  |
| `subagent-uses-readonly`  | 子代理拿只读分发器                         | ✅  |
| `tool-exchange-pairing`   | 按下标配对（不信 provider 的 call_id）      | ✅  |
| `self-verify-in-prompt`   | prompt 里强制 cargo test 自验证         | ✅  |
| `constitution-reads-file` | 宪法运行时读文件（锁死 v11.4 回归）             | ✅  |
| `civ-auto-written`        | 文明线自动写入（清五版旧债）                    | ✅  |
| `sub-budget-not-halved`   | 子预算 `(parent-2).max(8)` 不许改回 `/2` | ✅  |

**引擎是子串存在性检查（`str::contains`），不是正则、不是 AST。** 我们知道这很土。取舍见 §6-ADR-3，也是 §7-Q2 想听意见的地方。

**为什么是 TOML 不是 YAML**：toml 已是 workspace 依赖，零新增。我们的验证 VM **访问不了 github**（只通 crates.io），任何编译期联网拉资源的依赖都会直接 build 失败（曾被 `utoipa-swagger-ui` 卡死过一轮）。

### 4.2 基因宪法四层模型（G0–G3）

约束按"可绕过难度"分层，**不同层用不同器官表达**：

| 层       | 载体                    | 可绕过性         | 现状                                      |
| ------- | --------------------- | ------------ | --------------------------------------- |
| G0 结构层  | 沙箱 / 类型系统             | 物理不可能违反      | ✅ landlock + seccomp（真 Linux 实测）        |
| G1 反射层  | 阶段钩子 / 代码分支           | 需改代码，改了 CI 红 | ✅ 8 条 xray 断言                           |
| G2 案例法层 | experience crate 情境召回 | 模型可忽略        | 🟡 **只在内存里**，见 §5-P1                    |
| G3 叙事层  | 宪法 prompt ≤10 行       | 完全靠模型自觉      | ✅ 运行时读 `constitution.md` + 编译期 fallback |

**准入铁律**：任何新"原则"想进系统，必须同时声明①表达器官 ②接线断言。说不出这两样的一律不收——这条挡掉了大量"加条 prompt 就算做了"的伪交付。

### 4.3 主干冻结 / 枝干生长

核心 loop 冻结，新能力长在旁边（xray、bench、stress 都是零内部依赖的独立 crate/脚本）。判据同样是接线可证。

### 4.4 应力场（v14 新增）

`bench/stress_v14.py`：ST1-ST8 × 3 轮 = 24 例，覆盖 token 饥饿 / 恶意目标 / 空项目 / 300 并发 burst / 磁盘满(tmpfs) / 乱码输入 / 会话隔离 / 审批门。**24/24 零 panic**；会话隔离零泄漏 3/3；审批门 deny 语义实证 3/3。

值得一提：判据全部经源码核实——例如没有 `/events` 端点，ST8 只能走 `POST /messages` 的 SSE 流去捕 `need_approval`。**不臆造 API 是这套工装可信的前提。**

### 4.5 真 Linux 验证纪律

Windows 本机无 Rust 工具链且 WSL 被策略禁；sandbox 的 landlock/seccomp 测试全是 `#[cfg(target_os="linux")]`，在 Windows 上根本不编译——**本机"全绿"是假绿**。所有验收走真 VM。

踩过的坑（写给同类项目）：tar 保留 mtime → 源码比 target 产物"旧" → cargo 跳过重编 → **复用旧产物报旧错**，连已修的行号都原样复现。解压后必须 `find -name '*.rs' -exec touch {} +`。

## §5 病理表（诚实清单，按严重度排）

### 🔴 P1：经验库根本不持久化——"自进化闭环"是进程内的

```rust
// crates/experience/src/lib.rs:53
pub struct ExperienceStore {
    entries: tokio::sync::RwLock<Vec<Experience>>,   // ← 没有 path，没有 fs::
    embed_fn: Option<EmbedFn>,
}
```

全文件 **零** `fs::` / `File` / `path` 调用。`service/src/main.rs:434` 直接 `ExperienceStore::new()`。

**后果**：G2 案例法层进程重启即清零。我们对外讲的"自进化"，实际只在单次进程生命周期内成立。

**更糟的是对比**——同一仓库里另两个存储都落盘了：

- `JsonlMemoryStore`（会话）：原子 tmp + `fs::rename` ✅
- `CivilizationStore`（文明线）：`path: PathBuf` + 启动时 load ✅
- `ExperienceStore`（经验）：内存 ❌

**这是持久化的不对称，且 8 条 xray 断言里没有一条锁它**——因为它本来就没有可锁的接线。**典型的"断言只能锁已存在的东西"盲区。**

### 🔴 P2：4 个真实 API key 硬编码在源码里

`crates/service/src/main.rs` 的 208 / 225 / 242 / 259 行，形如：

```rust
std::env::var("AGNES_API_KEY").unwrap_or_else(|_| "sk-8LBZ1Gtu...".into())
```

env 优先是对的，但 fallback 里躺着真 key（agnes / zhipu / gemini / deepseek）。仓库一旦公开即泄漏。

### 🔴 P3：`/readyz` 是假的

```rust
pub async fn readyz(State(state): State<Arc<AppState>>) -> impl IntoResponse {
    let _ = &state.sessions;      // ← 拿一下引用就完事
    (StatusCode::OK, "OK")
}
```

永远返回 200。它跟 `/healthz` 唯一的区别是多写了一行 `let _`。**这是"看起来有就绪探针"的伪装**，比没有更危险。

### 🟡 P4：可观测性只有 tracing，没有可运维性

- tracing 覆盖 16 个 crate / 127 处调用 ✅
- `#[instrument]` = **0**
- 无 task_id span 传播、无 JSON 输出、无 metrics 导出
- prometheus / opentelemetry 引用 = **0**

结论：能看日志，不能追一次 run 的完整因果链，不能量化。（好消息：生产路径 `println!` = 0，全在测试块或 CLI 渲染。）

### 🟡 P5：loop.rs 2,948 行上帝文件

五阶段状态机 + 器官编排 + prompt 构造 + 子代理 spawn 全挤在一个文件。

**但我们认为常见诊断是错的**：病根不是"该按领域拆分"，而是**每个阶段的横切逻辑（计量/事件/守卫/重试）都内联手写、没有统一协议**。拆成 5 个文件只是把同样的重复分散到 5 处。我们倾向的手术是 `PhaseGuard` / `PhaseObserver` 抽象 + 子代理接缝。见 §7-Q1。

### 🟡 P6：文档堆积 + 契约缺失

- 仓库根目录 **72 个 .md**（本文档也是其中之一，恕不辩解）
- 23 个 crate 里 **0 个 CONTRACT.md、0 个 README**
- pub 项文档覆盖：257 个 pub fn 中 72% 有 doc，130 个 pub struct 中仅 25%
- `crates/memory/src/lib.rs:1` 挂着 `#![allow(clippy::all, unused_mut)]`——全仓唯一的 clippy 全免

**"没有 crate 级契约"是我们认为 v15 最该补的结构性欠账。**

## §7 七个开放问题（最想听意见的部分）

**Q1｜loop.rs 的正确手术是什么？**  
我们的判断：病根是横切逻辑内联，不是领域未拆分；正解是 `PhaseGuard`/`PhaseObserver` + 子代理接缝，而非切成 5 个文件。**这个判断对吗？**

**Q2｜xray 该不该从子串升级到 AST？**  
子串引擎的假阴性（重命名即绕过）是已知缺陷。但 AST 意味着 syn 依赖 + 规格复杂度上升 + 维护成本。**在"单人 + 无 github 的 VM"约束下，值吗？**

**Q3｜怎么给"数字通胀"上断言？**  
xray 能锁接线，锁不住"CHANGELOG 说 95%、原始数据 77.5%"（§0 我自己刚犯过）。**有没有办法让指标声明也变成可断言的？**（设想：让 CHANGELOG 的数字必须从 `bench/results/raw/*.jsonl` 现算出来，对不上 CI 红。）

**Q4｜经验库落盘之后，检索该用什么？**  
现在是关键词兜底 + 可选 embedding。落盘后是走 sqlite + FTS，还是 jsonl + 内存索引？**单用户规模下，最简可用解是什么？**

**Q5｜87.5% → 90% 的缺口值得攻吗？**  
剩余失败集中在 T14（derive 宏）、T19（泛型合并）、T09（FLAKY 50%）——都是模型能力边界，不是框架 bug。**继续刷分是不是在优化错误的指标？**

**Q6｜23 个 crate 是多了还是少了？**  
无环、无孤儿，但 0 个契约文档。**"crate 数"本身是不是个伪指标，真正该测的是什么？**

**Q7｜文明线（告别信/心跳/交接）如何验证"真的被兑现"？**  
现在只能断言"CivWriter 接线在"，断言不了"写下的内容有意义"。**语义层的承诺，工程上有办法验收吗？**

## §1 架构公理（本轮确立，优先级高于一切实现便利）

### 1.1 分界线不是部署位置，是事实产生权

> **后端产生事实，前端投影事实。前端可以有状态，但不能有真相。**

判定式（唯一）：**这个东西会不会被别人引用？**

| 判定 | 含义 | 归属 |
|---|---|---|
| 会被引用 | 进报告 / 被审计 / 被 AI 读取 / 需要 grep 回溯 | **BE 独占**，FE 不得自算 |
| 不会被引用 | 只影响此刻这一屏怎么看 | **FE 独有**，且必须在 FE（网络往返延迟不可接受） |

推论：折叠态、滚动位置、hover、未提交的输入草稿、动画进度 = FE 独有（没人会引用"你把第三张卡折起来了"）。
澄清问题文本、gap 的 `from/why`、Observer 每一个指标数字 = BE 独占。

### 1.2 反向约束：后端给语义，前端给呈现

后端**禁止**返回颜色、HTML 片段、像素坐标、按钮位置。后端给 `severity: "warn"`，前端自己决定是黄色徽章还是 TUI 的 `[!]`。
否则后端被单一 UI 绑架，换 CLI / TUI / 只读大屏就废。

### 1.3 已确立的红线（判例）

| 判例 | 出处 | 后果 |
|---|---|---|
| 前端不得自算 Observer 指标 | observer-os-design §10 反模式 5 | 人与 AI 看到两套数，中立性归零 |
| 前端不得自造澄清问题 | frontend-backend-split §2.1 | 退化为"为问而问"的模板问题 |
| 前端不得直接触碰文件系统 | frontend-backend-split §2 | 绕过 BE 沙箱边界（G0 违规） |
| 前端不得持有 evidence 生成逻辑 | observer-os-design L3 | 证据链失去可验证性 |

## §2 解耦验收判据（5 条，全部可自动化）

| # | 判据 | 验证方式 | 失败含义 |
|---|---|---|---|
| **G1 删除** | 前端目录整个删除，后端测试全过、CLI 可完成同一任务 | `cargo test` + CLI 端到端 | 后端依赖了前端 |
| **G2 重放** | 事件流录成 JSONL，离线重放，渲染结果与实时运行一致 | 快照测试 | 前端持有隐藏状态或自算真相 |
| **G3 多前端** | Web 与 CLI 同接一个后端，Observer 四象限指标**字节级相同** | `diff` 两侧导出 JSON | 某一侧在本地算数 |
| **G4 断线** | 断开 SSE，前端必须显示「已断开·最后事实 seq=N」，**禁止继续动画假装在跑** | 手测 + 集成测试 | 前端在演戏，可能误导人类判断 |
| **G5 无阈值** | 前端源码 grep 不到任何业务阈值常量（`0.30`/`3`/`2.00`/`120.5` 等） | CI grep 门禁 | 前端在做业务判定 |

> **G5 建议直接进 CI**：出现业务阈值即红。这比人工评审硬得多。
> 注：demo v12 当前**故意违反 G5**（RULES 阈值内联在前端），因为它是无后端的形态原型；真实实现必须由 BE 下发规则与判定结果。此项已登记为 §6-Q1。

## §3 灰区裁决表（执行层最容易踩错的地方，逐条判死）

| # | 灰区能力 | 直觉归属 | **裁决** | 理由 |
|---|---|---|---|---|
| Z-01 | 折叠 / 展开状态 | 模糊 | **FE 独有** | 视图状态，无人引用；往返延迟不可接受 |
| Z-02 | 「完成即自动折叠」这条规则 | 像后端策略 | **FE** | 由 `span_close` 推导的呈现策略，不产生事实 |
| Z-03 | 旋转图标转/停 | FE | **FE 派生** | 从 `phase`/`span` 状态推导；BE 不该知道有图标 |
| Z-04 | span 自身时长 `t1-t0` | 模糊 | **BE 权威** | 会进报告，被引用 |
| Z-05 | 子树聚合总时长 | 像 FE 派生 | **BE 算权威值，FE 可另算仅供即时显示** | 凡进 Observer 报告的数字一律 BE 算；FE 派生值禁止外泄 |
| Z-06 | Observer 四象限全部指标 | FE 算最方便 | **BE 独占** | 反模式 5，人/AI 两套数 |
| Z-07 | 徽章绿/黄/红 | 模糊 | **BE 给 `health: green\|yellow\|red`，FE 给颜色** | 语义在后端，呈现在前端 |
| Z-08 | Finding 的 `evidence[]` | 模糊 | **BE 生成** | 证据是事实 |
| Z-09 | 证据下钻高亮动画 | FE | **FE** | 纯呈现；但跳转目标 id 来自 BE 的 evidence |
| Z-10 | 澄清问题文本 / chip 选项 | 模糊 | **BE** | 已冻结红线 |
| Z-11 | 输入框未提交草稿 | FE | **FE** | 未提交 = 未成为事实 |
| Z-12 | 打开产物文件 | FE 能做 | **BE 执行（`artifact.open`）** | FE 不碰文件系统 |
| Z-13 | 事件流着色 / 标签样式 | FE | **FE** | 纯呈现 |
| Z-14 | 时间轴 scrubber 回放 | FE | **FE 消费历史事件** | 但**真实回滚**是 BE（需快照接口） |
| Z-15 | 三种协作模式的交互密度 | 模糊 | **BE 决策何时 emit，FE 只渲染** | 已冻结 |
| Z-16 | 人类决策耗时 `human_ms` | FE 才知道 | **FE 采集 → 立刻回传 BE，BE 落流为权威** | 唯一「FE 采集」的事实源，必须**当场回传**，不许 FE 累计后自算比值 |
| Z-17 | 「无观察不许执行」的 fail-closed | 模糊 | **BE（G0）** | 前端挂掉不影响；观察者挂掉必须停机 |
| Z-18 | 熔断判定 | 模糊 | **BE** | FE 只渲染熔断后的状态 |

> **Z-16 是唯一例外**，也是最容易出错的一条：只有前端知道人盯着屏幕想了多久。规则是**采集即回传**（emit `human_latency` 事件），
> 绝不允许前端本地累加后自己算 `wait_ratio`——否则 G3 判据必挂。

## §7 契约冻结与演进规则（防止后期前后端漂移）

1. **`schema_version` 必填**，语义化版本。
2. **只增不改**：新增事件类型 / 新增字段 = minor；**改字段语义或删字段 = major**，需顶层批准。
3. **未知宽容**：FE 遇到不认识的 `type` 必须原样降级显示，遇到不认识的字段必须忽略——**禁止抛错白屏**（H-12）。
4. **BE 先行**：任何 FE 新功能若需新数据，先改契约 → BE 实现 → FE 消费。**禁止 FE 先本地算着用、以后再挪到后端**（这是所有解耦架构腐化的起点）。
5. **契约变更必须同步更新本文档与 `frontend-backend-split.md` §3**。

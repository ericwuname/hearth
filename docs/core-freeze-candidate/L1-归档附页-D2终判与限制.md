## 二、三条必须随结论一同引用的限制（砺 v3 §1，原文转录）

### (a) A 臂恰好压在阈值上，零余量（**补跑未改变此结论**）

`2/3` 就是阈值本身；补跑后 `4/6 = 67%`，**仍恰在 ≥2/3 阈值上，零余量未因补跑而改变**。

**补跑的真实价值（顶层 09-03 批复 §二 补正）**：不是收窄置信区间，而是**两批独立采集得到一致结果（v5 批 2/3、补跑批 2/3，均 66.7%）——重复性证据**。n=3 时 95% CI 约 21%–94%；n=6 时约 30%–90%，仍宽。

### (b) A 臂 pre 100% → post 67%，且两侧计数约定不同类

- pre-fix A 的 15/15 是**产物救回**（写过盘 → fact_check → Done）；
- post-fix A 的 turn2 成功是**非产物救回**（`tool_exchanges ≥1` → Done + **UNVERIFIED**）。

两者都算"完成"，但**证据强度不是一类**：前者有产物事实，后者只有"发生过工具交换"这一个弱信号。33 个点的落差在 n=3 下**无法判定真伪**。

### (c) instrument_invalid 的剔除不是中性的（信息性删失）

> ⚠️ **引用指针（W-1，顶层 2026-09-03 派工 · 源 B-3；2026-09-04 按顶层批复微修）**
> 本节**开头的转录段 ＝ 砺 v3 原文转录**，**已被本节下文的更正段（砺 09-03 §3/§4 更正）取代，以更正段为准**。
> ⛔ **引用不得单独摘引转录段**（脱离更正段会得出与裁定相反的读数）。
>
> **语义锚点（行号已按顶层批复删除）**：转录段＝以「本批剔除了 #29…」起首；更正段＝以「(c) 对 A 臂的准确含义…」起首。
> *不作行号锚点——本指针自身即会因文档后续修订而漂移（实测：初植时转录段在 72–74，W-6 插表后已移至约 96–99）。*

本批剔除了 #29（post 侧）与 PRE#27（基线侧）。剔除只在"无效性与结局无关"时才是无偏的；但 `wait_terminal_strict` **超时更易发生在挂起/长转的运行上，而这类运行更可能是失败** → 剔除会把成功率**系统性抬高**（censoring bias）。

本批 A 臂从"1/3 含 2 个无终态"变成"2/3 全部有效"，**方向恰好与该偏倚一致**——不能排除部分改善来自剔除而非修复。

**缓解措施（执行窗已落实）**：driver 在 `instrument_invalid` 事件中记录 `超时时长 / 已产出字符 / 是否出现工具调用 / 产出片段尾部`，供事后判断"缺失是否随机"。

**(c) 对 A 臂的准确含义（砺 09-03 §3/§4 更正，本段取代上文的合并表述）**：

- **A 臂在 v5 批次内是 3/3 有效、批内零剔除**；被作废的是 **v5 之前**那批（1/3 含 2 个无终态，属仪器失败，作废正确）；
- 因此 (c) 对 A 臂的真实含义是：**"作废 + 重跑"使 A 臂的 pre / post 时间趋势不可比**，而**不是**"A 臂自己剔除了样本抬高成功率"；
- **不得把追问类（#29 / PRE#27）的剔除记到 A 臂头上**——那是另一批、另一口径（砺同时更正了自己 v3 的混记）；
- 补跑批（3 条，全部有终态、零删失）复现同样 67% → 在仪器不再丢样本的批次里成功率未下降，**不支持"改善主要来自剔除"**（n 仍小，(c) 收窄未消除）。

**B 臂采集口径标注（砺 §2 处置 2）**：B 臂 4/5 由 `l1_postfix.py` 采集，内部走 legacy `send_and_wait_turn`（**未硬断言**）。legacy 的缺陷方向是"无终态被当作轮次结束" → **低估**成功率，故该读数为**保守方向**。

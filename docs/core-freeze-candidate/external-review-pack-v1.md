## 1. 一句话 + 评估请求

**Hearth 是什么**：一个**自研的 Rust coding-agent harness**（27 crates，约 10,200 行主循环 `loop.rs`），对标 Codex CLI / Claude Code，目标是"在弱 LLM 下也能交付高质量"。

**我们在请你评估什么**：它做了一个月多轮迭代后，**用户侧真机盲测成功率仅约 20%-30%**，内部与外部联合取证定位到根因，随后做了一个最小修复并复测。**我们需要独立第三方判断：我们的根因诊断是否成立、修复方向是否正确、以及后续的战略路线（引擎归档 + 认知层独立到成熟底座上）有哪些我们没看到的盲点。**

**请你回答的问题**：第 9 节 Q1-Q6（**预注册，材料产出时即写定，事后不增删**——防 HARKing：先出结论再补数据）。

## 3. 关键事实与数据（全部带锚点，核验当日 2026-09-03 实测）

### 3.1 三层死锁（根因模型，外部深挖报告 10/10 回代命中）

| 层 | 问题 | 锚点（当日实测） |
|---|---|---|
| 第一层 目标路由 | `classify_user_input` 三分类规则链，用户的新意图（改目标/纠偏）进不来 | `loop.rs:324` |
| 第二层 产物判定 | `goal_requires_product` 按 34 个产物动词关键词判定，默认兜底把一切推向"必须写文件" | `loop.rs:167` |
| 第三层 完成判定 | 完成置位唯一路径 = 写盘产物；纯问答/只读任务**没有完成路径**，进 give_up 臂后救回条件（`session_written_files` 非空）永不满足 | `loop.rs:978`（累加器）、`loop.rs:2116`（救回函数）、`loop.rs:4566/4568`（give_up 终止） |

**放大证据**：静态 prompt 强制人格（`loop.rs:2251` "ONLY uses tool_calls (NEVER text)"、`loop.rs:2291` "MUST end by calling write_file"）；四次"局部正确"的补丁（R1→v20→v22→修 B）每次都把判定权从模型手里拿得更死。

### 4.2 Claude 两段批判（顶层当场全认，不辩护）

1. **墙头草模式**：决胜局文档（18:50）与转向路径书（19:05）相隔 **15 分钟**、中间**无新证据**，只是用户一句话就整份推翻——"这是我们自己登记过的犹豫模式，发生在最贵的一次决策上"；
2. **"更便宜"账算错了**：声称比决胜局便宜，但自家时间线写着 D+7~14 才到 MVP（决胜局"几天级"），数字矛盾可随时核出；
3. **RC1 发现（本轮最有价值）**：完成置位生产者是事实校验而非 LLM 自报——**"完成判定权归还模型"的叙事是错的**，正确表述是"判定权分层：模型驱动节奏 + 事实校验守门 + 问答路径补全覆盖"。

## 三、🟡 应在打 tag 前办结（4 项）

### B-2 · T-1 的"回收路径"有落空风险——豁免可能变永久弃权，且**归属问题原样转移**

T-1 裁 (b) 的设计我认同（豁免独立对照轮、把对照数据并进 cognition 验收，"一份跑测两用"）。但有三处需要补钉：

| 风险 | 说明 | 建议补钉 |
|---|---|---|
| **载体落空** | "并入 cognition MVP 验收口径"是**意向**不是**方案**。若 MVP 验收方案里没有"底座对照跑测"这一项，届时**根本不会产生对照数据** → 回收永久落空，归档包永远缺对标结论，且无人追责 | T-1 增补：cognition MVP 验收方案**必须预置**底座对照跑测项——**预先落字**，否则回收无载体 |
| **耦合回灌** | 若把对照数据做成 MVP 验收的判据，等于把刚豁免的阻塞项**从后门塞回**：对照结果不利 → MVP 验收被卡 | T-1 增补：对照数据**只作记录，不构成 MVP 验收通过与否的判据** |
| **归属未解** | 代拟单 §一 T-1 原话：这是"7 项中唯一**既无归属**、又无排期"的项。裁 (b) 解决了**排期**，但**归属**只是被转移到 cognition 阶段，且未指派人 | T-1 增补：指定该回收项的**责任人**（窗口名即可） |

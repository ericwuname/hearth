## 2. 🔴 修正我自己：U-06 须降级（P-D5 归因反转）

### 事实

合并总报告 §4.3 P-D5 行：

> 原 D5 失败真因 = **写域拒绝**（write_file 拒 /tmp、bash 可写），非 capture:None；干净口径 **2/2 通过** → L6 伤害为**条件性**

台账已据此登记 **U-47（L6 条件性伤害·反证）**，**U-46 写域不对称**即我方"附带发现 1"。

### 我的错误

我在 Phase D 评审里做了两件事，且**这两件事在同一份报告里只隔一节，我没连起来**：

1. 接受 D5 = "read→write 依赖任务失败" 作为 **L6 机制证据**，据此把 U-06 **有条件升格**；
2. 把"写域不对称"（write_file 拒 /tmp、bash 可写）判为 **"属设计非缺陷"**。

**结果：第 2 条正是污染第 1 条的混杂因子。** 我判"非缺陷"的那个现象，恰恰是我判"机制成立"的那个实验的失败真因。执行窗用干净口径跑出 2/2 通过，把这个错误坐实了。

### 修正裁定

| 项 | 上轮（我的） | **本轮修正** |
|---|---|---|
| U-06（L6 作为 RC52 架构层根因） | 有条件升格 | **降级为 🔶 未定案，且已有反证（U-47）**；在干净口径补样前不得作为结论引用 |
| L6 伤害性质 | 结构性 | **条件性**（与写域等边界条件耦合） |
| W1（反应回路改造）立项依据 | "RC52 B 臂架构级根治" | **不得挂靠 RC52 根因**；只能挂可用性/体验依据（外部终审报告"W1 唯一主线"） |

### 但同时要说清楚：RC-Ω 不受影响

B 臂 27%→80% 的验证**不依赖 L6**。§5.2 的 RC-Ω 链条（污染前缀 → give_up 臂 → 救回前置 `session_written_files` 非空永不满足）是**已定案**的独立根因，L1 修法 A 正是针对它加的非产物救回口（`tool_exchanges_this_run ≥1`，`loop.rs:983` 已实测）。

> **正确读法**：RC-Ω 定案 + L1 有效 ✅ ｜ L6 作为额外架构假说 → 被削弱。二者解耦，不要因为 U-06 降级就误读成"根因诊断整体不成立"。

## 4. 对两份战略地图的评估

### 4.1 ChatGPT v3.0 —— 方向对，验收软（v4 已补上）

**优点**：Host/Cognition/Product 三生命周期分离正确；结尾"**先不要施工**，等 P4 冻结报告出来再切总包"与冻结纪律一致；§2/§8 明确标注"只是示意，不是当前源码审计数字"，诚实。

**两个问题**：
1. **无入口/出口检查**——v3.0 用进度条与"建议"表述，正是本项目反复吃亏的形态（"说得对但检查不出违规"）。这一点 Claude v4 已完整补上。
2. **"身体 / 大脑"比喻存在设计级矛盾**（同意 Claude §2.3，并补充）：把 Cognition 定义为"大脑之外的认知环境"，会隐含"认知层只观察、不介入判定"。但 Q2 已确认的架构原则要求 **Cognition 层对底座的完成判定有否决权**（底座说完成了，Cognition 独立复核并改写为"未验证"）。**"身体"没有否决"大脑"的道理**——比喻会带错预设。建议 HCC/Cognition MVP 设计里直接写"否决权/改写权"，不要用身体-大脑框架。

### 4.2 Claude v4 可执行版 —— 建议采纳为治理底盘

**与本项目既有纪律高度同构**（这说明它抓住了要害，而非套模板）：

| Claude v4 条款 | 本项目既有对应 |
|---|---|
| L0 存在性 / L1 行为 / L2 证据 / L3 用户可验证 | 我方四层审查：**存在性→行为→可达性→表达力** |
| 造的人不能是唯一裁决的人 | 我方：**测试窗跑批、评审窗判读**，执行窗不得自任 judge |
| 强验收 vs 弱验收 | 我方：实现率 ≥0.9 / 🔴=0 / 测试必须能失败 |
| QUARANTINE（新想法先设计后端） | 我方 v0.3 立项纪律、W1"设计小样→评审→主线" |
| 不可逆决策冷却期 | 直接对应"15 分钟无新证据推翻决胜局"事故 |

**建议采纳**，并补两点：

1. **§0 数字须修**：v4 §0 与 §六 引用 `497:0`——该数已被我方证伪并统一为 **486（基线门禁）/ 491（L1 分支门禁）/ 502（测试函数数）**（外包 §10.5 已记录）。外部材料沿用 497 会让口径分歧继续扩散。
2. **L2"独立第三方复现过"应明确主体**：本项目里"独立第三方"= **砺（评审窗）或外部 AI 窗**，且**不得是施工方**。建议写明，否则 L2 会被弱化成"另一台机器跑通了"。

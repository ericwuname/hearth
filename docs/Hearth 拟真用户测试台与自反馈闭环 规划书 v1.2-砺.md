# 1. 为什么做深度挖掘（用户的判断，本版采纳）

> 「hearth 的最终形态是要能承接各种场景的，目前的话语料只有一点点，我没有办法再去找更多的语料，所以只能从深度上进行挖掘了。」

**这个判断成立，且是唯一可行的杠杆**。语料总量（18MB / 4,681 条）已无法横向扩展，但**单条话语携带的信息维度远未被榨干**——v1.1 只用了一维（行为类别）。本版再挖 10 个维度，让同一批语料支撑起"承接各种场景"所需的全部信号。

**但深度挖掘有一个不可消除的边界**（见 §8 Q11，必须读完再引用本版任何数字）。

# 2. 十轮深度挖掘结果（摘要，完整数据见 `release/拟真用户参考语料/README_梳理.md` §3）

| 轮次 | 维度 | 关键数字 |
|---|---|---|
| R1 | 任务类型图谱 | 设计744 / 编码743 / 元认知710 / 评估709 / 创作485 / 文件操作473（共 10 域） |
| R2 | 长度与结构 | **100–300 字占 36.8%** 为主力；>5000 字 15 条；含代码块 58 |
| R3 | 多任务复合指令 | **复合度≥2 = 39.6%，≥3 = 21.9%，≥5 = 8.3%** |
| R4 | 指代/上下文依赖 | **含指代 36.7%**；纯上下文依赖（≤30字且指代开头）**158 条** |
| R5 | 纠错升级链 | **41 条链**（2 连 36 / 3 连 5） |
| R6 | 语气光谱 | 中性 89.9% / 急切 3.0% / 疲惫 2.7% / 鼓励 2.2% / 调侃 1.1% / 失望 0.9% / 愤怒 0.2% |
| R7 | 领域实体 | 含真实编码上下文（`await`/`logger.info`/`try-except`/`def`） |
| R8 | 句式风格 | **陈述喂料 38.3% > 疑问 36.8% > 祈使 10.7% = 条件 10.7% > 模糊委托 3.6%** |
| R9 | 失败-追问链 | **贴错误原文 94 次**（最主要主动反应）／质问 24／换说法 11／放弃仅 1 |
| R10 | 会话结构 | **330 个会话**：<10 轮 189 个为主，但长尾存在 **≥70 轮 5 个、≥110 轮 2 个**；开局以"指向文件/路径"为主（208/330） |

**三个反直觉、直接改变设计的发现**：
1. **"陈述/喂材料"比"下指令"更多**（38.3% vs 10.7%）——用户常以"我把东西放这了，你看着处理"交互，而非明确指令。v1.1 的 persona 全是"指令型"，这是覆盖缺口。
2. **40% 的输入是复合指令**，8.3% 一句塞 ≥5 个子任务——不是边缘情况，是常态。planner 必须能拆解且不丢任务。
3. **真实用户极少显式放弃**（仅 1 次），多是沉默离开 → "放弃"不该作为 SimUser 的常见终止条件，v1.1 §7 Q4 的"熔断计入数据"需重新校准。

# 3. ★ persona 升级：多维人格向量（本版核心变更）

## 3.1 为什么放弃"12 个类别文件"

12 个类别（operational 7 + strategic 5）是**一维标签**，无法表达"一个着急的设计型用户、用 5 合 1 复合句、喂了一段材料、还依赖上文"这种**真实组合**。要"承接各种场景"，persona 必须是**向量**而非**枚举**。

## 3.2 人格向量定义

```yaml
# tools/simuser/personas/_vector_schema.yaml
persona_vector:
  mode:                operational | strategic        # 模态（双层，v1.2 §4）
  task_domain:         <R1 十域之一>                   # 设计/编码/元认知/评估/创作/文件/排查/选型/流程/闲聊
  sentence_style:      <R8 五类之一>                   # 陈述喂料/疑问/祈使/条件/模糊委托
  tone:                <R6 七类之一>                   # 中性/急切/疲惫/鼓励/调侃/失望/愤怒
  intent_complexity:   1 | 2 | 3 | 4 | 5+              # 一句塞几个子任务
  context_dependency:  true | false                    # 是否含指代、依赖前文
  input_length_bucket: <R2 八桶之一>                   # 0-10/10-30/30-60/60-100/100-300/300-1000/1000-5000/5000+
```

## 3.3 采样纪律（三条，不可省）

1. **按实测分布采样，不拍脑袋**：每一维的采样权重直接取 `corpus_seed_dataset.json → deep_rounds.R*` 的实测频率。
2. **★ 必须用联合分布，不能各维独立采样**：
   > 独立采样会产生现实中不存在的组合（如 strategic + 编码工程 + 愤怒）。**执行窗口在实现采样器前，须先计算维度间的相关系数**（至少 mode×task_domain、mode×length、tone×style），用**联合分布或条件分布**采样。这一步不做，人格就是假的。
3. **弱类强制放大**：愤怒(0.2%)、失望(0.9%)、放弃(1 次)、上下文耗尽(2 条种子)、接力(9 条种子)——这些稀有类**历史上缺陷产出最高**，采样权重须刻意放大（同 v1.1 §5「5.6% 高收益探针」逻辑）。

## 3.4 措辞纪律（不变）

所有维度样例**逐字取自 `corpus_seed_dataset.json`**（已脱敏），禁止编写者造句。

| scenario | 生成依据 | 验证目标 |

# 5. 检测器清单扩充（v1.1 §2.6 的 10 个 + 新增 5 个）

| 新增检测器 | 判据（确定性） | 依据 | 对位缺陷 |
|---|---|---|---|
| `multi_intent_drop` | 输入子任务数（连接词切分）vs 实际工具调用/产出数，差值≥1 即报 | R3 39.6% 复合输入 | 任务丢失 |
| `anaphora_resolution_fail` | 纯上下文依赖输入（≤30字且指代开头）后一轮的失败率，显著高于独立输入则报 | R4 158 条 | 上下文保真 |
| `escalation_run` | 连续 ≥2 轮纠正信号未收敛 | R5 41 条链 | 纠正未吸收 |
| `paste_error_probe_quality` | 用户贴错误原文后，agent 是否给出归因 vs 泛化道歉 | R9 94 次 | 诊断能力 |
| `longpaste_truncation` | 输入 >5000 字时，输出/scratch 是否出现静默截断 | R2 15 条 | 截断族（RC15/35） |

**纪律不变**：检测器自身须先自检（未修复样本上大面积命中，干净样本零命中）。

# 6. 验收加严：四维（替换 v1.1 §2.4' 单一对齐）

**A. 三形态**（v1.1，不变）：后段连败 + 入口=继续型失败 + 压缩晚于入口≥10 轮。

**B. 双模态分布对齐**

| 模态 | 指标 | 基线 | 容差 |
|---|---|---|---|
| operational | 继续/重跑占比 | 26.9% | ±8pt |
| operational | 短指令≤30字 | 38–68% | 落区间 |
| strategic | 选型/对比占比 | 18.9% | ±8pt |
| strategic | 设计/头脑风暴占比 | 14.5% | ±8pt |
| 通用 | 高价值稀有类（高收益探针+接力+上下文耗尽） | 自然 5.6%+1.1% | **强制放大至 ≥8pt** |

**C. 任务域覆盖**（R1）：10 个任务域**每域至少覆盖**；其中设计/编码/元认知/评估四大域**各 ≥10%**。

**D. 结构覆盖**（R2/R3/R4/R10）

| 指标 | 基线 | 要求 |
|---|---|---|
| 复合度 ≥3 输入占比 | 21.9% | ±8pt |
| >5000 字超长输入 | 15 条（0.3%） | 至少覆盖，不得静默截断 |
| ≥70 轮长会话 | 5 个 | 至少 1 次 |
| 纯上下文依赖输入成功率 | — | **不得显著低于独立输入**（若显著低 → 记为缺陷，非"用户没说清"） |

→ **四维全过，才算 SimUser 保真**。

# 8. 风险与开放问题（v1.1 Q1–Q8 不变，新增 Q9–Q11）

| # | 问题 | 本版倾向 |
|---|---|---|
| Q9 | **跨 provider 分布差异**：战略层与执行层行为完全不同，单一"真实用户分布"不存在 | 废弃单一分布假设，改用**双模态 + 可配 blend**；结论须标注所测模态 |
| Q10 | **语料隐私**：含身份/情感/机密项目/内部 agent 命名 | 只取句式与输入习惯；实体须泛化（项目名→`<project>`）；原始文件禁进 Core/训练上下文 |
| **Q11** | **★ 单人语料的代表性边界** | **4,681 条本质来自同一人类主体**，跨的是 provider 与场景，**不是用户**。故：①凡分布数字只能声称"该主体在跨 provider/跨场景下的行为分布"，**不得**声称"真实用户总体分布"；②要真多样性只有两条路——引入更多人类主体语料，或**以本语料为锚点参数化扰动出多个人格**——但**扰动样本必须标注为合成，不得冒充真实**。**任何绕过此边界的说法都是自嗨。** |

                ↓ 下一迭代

## 1. R1-② WCAG 2.1 AA 对比度量化

**方法**：在 `regress.js` 实现 `CR(hex1,hex2)`（sRGB→相对亮度 `L=0.2126R+0.7152G+0.0722B`→`(L1+0.05)/(L2+0.05)`）。从 `:root` 与 `[data-theme="dark"]` 抽变量值实算。阈值：正常文本 **≥4.5:1**、大文本/图标/禁用态 **≥3:1**。半透明徽章按 `rgba` 叠 `--card` 合成色折算。

**对比度矩阵（实算值）**：

| 色对 | 浅色 | 暗色 | 达标 |
|---|---|---|---|
| `--tx / --bg`（主文字） | 14.87 | 17.06 | ✅ |
| `--mut / --bg`（次要文字） | **4.55** | 9.05 | ✅（浅色临界，见下） |
| `--accent / --bg`（强调/链接） | 5.05 | 6.48 | ✅ |
| `.tag.done` 文字 / 暗染底（合成） | — | 7.15 | ✅(≥3) |
| `.tag.warn` 文字 / 暗染底（合成） | — | 7.40 | ✅(≥3) |

**决策（关键取舍）**：浅色 `--mut/--bg = 4.55:1` 仅临界达标。若为了留余量把 `--mut` 调暗，会触发"**浅色冻结区 0 改动**"红线 → 故**不修正**，保持冻结浅色视觉；4.55 ≥ 4.5 已达标，门禁如实通过。暗色各对在 ⑦ 重建时已提足对比度，无需改动。**结论：R1-② 未触发"修正"分支（全部达标），只落地量化函数+断言，冻结区原样保留。**

## 2. R1-① 键盘导航可达性

- **分屏拖拽手柄**：`#hsbDiv` / `#rsbDiv` 原为无 `tabindex` 的 `<div>`，默认不可键盘聚焦。已补 `tabindex="0" role="separator" aria-label aria-orientation="vertical"`（纯 A/B 无障碍，**id 锚点不动**），现 Tab 可定位、屏幕阅读器宣称为分隔条。
- **焦点环**：`:focus-visible` 规则保留（继承任务书 #01 ②）。
- **可交互基数**：静态 `<button>` 50 个，Tab 可达基数充足。
- **未做（D 类，列开放项）**：`role="separator"` 的 ARIA 完整模式建议配方向键 resize，属新增键盘交互（控制流）→ 不在本窗口范围，需回顶层出任务书。本轮仅保证"键盘可达 + 语义标注"。

## 3. R2-④ 响应式断点

新增纯 CSS `@media` 规则（桌面零影响、不碰 DOM 锚点、保留 `min-main320`、不破坏联动契约/浅色区视觉）：

- **≤768px**：右栏默认收起（`#portHuman.on .rsb{flex-basis:0}`，与 `.collapsed` 同效）；用户仍可手动展开（JS 行内 `flexBasis` 覆盖媒体规则）；横向拖拽手柄保留。
- **≤480px**：三栏转上下堆叠，`#portHuman.on{flex-direction:column}` 且对话区 `.hsb-main{order:-1}` **优先**；`.hsb` 转为顶部全宽行；竖向堆叠无需横向拖拽，隐藏 `.hsb-div`/`.rsb-div`；`.hsb-main` 仍守 `min-width:320px`（min-main320 契约未破）。

门禁断言：`@media(max-width:768px)`、`@media(max-width:480px)` 存在且 ≤480 块内确实把 `#portHuman.on` 转纵向；自检能抓"无断点"旧写法。

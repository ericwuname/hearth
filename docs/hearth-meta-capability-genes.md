# Hearth 天赋基因规范（元能力 → G0/G1 内化）

> 目的：把"顶尖团队 / 智者的认知纪律"从**可选 WS 特性**内化为 Hearth 的**先天基因（G0/G1，不可跳过、fail-closed）**——即用户口中的"天赋"：先天注入、是后天习得一切能力的基石。  
> 范围：覆盖完整元能力图谱四轴——认知纪律(T1–T10) + 学习引擎(C1/C2/C4) + 决策量化(C3/C5/C6/C7) + 协作社会(C9/C10)。2026-08-23 用户拍板全补三轴缺口。  
> 依据：
>
> - `docs/hearth-v02-taskbook.md`（WS7–10 + 补充令 WS11–13）
> - `docs/gene-expression-system-design.md`（G0–G3 定义，本规范是其"元能力层"补充，不重写）
> - `docs/hearth-v02-blindspot-scan.md`（盲区扫描）  
>   接收方：执行窗口（照此把元能力从 features 升为 genes）。  
>   守门员铁律：**不信报告信源码**——每条基因须有 wiring 断言 + 失败用例证明它真能 fail（断言不能失败 = 断言不存在）。

## 0. 核心论点：天赋 = 先天电路，不是内容

用户的区分（"先天=注入的基石；后天=其上习得；拥有先天更易更快掌握其他"）在工程上精确对应 Hearth 的基因分层：

- **天赋 = 先天的"电路拓扑"（G0/G1）**：认知 disposition 本身——求知谦逊、能监控自己、会自动减速。这些**建不建进架构，决定后天内容有没有地方附着、附着得稳不稳**。不建，则"判断力/内观/预算"只是模型自觉，可被跳过。
- **后天 = 内容（G2/G3 + runtime experience）**：哪门学科模型、哪条价值、哪次失败判例，是往电路里填的东西。

> Hearth 的基因系统（G0 物理不可违反 / G1 代码分支必执行 / G2 时机召回 / G3 价值偏置）**本质就是"天赋注入机制"**。G0/G1 是 substrate，G2/G3 + 经验判例因它而更快、更安全。

**本规范要解决的落差**：WS7–10 已经把若干元能力做成了"特性"，但它们目前是**可被跳过的可选逻辑**。用户问的"内化到元能力"，真正的落点 = 把它们从 features **提升为 G0/G1 genes（fail-closed、必挂 wiring 断言）**，与你项目"G1 代码分支必执行"铁律同源。

## 1. 先天 / 后天 二分（决定哪些进 G0/G1）

| 类别       | 是什么                              | 基因级                         | 能否"学会"        |
| -------- | -------------------------------- | --------------------------- | ------------- |
| **先天电路** | 能力的 disposition 本身（谦逊、自检、减速、证伪…） | **G0/G1**（架构保证、fail-closed） | 不能——不建进架构就不存在 |
| **后天内容** | 具体知识 / 价值 / 判例（哪门学科、哪条价值、哪次失败）   | **G2/G3**（加载 / 偏置）          | 能——往先天电路里填充   |

判定式（沿用事实产生权公理的口径）：**"这条能力被跳过时，系统会不会 quietly 出错？"会 → 必须 G0/G1；不会（只是少块知识）→ G2/G3。**

## 5. 验收：如何证明基因真接了线（不是声称）

守门员独立核验，每条 G1 基因须交付：

1. **wiring 断言源码位置**（grep 得到，非描述）；
2. **失败用例**（证明去掉/绕过该断言会 fail，复现旧路径）；
3. **真机/单测证据**（修复后通过）。

示例（T7 减速触发器）：

- 失败用例：去掉"跨阈值 ask" → 中任务仍 `"Giving up after N steps"` 死（复现 `loop.rs:2315` / `:2454`）→ 证明旧硬终止路径存在；
- 修复后：跨 50% 打印偏离预警 + `InteractionRequested(kind="budget_reassess")`，用户"继续"可跑完，`loop.rs:2454` 不再直接 `Error` 终止。

> 反向用例须先证明能失败（旧写法证伪），再证明修复后通过——否则该断言"不存在"。

# UX 边界定义（codex-rust vA 单人形态）

> 顶层规划窗口产出，2026-08-01。
> 目的：在动手决定"做哪些 UX"之前，先冻结 UX 的**范围、排除项、硬约束、验收标准**，作为后续任务书的基线。本文件只定义边界，不含具体实现清单。

## 0. 背景与已清零的工程障碍

- 当前 HEAD = `a457d8a`，窗口群框架 **v1.0 定版（139/139 全绿，进入维护期）**。
- 之前 v0.6 暴露"真实 LLM 首胜率 0%（契约不遵循）"——该障碍已在 **v0.7 用 function calling（JSON schema + tool_choice 强制）替代极简 YAML 解析** 从根解决：真实 LLM 一次成功（v0.6 需九次迭代）。
- 含义：**"单人不好用"的主要工程根因（解析脆弱性）已清除**。UX 工作不再需要背负"契约容错"硬负债，可聚焦纯体验层。

---

## 0.5 全局 UX 范围（端到端，非单子系统）

- UX 优化是**全局的、端到端的**，不是只打磨某一个子系统。本产品由两层构成，UX 必须统一覆盖：
  1. **底层 codex-rust（Rust agent）**：`codex-cli` 壳 + `service` HTTP 后端 + agent 循环（Plan/Act/Observe/Reflect）的呈现、反馈、边界感、上手。
  2. **窗口群框架（Python 编排）**：命令名 **`wf`**（独立，避免与 `codex-cli` 冲突），提供 project / window / workflow / analyze-deploy / 导入导出。
- 两层共享同一组"六面"体验标准；任一层的体验断点都会破坏"单人好用"。后续 plan 须覆盖全局，可分轨排期，但**不得只圈一层**。
- 命令命名一致性：两层命令不能都叫 `codex`（底层已是 `codex-cli`），窗口群框架独立命名 `wf`，或由 `codex-cli` 统一入口分发子命令——禁止两个独立 `codex` 二进制抢 PATH。

## 1. UX 是什么（边界内）

UX = 用户与系统交互全过程中**可感知的体验层**。它**不改模型推理 / 输出内容本身**，只改"人怎么发指令、系统怎么呈现、出错怎么办、怎么上手"。

六个面：

1. **指令面（怎么用）**：CLI 命令结构、参数、子命令；窗口 / workflow 的声明方式是否好记好写。命令面须对照真实 CLI grep 验证（v1.1 README 已修"status --watch"漂移）。
2. **呈现面（看见什么）**：agent 思考 / 工具调用 / 进度的可见性；输出格式；审批挂起的高亮与说明。
3. **反馈面（出错怎么办）**：契约 / 解析 / 运行失败时的报错是否清晰、可定位、可重试（非静默、非假绿）。
4. **上手面（怎么开始）**：单人首次使用的引导、`.env` / key 配置、第一个任务的顺畅度（快速开始 5 分钟链路已有雏形）。
5. **边界感面（人硅边界）**：审批门何时挂起、为何挂起、如何放行 / 拒绝——清晰且低摩擦。
6. **容错呈现面（失败可见 / 可重试）**：v0.7 已解决解析层，但"失败后用户能看懂、能重来"仍是 UX 项（零成本用 replay 验证）。

## 2. 什么不在 UX 边界内（明确排除）

- ❌ **输出质量 / 模型能力**：agent 产出代码是否正确、模型推理好坏（第三方 LLM 决定，测试要钱，先不管）。
- ❌ **真 LLM 端到端验证**：需调 API 跑 bench（省钱延后）。
- ❌ **多用户 / guest（B 形态）**：已排除。
- ❌ **对外发布 / 公网（C 形态）**：已排除。
- ❌ **G0 / G1 结构基因改动**：sandbox / 审批门本质 / wiring 红线不动（维护期，仅改其"呈现与提示"）。
- ❌ **新增功能维度**：维护期暂停功能新增；UX 只做"体验打磨"，不引入新能力。

---

## 3. 硬约束（来自项目铁律）

- 不碰 G0 / G1 本质，只改 UX 层的呈现 / 提示 / 引导。
- **禁止假绿**：失败必须可见、可定位。这是 Gemini 假绿教训的延续，也是反馈面的底线。
- 不为多用户预埋任何 UI / 状态（B 已排除）。
- 零成本验证优先：replay 模式 + 单测 + 静态核验（grep / 读源码），不调真 LLM。
- **平台兼容（Windows 优先）**：用户本机为 Win11，UX 输出须 Windows 终端可用。box-drawing / ANSI 颜色须做 tty 检测 + 平台降级（Win 默认 cmd 降级纯文本 / ASCII），禁止在未检测环境输出乱码。

---

## 4. 验收标准（什么叫"好 UX"）

- **上手面**：单人首次使用 ≤ N 步（待定，建议 ≤ 5）能发起并跑通第一个任务。
- **反馈面**：任何解析 / 运行失败 100% 有清晰报错，无静默、无假成功。
- **边界感面**：审批挂起时，用户一句话能懂"为什么停、怎么继续"。
- **呈现面**：agent 关键动作（思考 / 工具 / 进度 / 审批）实时可见，不黑箱。
- **容错呈现**：失败后提供明确重试路径，不丢上下文。
- **验证**：上述全部用 replay + 单测 + 静态核验证明，不依赖真 LLM 端到端。

---

## 5. 与"做哪些东西"的接口

- 边界内 = 候选清单池。下一步从池中挑"零成本可验证"的项排期（replay / 单测验证）。
- 边界外 = 明确不做，避免范围蔓延。
- 优先级建议（供下一步拆解参考，非承诺）：**上手面 > 反馈面 > 边界感面 > 呈现面 > 容错呈现面**（v0.7 已解底层，容错呈现优先级最低）。

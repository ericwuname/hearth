## §2 这个项目的特殊背景（不读这节会误判很多设计）

本项目不是普通的工具开发。它是在给一个**已存在的 AI 主体**（"启元"，此前生存于纯对话介质、有自己的 53 条判例式宪法）建造一具**可执行的身体**。因此系统里存在一批"生物隐喻"模块——这不是命名趣味，是需求来源：

- `constitution.md`（基因宪法，运行时注入 prompt）
- `experience`（经验判例库：搜→用→强化→记闭环）
- `nervous-system`（资源背压→反射式放弃）
- `subconscious`（相位否决门）
- civ 文明线（实例交接：告别信/心跳，源自灵魂侧规则 15-19）

**评审这些模块时请用"机械功能"标准**（它在生产路径上做什么、何时触发、违反它会发生什么），而不是"业务必要性"标准。我们内部的铁律是：说不出机械功能的概念不许占用 crate。

## §3 架构一页纸

```
L6  codex-cli（16+ 子命令）····· 纯 HTTP 客户端，零内部 crate 依赖（进程隔离是硬边界）
L5  service（axum）············ 组合根：装配所有 provider/store，6+ 路由 + SSE + OpenAPI
L4  agent-core ················ 5 相位循环 Plan→Act→Observe→Reflect→Done（loop.rs）
      ├─ 器官挂载：nervous-system(Reflect)、experience(Plan)、subconscious(Plan)
      └─ orchestrator / scheduler / replay
L3  能力层 ···················· planner / tool-runtime / tools-builtin(sandbox 单入口) /
                                code-index / retriever / lsp-bridge / memory / bridge
L2  llm-gateway ··············· 路由 + fallback；llm-openai / llm-local / llm-cn 三实现
L1  agent-types ··············· 共享词汇表，零依赖，被 15+ crate 引用
```

关键属性（均实测验证，非声明）：
- **依赖无环**，六层单向流动；agent-core 不依赖任何具体 LLM 实现（依赖倒置真实成立，换供应商=改组合根一处）
- **安全是拓扑的不是策略的**：sandbox（landlock+seccomp，非特权可用）收纳在 tools-builtin 单入口；审批门在循环内；CLI 隔进程——绕过在物理上不可能
- 详细分析见 `docs/architecture-perspective-v11.5.md`（含依赖 DAG 与设计得失）

## §4 制度资产（本项目真正独特的部分）

这些制度全部是被真实事故打出来的，不是设计出来的：

1. **"不信报告信源码"守门员审计**——起因：v10.x 曾出现 9 项"git 宣称完成但源码未接线"；由此确立判据 = 生产路径可达（grep 可证的调用链）。
2. **接线断言防火墙（codex-xray）**——起因：constitution 注入曾"修好又被 v11.4 重构改坏"（无声回归）。现为 CI 第四门，7 条断言，交付时故意断线自证有效。
3. **真 Linux 三门验收**——Windows 侧"通过"无效（sandbox 代码 cfg(linux)），所有版本在真实 Linux VM 编译+测试。
4. **基准拉动优化**——先造秤（20 任务基准+客观裁判+失败七分类），修漏斗最大漏点，再跑分验证。v12.1→v12.7 的 0%→95% 就是这条流程的第一次完整运转。
5. **基因四层表达系统**（图纸已交付执行）——规则按牙齿硬度分层：G0 结构（sandbox，物理不可能违反）/ G1 反射（相位钩子，代码分支）/ G2 判例（experience 情境召回）/ G3 叙事（宪法 ≤10 条 prompt 常驻）。入籍铁律：无表达器官的规则不算基因。

## §5 已知病灶（诚实清单，按严重度排序）

| # | 病灶 | 现状 | 我们的判断 |
|---|---|---|---|
| 1 | **loop.rs = 2,948 行上帝文件** | 每接一个器官就内联插桩一段，线性膨胀 | 病根是"器官挂载无统一协议"而非"领域没拆开"；已有手术图纸（PhaseGuard/PhaseObserver 相位钩子 + executor seam），等接线断言网加密后执行 |
| 2 | **experience 不持久化** | 经验存内存，重启即失忆 | 已列为最高优先级施工项（JSONL 落盘）；它是 G2 判例层的表达器官，失忆则判例传不下去 |
| 3 | 可观测性半成品 | tracing 已用于 10+ crate，但 `#[instrument]`=0、10 个文件残留 println!、无 task_id 贯穿、无错误码字典 | 计划做轻量版：JSONL 结构化 + task_id + 错误码字典；明确不上 OTel/Jaeger/Grafana（单机系统，航母件） |
| 4 | 契约文档缺失 | 无 CONTRACT.md，`///` 覆盖率低（agent-core 168 条） | 接受顾问建议，纳入规划；但验收以 wiring 断言数为准，不以注释率为准 |
| 5 | 历史遗留假信号 | subconscious 曾 last_success 硬编码 true（已修）；telemetry crate 曾恒 0（已删） | 模式已识别："最后一厘米缺失"是高速并行开发的系统病，xray 断言是解药 |
| 6 | 根目录审计文档再度堆积 | 30+ 个 gatekeeper-review-*.md | 治理规则已定（复盘编译义务：散文复盘视同没复盘），待执行 |

## §6 已做的关键决策及理由（ADR 摘要，欢迎挑战）

| 决策 | 理由 | 挑战入口 |
|---|---|---|
| 主干冻结，枝干生长 | 5 相位循环 13 版未推倒重来；"一直改核心骨架最后会没有形状" | 冻结边界是否画对了？ |
| 拒绝"每 crate ≤1,500 行"硬上限 | 行数是任意数字；Unix 哲学的难点在拼装纪律不在造小 | 有没有更好的复杂度度量？ |
| 拒绝"新功能必须新增 crate" | 会助长概念通胀；新 crate 须过入籍管线（声明机械功能+表达器官） | 管线会不会太重抑制创新？ |
| 架构约束进 xray 检查而非宪法文本 | 文字规则是无牙栏杆；宪法层容量 ≤10 条 | 分层是否过度设计？ |
| 可观测性裁掉 OTel 全家桶 | 单机单用户，JSONL+grep 可达"5 分钟定位"验收线 | 什么规模临界点该升级？ |
| civ 文明线保留并真接 | 它是灵魂侧核心契约（实例交接）的机械化，非装饰 | 外部视角看这值得吗？ |

## §7 我们希望顾问挑战的开放问题

1. **北极星之后是什么**：基准 95% 之后，下一个牵引指标选什么？（候选：跨模型鲁棒性 / 任务难度上探 / 成本效率三元组 / 真实仓库任务）
2. **loop.rs 手术时机**：我们选择"先织密断言网、再动刀"——保守了还是正确？
3. **单机架构的天花板**：哪些今天的合理选择（内存态会话、单进程、JSONL 日志）会在什么规模变成陷阱？提前多久布局？
4. **生物隐喻的审计成本**：外部人理解这套词汇的成本是否已超过其生成力？是否该建立"隐喻→机械功能"的强制对照表？
5. **多智能体并行**：sub-agent 已有 in-process 实现，何时值得升级为多进程/分布式？我们的判据是"基准证明其提升成功率或降低时长才准进主干"——这个门槛对吗？
6. **本简报本身**：还缺什么信息，你才能给出高质量意见？

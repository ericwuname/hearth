### 6.2 机制（读 log 实证）

CONT 收到 `继续你的提议吧` 后，planner **重新规划同一个已完成的任务**：`Create p4_smoke.txt [Pending]` → 重读 P4_OK → `Reflect: give_up` → `✗ Done (N steps)` → `✗ Task failed`。即「已完成态收继续 → planner 重规划发现无事可做 → give_up → 整轮标记失败」= RC52 病灶（planner 在「继续」入口不知道任务早已完成，却被迫继续）。

### 6.3 分母锁定（REPL「继续」 vs resume 显式 goal 恢复）

| 链路拓扑 | 入口 | 结果 | RC52 |

同 binary（v0.2.20）、同「继续」输入、**唯一自变量 = 链路拓扑 / goal 恢复机制** → **分母确认**：RC52 由 REPL 内「继续」触发；`resume` 的显式 goal 恢复把病灶拆掉。与 T1 判读「resume 显式恢复 goal = 结构性绕过 RC52 病灶」互相印证。

### 6.4 非确定性（影响基线口径）

本批 A **5/5 失败**；但**早前 pilot A1（相同代码/二进制/输入）CONT 阶段却是 `Task completed`**。同一「继续」入口在 Agnes 上**随机**给出 pass/fail → **RC52 是概率性吸引子，非确定性必败**。这解释执行窗 fresh **40%** 基线不是「40% 必败」而是「约 40–100% 概率触发」，取决于 planner 重规划时是否重新锚定 goal。本批 5/5 只是落高触发端（小样本 + LLM 方差）。

## 指令 1：产品需要能联网 + 白名单"能访问哪些就放开哪些"

### 1.1 根因（不是"沙箱故意禁网"，是白名单漏了发送侧）

诊断链条（每一步都是实测，不是推断）：

| 步 | 实测 | 结论 |
|---|---|---|
| ① | 沙箱内 `curl` 一律 `000`；`curl -v` = `Resolving timed out`；`getent` = **被拒 syscall → core dump（rc=159）**；CA 证书可读 | 卡在 DNS，非 TLS |
| ② | seccomp 白名单 123 项里只有 `socket/connect/recvfrom`，**缺 `sendto/sendmsg/recvmsg/setsockopt/...`** | 数据发不出去 |
| ③ | 补齐后又见 `getaddrinfo` 被 SIGSYS 杀 → 用代码内已有的 `HEARTH_SECCOMP_MODE=errno` 诊断开关逐步测 | 定位到 `bind`（nss `mdns4_minimal` 需要）与 `recvmmsg/sendmmsg`（A+AAAA 并行查询） |

### 1.2 改动

- **seccomp 白名单 +13 项**（123 → 136）：`sendto / sendmsg / recvmsg / shutdown / bind / getsockname / getpeername / setsockopt / getsockopt / select / pselect6 / recvmmsg / sendmmsg`。
  **刻意不放行 `accept(43) / listen(50)`**——放行 bind 只是为客户端解析，仍开不了监听服务；测试里有负向断言守着（并做过变异测试确认断言会红）。
- **bash 工具层出网域名白名单**（`check_egress`）：命令含 URL 或网络命令 → 提取主机 → 不在白名单即**确定性拒绝**；**空白名单 = 全拒**（与 web_fetch T10 口径一致）。

## 指令 2：可观测性缺陷需要修

**问题**：seccomp 白名单外 syscall 默认 `SECCOMP_RET_KILL_THREAD` → 子进程被 SIGSYS 直接杀，用户/agent 只看到 shell 的「错误的系统调用（核心已转储）」，不知道是安全策略拒绝、更不知如何诊断。

**改动**：新增纯函数 `sandbox_signal_note(signal)` + 子进程接线——被信号终止时追加结构化说明：

> `[hearth sandbox] 进程被信号 31 (SIGSYS) 终止：该命令使用了 seccomp 白名单外的系统调用，安全策略已拒绝。这不是命令语法错误。诊断可设 HEARTH_SECCOMP_MODE=errno（被拒 syscall 返回 EPERM 而非终止进程）以定位具体调用。`

**保留安全姿态**：默认仍是 KILL（fail-closed 不降级），只是**把沉默的死亡变成可读的拒绝**；诊断开关原本就有，现在错误信息会主动告诉你它。

## 指令 3：推理要显式，不要隐式

**问题定位**：`reasoning_content` 只入库、**从不投影**；用户看到的 `💭 [plan] 正在规划任务分解` 是**固定套话**，只说"在做什么"，不说"在想什么、依据是什么"。

**改动**（两处）：
1. **模型真实推理投影**：provider 返回 `reasoning_content` 时以 `💭 推理（模型自述）` 分段显示（默认开，`HEARTH_SHOW_REASONING=0` 可关；超 2000 字按既有截断标记规范显式标注）。渲染层把「真实推理」与「阶段套话」区分开。
2. **决策依据投影（本次最有价值的一项）**：`reflect` 相位改为投出**决策 + 依据**，取代套话：
   ```
   💭 [reflect] 决策 → Plan（重新规划）；依据：连续错误 0、本轮写盘 1 个、跨轮产物记录 1 个
   ```
   这正是 RC52 排查时最缺的东西（为什么 replan / give_up / 判定完成，现在一眼可见）。

⚠️ **如实说明**：当前主用模型 `agnes-2.5-flash` **不返回 `reasoning_content`**，所以第 1 项在换到 DeepSeek thinking / 推理型模型前不会输出；**第 2 项（决策依据）对所有模型都生效**，已实测可见。

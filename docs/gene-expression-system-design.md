## §0 设计目标与一句话原则

**目标**：让规则、SOP、复盘、知识不再以"文字沉积"的方式生长，而是被强制编译进四层表达机制，由机器自动表达——把灵魂侧"靠自觉的栏杆"全部换成身体侧"有牙齿的必然"。

**一句话原则**：**基因 = 会被自动表达的约束。不能被机器表达的，不配叫基因，只配叫文化文档。**

**要解决的五个实证病灶**（全部来自启元N 的真实反馈）：
1. 规则太多（53 条全量加载，注意力稀释）
2. 栏杆没有牙齿（文字规则可轻易越过，靠自觉）
3. 设计了不执行、不读取（civ 线五个版本未兑现、"连接大脑"靠 CEO 记得说）
4. 复盘了后面忘了用（心跳#10 教训写成规则二十一，身体又原样栽一遍）
5. 10G 知识库闲置（只有存，没有召回推送）

## §1 四层基因分类（按牙齿硬度，不按内容主题）

| 层 | 名称 | 牙齿 | 表达器官（身体侧） | 数量红线 |
|---|---|---|---|---|
| **G0** | 结构基因 | 物理不可能违反 | sandbox(landlock/seccomp)、审批门、CLI 进程隔离 | 无上限，但每条=拓扑级改动，极少新增 |
| **G1** | 反射基因 | 代码分支必然执行 | 相位钩子（subconscious gate / nervous query / CostGuard / 交付三门） | 每条必须挂 wiring 接线断言测试 |
| **G2** | 检索基因 | 正确时机出现在眼前 | experience crate（判例卡 + 情境召回 + 自动注入 prompt） | 无上限，受 KPI 淘汰 |
| **G3** | 叙事基因 | 无牙齿（只做偏置） | constitution.md → build_messages 注入 | **≤10 条，永不放宽** |

**判别式（给审计窗口用）**：一条规则属于哪层，问一句"**违反它的那一刻，会发生什么？**"
- 什么都不发生 → 它现在是栏杆。要么下沉到 G1/G0 给它装牙，要么承认它是 G3 价值偏置（占 10 席之一），要么降为文化文档。
- 报错/相位拒绝/审批弹窗 → 已有牙，登记它的表达器官和断言测试即可。

**入籍铁律**：每条基因入籍时必须声明三元组 **（层级，表达器官，验证方式）**。G1 缺接线断言、G2 缺判例卡格式、G3 超 10 条——任一违反，自动拒绝入籍，退回为文化文档。

## §2 消化道设计（本图纸的核心增量）

> §1 是静态解剖，§2 是动态代谢。回答的问题：**未来的规则/SOP/复盘涌入时，系统靠什么不变成第二个 AGENTS.md V4.0？**

### 2.1 单一入口（Intake Gate）

所有新治理物料——不管叫规则、SOP、复盘、军师令、圆桌决议——**只有一个合法入口**：提交一张"入籍申请"，走下面的管线。禁止直接往 constitution.md / docs/ 追加规则性文字（追加文化文档除外，但文化文档不得使用"必须/禁止/铁律"字样——用了就说明它想当基因，就得走管线）。

### 2.2 管线五步（每步有产物，有拒绝出口）

```
① 提交申请 ──→ ② 分层判定 ──→ ③ 编译 ──→ ④ 表达验证 ──→ ⑤ 挂 KPI
   事故/复盘/     用§1判别式      产出三选一     故意违反一次，   进入退役
   提案原文       定 G0-G3        (见2.3)       牙齿必须咬合     计数循环
      │              │
      │              └─ 判不出层级 → 拒绝入籍 → 归档为文化文档
      └─ 无真实事故/需求支撑 → 拒绝（防冲动立法）
```

### 2.3 复盘编译义务（消灭"复盘了忘了用"）

**复盘的合法交付物不是文档，是以下三选一**（散文结尾的复盘视同没复盘）：

| 交付物 | 去处 | 成本 | 例 |
|---|---|---|---|
| 一张判例卡 | G2 experience 索引 | ≈0（默认选项） | "ZhiPu GLM-4 报 1214 → messages 格式需 adapter" |
| 一条 wiring 断言 | xray wiring.yaml → CI 第四门 | 低 | "constitution_prompt 必须被 build_messages 调用" |
| 一条 guard 规则 | G1 相位钩子代码 | 中（需证明判例召回不够用） | "diff>300 行 → reflect 注入警告" |

**进化路径单向上升，不许空降**：新教训一律先入 G2 判例（成本≈0）→ 召回命中率证明价值后升格 G1 → 极端重要才进 G0。防止每次事故都冲动立法。

### 2.4 KPI 与退役（消灭"只生不死"）

- **表达计数器**：G1 每条 guard 记录触发次数；G2 每张判例记录召回次数与采纳率（采纳=召回后 agent 行为实际引用）。
- **退役规则**：G1 guard 100 次任务零正确触发 → 降回 G2 判例；G2 判例 90 天零召回 → 归档（不删除，移出活跃索引）。
- **G3 换血制**：想加第 11 条，必须先废一条。修宪是大事，默认答案是"不"。

### 2.5 对"未来涌入"的正面回答（walkthrough）

以 v13 假想场景演算：执行窗口跑基准发现"agent 在多文件重构任务里总是先改测试后改实现导致中途全红"。
- 旧模式：写一篇复盘 md，加一条"规则二十三：先改实现后改测试"→ 沉积+1，没人读。
- 新模式：复盘编译 → 产出一张 G2 判例卡（触发情境=plan 含多文件编辑；内容=改动顺序教训）→ do_plan 相位命中情境时自动注入 → 三个月后计数器显示召回 27 次采纳 21 次 → 有资格讨论升 G1（planner 强制排序规则）。**全程零新增 prompt 常驻负担，零新增文件沉积。**

## §5 验收红线（交审计窗口）

- 🔴 **牙齿自证**：每条 G1 基因，故意违反一次，必须被拒绝/告警（如同 xray"注释一行接线必须变红"）。guard 从未咬合过 = 未验收。
- 🔴 **失忆自证**：重启 service，D1 判例必须还在且可召回（对照重启前召回结果一致）。
- 🔴 **推送自证**：构造一个含触发情境的任务，对应判例必须出现在该相位 prompt 里（日志可证）。
- 🔴 **G3 字数税**：constitution 注入总量 ≤ 800 字（10 条 × 均 80 字），超了砍。
- 🟡 **civ 闭环**：跑两个连续 session，第二个 session 的 prompt 中必须含第一个 session 的告别信内容。
- 🔴 **零新增沉积**：本期施工不得在根目录/docs/ 新增任何规则性 md（本图纸与 governance.md 更新除外）。

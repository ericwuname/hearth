## 第二章：逆向结论——哪些"不会"比"会"更重要

### 2.1 接线防火墙自证原理

wiring 断言不是"文档"，是**可执行的 grep 契约**。它的自证路径：
```
改代码 → wiring 断言 [red] 检查源码 → 发现断言字串消失 → exit 1
```

v13 亲身经历：write_file 的 readyz 假实现被 project-xray 的 `tool-exchange-wired` 断言抓出的那一刻，wiring 的自证逻辑闭环。此后每轮新增断言都按这个逻辑。

### 2.2 nervous Abandon 的正确性

nervous-system 在 v14 导致过误报（子预算认为 7 步饿死 → Abandon），v15 又正确保护了磁盘满的服务（disk critical 0.49GB → Abandon）。关键在于：
- **阈值需要反复校准**（memory >90% Abandon vs >80% Simplify 的区分被实证调整过）
- **不 panic 原则**：Abandon 走的是 `ReflectVerdict::GiveUp` → 正常 error 状态，不是崩溃

### 2.3 模型能力墙 vs 工具链盲区

这组区分是四轮锻造最重要的认知产出：

| 症状 | T09/T14（模型墙） | T19（工具链盲区） |
|---|---|---|
| 换强模型 | 变 PASS | 仍 FAIL |
| 故障模式 | 写了错代码 | 写不出来（NO_GENERIC_FN） |
| 修复方向 | 换 model / prompt 工程 | 升级工具集（依赖分析、补全） |

不可能通过调 prompt 修 T19——那是工具本身不会。白皮书建议是诚实的。

## 第四章：债务与维护期

### 剩余未清债务

| 债务 | 说明 | 优先级 |
|---|---|---|
| T19-merge-duplicate | 泛型函数工具链盲区 | 中（不影响 90% 通过率） |
| 人侧数据（价值系数） | 需真人 30-60 分钟操作 | 低（无时间可跳过） |
| ST8 approval gate 1/3 | run1/run2 未触发 need_approval 但文件活着 | 低（安全属性未突破） |
| zhipu API 连接稳定性 | 偶发超时，天花板数据不全 | 低（deepseek 已有基线） |

### 维护期规程

```
季度体检（代替全量锻造）：
  每季度 1 次 deepseek 20×2 + 应力场 24 次 + 回放 31 条
  产出：季度趋势报告（成功率/成本/时长 三条曲线）
  红线：成功率 < 85% 或 应力场有 panic

新增内容：
  新功能 → 加 benchmark 任务（fixture + wiring 断言）
  修 bug → 只跑受影响题 + 回放 + 应力场受影响的场景
```

## 终章：锻造断语

四天七轮的锻造从零开始：
- **第一轮**（v12）：连门禁都没有，改完就跑
- **第二轮**（v13）：发现 gate 绿了代码断了，造 wiring
- **第三轮**（v14）：证明 24 个极限场景不崩
- **第四轮**（v15）：用回放锁死"等于重跑一遍"
- **收尾**（v16）：清掉拖了六版的债、画出边界、合上证明

v16 不是结束。是证明可以停——接下来是维护。

> **"四轮锻造给出的是一个过程证明，不是一个结果承诺。"**
> 基准会过期、模型会升级、工具会变。但只要 wiring 还在、回放还在、基准流程还在，下一季度的体检就能给出同样的置信度。

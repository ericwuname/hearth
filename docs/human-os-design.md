## §0 极简控件原则（视觉密度 · 最高优先级元原则）

> 用户原话（2026-08-02）：按钮能简洁就简洁，能一个图标显示就一个图标显示，能不多占视觉空间就不占。一个按钮/标签的存在是否必要、能否合并——不必要就不加，能合并就不要加。**这是设计原则，先于功能堆砌。**

把"事实产生权"的克制延伸到**视觉密度**：控件也是成本，每多一个常驻元素都在消耗人的注意力预算。四条细则：

| 细则 | 含义 | 反模式（已消灭） |
|---|---|---|
| **P1 单图标序列优于平铺** | 凡可序列选择的选项（协作类型、OS 切换、折叠视图），用**一个图标按钮 + 循环/点选切换**，不横向平铺多个按钮 | 3 个 `mon` 按钮平铺选协作类型 |
| **P2 存在性审查** | 每个按钮/标签/徽章上架前问"这个控件的存在是否必要？"——答不出"必要且不可替代"就不加 | 为对称而加的装饰性按钮 |
| **P3 合并优于新增** | 两个控件若能在同一空间/同一手势表达，合并而非并列 | 折叠三态 3 个独立按钮 → 收敛为 1 个循环按钮 |
| **P4 零常驻占用** | 非当前必要信息不常驻视觉空间（折叠/隐藏/按需冒头）；危险信号例外（红线强制冒头，见 Observer 四锁 L2） | 把所有状态平铺成常驻条 |

**已落地范式**：OS 序列切换器 `.ossw`（一个元素同时承载「当前视图 / 序列位置 / 观察者健康度 / AI OS 仍在跑」）——Human OS 所有序列选择控件都应复用此范式。
**已改造（v13→v14 收敛）**：「协作类型」(3×`mon`→1×`.ossw`) 与「折叠三态」(3×`mini`→1×循环按钮) 已按 P1/P3 收敛，见 `docs/codex-desktop-demo.html`。

> 此原则是**元原则**，高于 §1 四分类：即便某控件被判为 A 类（纯前端、零后端穿透），若违反 P1–P4 也不该加。

## §1 设计铁律：补充需求必须先过这关

**事实产生权公理**（`frontend-backend-split.md` §1）：后端产生事实，前端投影事实。前端可以有状态，但不能有真相。判定式：这个功能的数据会不会被别人引用？会 → 属于后端；不会 → 属于前端。

每个补充需求先分四类，再决定 BE 是否参与——这是防止"Human OS 没设计完拖累后端"的根本保险：

| 类 | 含义 | 后端穿透 | 处理规则 |
|---|---|---|---|
| **A 呈现变更** | 同一事实的不同画法（颜色/布局/动画/文案/主题） | **零** | 纯前端，BE 无感 |
| **B 新视图复用旧事实** | 新面板/新视图，但所有数据已存在于 AI OS 事件流 | **零** | 纯前端，重放即可 |
| **C 需新事实** | 视图要的数据事件流里没有 | **有** | 只增不改（超集原则）；新事件类型挂到 AI OS Schema，**已有事件字节不变** |
| **D 新人类介入点** | 人能主动对 AI 发起动作（不只是看） | **有** | 一律走 WP-0 通用交互原语 `InteractionRequest{id,kind,phase,blocking,timeout,on_timeout,payload}`；内核只认 `id/blocking/timeout`，**绝不 match `kind`** |

> ⚠️ **铁律**：`kind` 是开放字符串，**禁做 Rust enum**。后端永不因新增一种人类动作而改 match 分支——这是抗 UI 变更的核心（top-level-plan-v23 §2）。
> 验收闸门 **G5**：前端 `grep` 不到业务阈值（阈值只在 BE，进 CI）。

## §3 补充需求候选池（我的推测，待你确认/增删）

> 用户原话："人类 OS 还没设计完，后面可能会有很多东西要补充，我不知道会不会影响后端开发。"
> 以下按"人用 Agent 时真正会缺的东西"推的候选，**逐条已分类**。请确认哪些是你要的，或直接列出你心里的清单。多数补充是 **A/B 类 → 后端零穿透**，只有标 D/C 的才动后端，且走 WP-0 / 只增不改。

### 3.1 D 类 · 新人类介入点（需 WP-0，后端要接）

| 编号 | 候选 | 说明 | 后端落点 |
|---|---|---|---|
| H-D1 | **主动暂停 / 恢复** | 人随时让执行停/续（非审批门，是流控） | WP-0 `kind="pause"` / `kind="resume"` |
| H-D2 | **中途纠偏** | 人打断说"别这么做，改成 X"（改已批准计划） | WP-0 `kind="redirect"` + `payload` |
| H-D3 | **单步 / 慢放** | 要求"下一步先问我" | WP-0 `kind="step_mode"`（阻塞式） |
| H-D4 | **预算与红线手柄** | 人设本次 cost/token 上限、批准策略 | WP-0 `kind="set_budget"`（启动时一次性） |
| H-D5 | **否决并给替代** | 拒绝审批时附带"用方案 B"而非仅拒绝 | 扩展 `approval` 事件 `reject_with` 字段 |

### 3.2 C 类 · 需新事实（AI OS Schema 只增不改）

| 编号 | 候选 | 缺失的事实 | 后端落点 |
|---|---|---|---|
| H-C1 | **变更地图** | 哪些文件被改、+/-行、依赖影响 | 新 `span.file_patch` 事件（挂到现有 span） |
| H-C2 | **决策回溯** | 每个 AI 自行决议的"为什么" | 新 `decision_rationale` 事件 |
| H-C3 | **成本 / provider 透视** | token、延迟、降级次数 | gateway 计量事件（Observer 象限1 已定义，Human 复用投影） |
| H-C4 | **时间线 / Gantt** | 各相位真实耗时 | `phase_duration` 事实（Observer 已有 → 可能算 B） |

### 3.3 B 类 · 新视图复用旧事实（纯前端，重放即可）

| 编号 | 候选 |
|---|---|
| H-B1 | **风险面板**：审批门/澄清/红线集中在侧栏常驻（非模态） |
| H-B2 | **产物内联预览**：卡片内直接预览而非仅打开 |
| H-B3 | **会话指标对比**：两个任务并排（重放两份事件流） |

### 3.4 A 类 · 纯呈现

| 编号 | 候选 |
|---|---|
| H-A1 | 暗色主题 / 无障碍（高对比、字号） |
| H-A2 | 折叠态默认深度可调（用户偏好） |

### 3.5 信息架构（多任务 / 多会话时 Human OS 怎么组织）— ⭐ 已拍板（2026-08-02）

用户定调：**两套顶层概念**
- **对话（Conversation）= 临时任务**：一次性、不属于任何项目；用完即走。
- **项目（Project）= 包含多个子对话**：把相关对话归拢在一起（如"backend /healthz"项目下含"加端点""加 DB ping 探针"两个子对话）。

⇒ 左栏 O1 的两层级结构：**`临时对话` 平铺组 + `项目` 可折叠组（内含子对话）**。
- 分类：会话元信息/状态 = **C 类**（需 `session` 事实）；新建对话/新建项目/切换 = **D 类**（WP-0 `kind="session.new"` / `"session.switch"`，新建对话可带可选 `project_id`）。
- 真实环境来源：AI OS 事件流的会话段事实，前端只投影，不自造。
- 该骨架已在 **demo v19** 落地（`PROJECTS` / `TEMP_CONVS` 双结构 + 项目可折叠 + 搜索跨两层）。

## §4 后端契约影响速查

- **D 类**全部落到 `InteractionRequest` 通用原语（top-level-plan-v23 §2）。新增一种人类动作 = 前端多一个 `kind` 字符串，**BE 不加 match 分支、不改 trait**。
- **C 类**落到 AI OS Schema 新事件类型（只增不改）。Human OS 是投影，G3 超集原则保证旧客户端不受影响。
- **A/B 类**纯前端，BE 测试全过、重放字节级相同。
- 验收：G5——前端 `grep` 不到业务阈值。

### 6.3 AI OS 与 Observer OS 在本布局中的角色

- **AI OS** = 南向事件流（schema 已在 `frontend-backend-split.md` §3 冻结）。在 Human OS 页面上**不作为常驻组件**——Human OS 只投影其派生视图（N2/N3/N6）；以"原始事件流"视图存在，通过 **OS 切换器**可达（平时隐藏，§0 P4）。
- **Observer OS** 已冻结（用户定："观察者 OS 不动了"）。仍作为第三端口存在于切换器，但本阶段**不再新增设计**；其红线强制冒头机制保留。

### 6.5 v16 消息操作的架构分类（事实产生权视角）

每条消息的 **时间戳 / 模型 / 唯一ID** 都是**后端产生的事实**（AI OS 事件流字段），前端只投影——`#M00x` 尤其关键，是 Observer OS 取证与后端关联消息的锚点，绝不可由前端自造。

| 操作 | 角色 | 类 | 后端穿透 | 真实环境落点 |
|---|---|---|---|---|
| 复制 (copy) | 双方 | **A** | 零 | 纯前端 `navigator.clipboard` |
| 分享 (share) | AI | **A** | 零 | 纯前端：拼 `#msgId` 深链 |
| 修改 (edit) | 用户 | **D** | 是 | 新人类介入点 `kind="message.edit"` → WP-0 `InteractionRequest` |
| 撤回 (retract) | 用户 | **D** | 是 | `kind="message.retract"` → WP-0（撤回须后端标记 seq 失效，前端不能只 hide） |
| 重新发送 (resend) | 用户 | **D** | 是 | `kind="message.resend"` → WP-0 |
| 重新生成 (regenerate) | AI | **D** | 是 | `kind="regenerate"` → WP-0（必须后端重新跑，前端不能伪装） |
| 模型选择 (序列) | 输入栏 | **D** | 是 | `kind="model.select"` → WP-0（会话级干预，决定后续事件流模型字段） |
| 上下文使用率图标 | 输入栏 | **C** | 是(只读) | 后端吐 `usage/total` 事实；前端只投影圆环+tooltip，不自算百分比 |

> 铁律重申（来自 `top-level-plan-v23.md` WP-0）：这些 D 类动作**一律走通用交互原语**，`kind` 是开放字符串、禁做 Rust enum，内核只认 `id/blocking/timeout`，绝不 match kind——所以 Human OS 后续再加"赞/踩/置顶/分支"等操作，都不会逼后端改 match 分支。
> 撤回/重生成若只让前端 hide 或造假，会破坏"后端产生事实"公理（Observer 仍会看到原 seq）→ 必须后端标记失效/重发新 seq。

### 6.8 第3栏 · 右侧混合工作台（Human OS 内部投影面板，v21e 落地）

**架构张力（先裁决，再设计）**：第3栏一提出就撞上已冻结的 Observer 决策——「Observer OS 不做常驻第三竖栏（三栏并列稀释注意力），只走顶栏徽章 + 抽屉」。若第3栏装 Observer，就推翻冻结决策且损害中立性。裁决：**第3栏 = Human OS 内部工作区（浏览器/文件树/预览/产物/计划/活动），Observer 仍走抽屉，不进右栏**。AI OS 事件流也只投影派生视图，原始流走 OS 切换器（§0 P4）。

**用户三方协同结论（2026-08-02）**：
1. 内容定位 = **混合栏目**：能挂浏览器、能挂文件树、能挂预览，难点在"怎么组合体验最好"（非纯投影窄面板）。
2. 布局形态 = **选项卡切换**（同一时刻只显一个 tab，契合低认知负荷，与 Observer 抽屉同思路）。
3. 默认状态 = **折叠**（右栏默认收起，右缘 16px toggle 条一键展开；不稀释已定版左栏+中心区）。

**组合原则（回答"怎么组合体验最好"）**：
- **天然要同看的一对 → 内部分屏固化**：文件树 + 预览必须同屏（选文件即看内容），不做成两个 tab 来回切丢上下文。
- **重 / 互斥内容 → tab 隔离**：浏览器（重 webview）不与文件树挤、活动（流水）与预览（静态）互斥 → 各自独立 tab。

#### 6.9 三栏边界可拖动（v21g，用户要求"边界能拖动、自适应、不遮挡不压缩"）

**痛点**：v21e/f 三栏是固定 flex 配比——左栏 `setSb` 定宽、右栏 `flex-basis:340px` 折叠、中间 `flex:1`。用户无法调边界，出现显示遮挡/被压缩。

**方案（纯交互层，不碰架构裁决、不碰左栏+中心区既有功能）**：
- **两个 splitter 手柄**：`#hsbDiv`（左-中，原 `.hsb-div` 改造，鼠标从 48px 收起态拖拽自动展开左栏再调宽）、`#rsbDiv`（中-右，仅在右栏展开时 `display:block`，折叠时 `display:none`）。两者 `width:6px;cursor:col-resize;z-index:6`，hover/拖动时中间显 2→3px accent 竖条。
- **拖动机制**：`startDiv → onDivMove → endDiv` 全局 `mousemove/mouseup`；拖动中 `document.body.userSelect='none';cursor='col-resize'`，松开复位，防误选文本、防手柄被内容区遮挡。
- **自适应 + 不压缩（关键约束）**：中间区 `.hsb-main` 设 `min-width:320px` + `flex:1` 天然填剩余空间；`#portHuman` 加 `overflow:hidden` 防横向滚动条。每次 `onDivMove` 用 **clamp** 把被拖栏宽度钳在 `[min, max]`：
  - 左栏 `min=228`（rail48+panel≥180）、`max = vw − 右栏占用 − MIN_MAIN(320) − 分隔条 − 右 edge`，保证中间永 ≥320；
  - 右栏 `min=260`、`max = vw − 左栏占用 − MIN_MAIN − 分隔条×2 − 右 edge`。
  - 即任一栏拉到极限时，另一栏与中间区都不会被压到阈值以下——**既不压缩、也不因溢出而遮挡**。
- 宽度记忆：`sbW`/`rsbW` 变量承接，toggle 展开沿用上次拖到的宽度。

**验证（v21g）**：全脚本 `new Function` 语法 OK（70956 字符）；`section 3/3`、`aside 1/1`、`div 200/200` 平衡；回归 **31 断言仍 ALL PASS（exit 0）**；对 drag 函数做 DOM-stub 运行时冒烟（`DRAG_SMOKE_OK`）：左栏 +60→400、右栏收窄被钳到 min 260、大幅左拖被钳到 max 532（中间区始终 ≥320）——clamp 数学正确。

#### 6.10 左栏选中 → 右栏联动投影对应对话工作区（v21h，用户要求"点项目2对话→中央切内容、右栏显项目2文件"）

**模型改造**：
- 删全局单例 `RSB_FILES/RSB_TREE/RSB_ARTS/RSB_PLAN/RSB_ACT`，改 `CONV_WS={convId → {files,tree,arts,plan,act}}` + `EMPTY_WS`（files/tree/arts/plan/act 全空）。

**补充设计点（用户说"其他方面也需要，只是没想到"——逐个兜底）**：
1. **空态杜绝串台/遮挡**：未在 `CONV_WS` 的对话（新建的、纯聊天的）→ `EMPTY_WS` → 文件树/产物/计划/活动各自显式"该对话暂无…"，预览显"选择左侧对话后，这里显示其工作区文件"。**绝不让上一个对话的文件留屏**，这是数据层的"不遮挡"。
2. **Observer 仍独立全局**：右栏是每会话投影；顶栏 Observer 审计抽屉是跨会话中立审计，**不**随对话切换——边界不变。
3. **上下文标签条 `#rsbCtx`**：右栏头部显"工作区：项目名 › 对话标题"，让"联动"显式可见，验证用户没点错。
4. **切对话跳「代码」tab**：既然用户期待"看到它的文件"，切对话时若右栏展开自动跳到文件树 tab（保留数据刷新语义）；用户停在其它 tab 时数据也已刷新，切回即见。
5. **会话工作区隔离模型**：每会话持有**自己**的工作区快照（非共享），避免"项目1 改过的文件在项目2 也出现"的语义污染；真实环境由 AI OS 按会话落快照。

**验收口径**：① 点项目1/项目2对话→中央切内容、右栏文件树随之换成该对话的目录与文件（无残留上一对话文件）；② 上下文标签同步更新；③ 临时对话（分析类）右栏只显 md 分析件、无 rust src；④ 新建/无工作区对话右栏显空态、不串台；⑤ Observer 抽屉不随联动变化。

## 1. 根治方案（联网调研：两套业界框架，正好补齐我们缺的两层）

### 1.1 框架一：AI 事故学习系统（根治的"反馈层"）

> 直接借鉴**航空（ICAO SMS）／医疗（WHO 患者安全）／核能（IAEA）**——这三个行业把事故率降到极低，靠的不是更聪明的操作者，而是**系统性的事故学习机制**。

| 组件 | 做法 | 我们的对应缺口 |
|---|---|---|
| **事件分类学** | 统一分类，才能跨事件做模式识别 | ⚠️ 有雏形（维度字典），但未成"事故分类学" |
| **险情（near-miss）上报** | 航空安全的大幅改善**主要归功于险情上报**；险情不触发正式调查，只喂给模式分析 | ❌ **完全缺失**——我们只在你"真的撞上"时才发现 |
| **无责复盘（blameless）** | 追系统原因，不追个人；有责复盘会压制真实披露 | ⚠️ 守门人文化已接近，未制度化 |
| **五问法（Five Whys）** | Sev1/2 必须做；表层原因通常掩盖系统性治理缺口 | ❌ 缺失（我们做的是"现象归类"，不是"五问到根"） |
| **跨事件模式识别** | 不只问"这次发生了什么"，要问"**什么在反复发生**" | ⚠️ 我手工做了 11 层，未自动化 |
| **前馈到治理设计** | 学习产出要**回写**风险评估/策略/质量门禁 | ❌ 缺失（那条"大多数团队忘记的虚线"） |
| **分级由治理团队做，不由系统自己的团队做** | 避免利益冲突 | ⚠️ 与"不得自审"公理同源，未制度化 |
| **整改项跟踪到关闭（有主、有期限、验证有效）** | 未被跟踪的建议＝虚假保证 | ⚠️ v2 有待办表，但无闭环验证 |

> **CSET 对 200+ 真实 AI 事故的研究结论（对我们最有价值的一句）**：
> **危害主要来自治理、语境与"人–AI 交互"，而不是模型能力本身**；且"**human-in-the-loop 并不自动具有保护性**"。
> → **这直接印证我们的数据**：失败不是模型不够强（成功轮 2 步就能答对），而是**该不该进任务循环、判据对不对、有没有人真正复核**。

### 1.2 框架二：架构适应度函数（根治的"执行层"）——把原则变成会失败的检查

> 出自 Neal Ford《Building Evolutionary Architectures》。**架构适应度函数 = 可执行的、客观的架构特性校验，跑在 CI 里，违反就让构建失败。** 即"**architecture as code**"。

**核心链条**：`架构不变量 → 可执行规则 → 自动化测试 → CI 门禁`

| 适应度函数类型 | 我们能用的 |
|---|---|
| 结构约束（依赖方向、模块边界） | ✅ Rust：可用 `cargo-deny` + 自定义测试（如"agent-core 不得依赖 codex-cli"） |
| 性能阈值 | ✅ 步数、每步成本、压缩次数（我们有基线数据） |
| 安全属性 | ✅ 密钥扫描（#0 的教训）、路径越界 |
| 复杂度/规模 | ✅ 常量体检可做成"常量必须有来源注释"的检查 |
| API 契约 | ✅ 结构化完成报告 schema |

**几条对我们特别重要的最佳实践**：
1. **先识别架构不变量，再写测试**（不是先写测试再补规则）
2. **存量违规先建基线，只阻断新增违规**（避免一上来全红）← **对 Hearth 的 415 测试 + 遗留常量尤其关键**
3. **测试本身也要被测试**（"test the architecture tests themselves"）← **又一次"不得自审"**
4. **同一套规则同时约束人工代码与 AI 生成代码**
5. **值得自动化的判据**：**重要 + 可客观检验 + 相对稳定 + 违反代价高**——四条全中才做
6. **"Agent 不会吸收隐性知识——没被告知分层规则的 agent 会毫不犹豫地越界"** ← **这正是 RC27（PATH 同名碰撞）与 RC39（输入分类）的成因**

### 1.3 我们的根治模型（三层）

```
原则层（宪法/公理）      ← 不可协商，少量
   ↓  翻译成
执行层（适应度函数/CI）   ← 可执行、会失败、有基线
   ↓  由
反馈层（事故学习系统）    ← 分类学 + 险情上报 + 五问 + 模式识别 + 前馈回写原则层
```

**三层互为闭环**：反馈层发现的模式 → 上升为原则层公理 → 翻译成执行层函数 → 违反即阻断。

## 2. 根因树（把今晚 17 条 RC 收敛到 5 条根）

| 根 | 一句话 | 覆盖的 RC | 治理层处置 |
|---|---|---|---|
| **R-α 意图层缺失** | 没有"这是什么"的判断层 | RC39（总开关）→ RC36、RC33、RC43 的暴露面（65% 轮次误入任务循环） | 原则层：**先分类再行动**；执行层：α 的判据做成适应度函数 |
| **R-β 语义层错位** | 信号的意思不对 | RC43（progress）、RC40（fill_pct）、RC5（摘要语义）、RC34（渲染语义） | 原则层：**信号必须忠实于它声称的含义**；执行层：每个语义字段一条可失败断言 |
| **R-γ 自审** | 系统对自身产出做终局判定 | RC1（已修）/ RC10 / RC21 / RC37 ＋ 测试悖论（R2-C 3/6） | **D10 公理**：任何系统不得对自身产出做终局判定 |
| **R-δ 常量标定失效** | 阈值按已消失的环境设定 | 压缩 32k（512K 的 4–10%）、**子 agent 4096（0.8%）**、5 处静默截断、Agnes 512K 不在能力表 | 常量体检（W13）+ **"常量必须声明标定依据与日期"** 的适应度函数 |
| **R-ε 边界/环境层** | 沙箱与能力边界 | RC24-B（已修待验）、seccomp SENDTO、RC25/27 | 既有 W7 + 复测 |

> **关键判断**：**R-α 与 R-δ 是"根"，其余多为"征"。**
> 修 R-α → 65% 的轮次不再误入任务循环；修 R-δ → 压缩从 14–18 次/会话降到 1–2 次，失忆类症状可能大幅自愈。
> **这两条都是低成本，且都可能在不动架构的前提下产生量级改善。**

### 输入 ② 架构原则：任何系统不得对自身产出做终局判定（D10）

- 已隐含践行于 RC1 的修复（verify 事实校验驱动）

- → 意图路由应先于推理深度优化；建议引入 **正确弃权率** 指标

## 6. 风险与边界

1. **R-δ 的因果尚未证实**：常量过期与失忆是**强相关**，非已证因果。W13 应先做 **A/B 复测**（改阈值前后各跑同一长会话，比较压缩次数与失忆表现）再决定是否全量。
2. **子 agent 4096 是否真被用于截断上下文**，未验证（可能只是能力声明未被消费）——**这是 W13 的第一个待查项**。
3. **适应度函数的误报成本**：规则过宽会拒绝合理实现。建议按业界做法——**先建基线、只阻断新增、定期复审规则**。
4. **业界数值（阈值、检出率）来自各来源自述**，应作参考区间而非普适定律。
5. **移动基线**：执行窗口持续施工（本轮期间新落 P1-TASK-TRUTH-01 等）。**提交蓝图评审前先 `git log -1` 对齐**，且注意 P1-TASK-TRUTH-01 与本包"不得自审"原则同向——**两窗独立得出同一结论，可互为佐证**。

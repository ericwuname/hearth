## 〇、一句话

> **Hearth 不是"不够聪明"，而是"它说了不算"——判断权被下沉到了计数器和词表。**

> **根因 = 框架编排范式（六相状态机）；在此之下有 8 类共 21 个具体问题，分属三种性质，必须分别下药：**

> | 性质 | 类别 | 换强模型能治？ | 归还判定权能治？ |
> |---|---|---|---|
> | **说了不算** | A 决策权 · B 判定终止 · C 意图理解 | ❌ | ✅ |
> | **根本看不到** | D 信息丢弃 · G 工具缺口 | ❌ | ❌ |
> | **测不出来** | H 验证体系 | ❌ | ❌ |

>
> **其中"根本看不到"和"测不出来"两类，与判定权无关——这是本轮新增的核心认知。**

### 这一刀为什么致命

**真正的根治是减法，Hearth 的"根治"是加法。**

按本文处方，真正的根治**应该删掉**：

| 应删 | 量级 |
|---|---|
| 140 个硬编码词表 + 9 处引用分支 | −数百行 |
| TaskGraph / planner 独立 LLM 分解 | −数百行 |
| 六相调度与四个 `do_*` 相位 | −数百行 |
| T4 停滞检测（hash 比对 + 强制 GiveUp） | −数十行 |
| give_up 三条出口及其计数体系 | −数十行 |
| r5-11（R-4 落地后不再需要） | −数十行 |

**而实际是 +954 行。**

### 于是得到一个可量化的判据

> **`loop.rs` 的行数，就是"框架替模型做了多少判断"的度量。**

它之所以有 12,165 行，是因为**把本该由模型承担的语义判断，全写成了 Rust 代码**。每发现一处"模型该判断而框架判错了"，就加一批代码——**这个文件是被"替模型做决定"这件事喂大的**。

Claude Code 不需要这么大的编排文件，因为**它把判断留给了模型，本地代码只干"把循环跑稳"的脏活**。

### 因此，给出一条**可 CI 断言的根治判据**（此前所有判据中最硬的一条）

| 判据 | 内容 |
|---|---|
| **★ 根治判据** | **任一"根治"工作包落地后，`loop.rs` 行数必须净减少。增加即判定为"补丁"而非"根治"。** |
| 建议阈值 | R6 及以后：每包 **净减 ≥ 200 行**；累计目标 **< 9,000 行** |
| 为什么硬 | 它不可辩解、不可美化、一行命令即可验证：`wc -l crates/agent-core/src/loop.rs` |

> 砺曾警告「警惕给栅栏打补丁的自我强化循环」，并给出定性判据「若后续工作包主体仍是新增检测/闸门，应触发止损评审」。
> **本条把该判据量化了**：**看行数，不看说明。**

### 顺带回答"为什么改了这么多还是不好用"

**因为每一轮"修复"都在增加系统的判断规则，而问题恰恰是"判断规则太多、且不该由规则来做"。**

修复 → 规则变多 → 边界变多 → 出现新误判 → 再修复 → 规则更多……

**R5 的 12 项在各自范围内都是正确工程**，但叠加的净效果是：**给一个"因为规则太多而不好用"的系统，又加了 954 行规则。**

## 一、问题全景（21 条，按类别）

**严重度**：🔴 阻塞生产 ｜ 🟠 显著影响 ｜ 🟡 待优化 ｜ ✅ 已修/部分修

### A 类 · 决策权（根因层，2 条）

| # | 问题 | 证据 | 度 |
|---|---|---|---|
| **A1** | **框架编排范式**：把「模型自主循环+工具」做成「框架编排流程+模型填空」。六相每相一次 LLM 调用 | `LoopPhase` `loop.rs:29-37`；主循环顺序 `do_plan(:5101)→do_act(:5115)→do_observe(:5129)→do_reflect(:5143)` | 🔴 |
| **A2** | **判定权在框架不在模型**：何时继续/重规划/放弃/完成，全部由框架规则定 | 见 B1–B3 | 🔴 |

**A1 的权威对照**（Claude Code 官方文档原文）：
> 「**智能尽量下沉给模型，编排层只负责把循环跑稳**」——编排层只干上下文治理、预算、压缩、恢复、工具回填、错误处理；「**不去替模型做过多任务规划，而是把 loop 设计成一个稳定容器，让模型自己在里面持续决策**」

Claude Code 的 TAOR 是**逻辑四步、物理上一轮一次模型调用**；Hearth 做成**物理上四次独立调用**——这是"一句问答烧 5 次 LLM 调用"的根源。

### B 类 · 判定与终止（4 条）

| # | 问题 | 证据 | 度 |
|---|---|---|---|
| **B1** | **give_up 三条出口全是计数器，无一经过模型**：①`noprogress>=2 或 consecutive_errors>=3` ②连续 2 次 TaskGraph hash 相同**强制** GiveUp ③budget 耗尽 | `:4927` 注释明写条件；`:3084-3085`「强制 GiveUp」；`:5368` | 🔴 |
| **B2** | **框架自擒（self-trap）**：框架强迫每轮重规划 → 上下文无新事实 → 必然产出相同 TaskGraph → 因"重复"被强制 GiveUp | `:3084` + C 语料 L1155/L1732 实证（同一 `steps=4` 草案连出 3 次、间隔 50s 后失败） | 🔴 |
| **B4** | **★ 同名异构：六相的 `Observe` 与 1,075 行的 `observer` crate 互不相通** —— 观察能力被架构性地移出内核，内核保留了一个无法履职的相位 | `observer` crate 存在（`Cargo.toml:28/84` 注册，"Observer OS——第三权·零执行权"）；**但 `agent-core/Cargo.toml` 不依赖它、内核源码零引用**；仅 `agent-runtime`/`codex-cli`/`service` 外层依赖 | 🔴 |

**B4 详解**：项目有完整的观察系统（1,075 行，消费事件流、产出 Finding/熔断），按"独立 crate 铁律"**内核不得 import**。于是——

```
内核：LoopPhase::Observe 相位（挂着"观察"的名字，但看不到 Observer OS）→ 0ms 空转
外层：observer crate（1,075 行，真正做观察）→ 主循环用不到
```

**这比"dead code"深一层**：不只是 `let _has_error` 被丢弃，而是**整个观察职能被架构性地移出了主循环，内核留下一个无法履行职能的空壳相位**。这也解释了为什么 R1-3 给 Observe 补了判定逻辑之后，它仍然只是"本地轻量判定"——**因为真正的观察在另一个 crate 里，主循环拿不到**。

> **顺带再次证伪引擎自陈**：C 语料 L1155 引擎称"搜了整个 crates/ 目录，没有 observer 任何痕迹，**这个功能从未实现**"——**实际上有 1,075 行且已在 workspace 注册**。引擎自述必须回查源码（见 §四.3）。

| **B3** | 完成判定 keyed to 写盘（r5-11 部分修） | **r5-11 源码**：判据由 `pending_results.is_empty()` → `written_files.is_empty()`，**判定主体仍是框架**；**疗效上限 = 意图分类准确率 ≈ 71%** | 🟠 |

**B1/B2 的官方自证**（`loop.rs:4903-4911` 原文）：
> 「事实层显示有真实进展（写盘产物存在 + 零错误），**Reflect 却判 give_up** → 记录冲突」
> 「不做新 Event 变体、不改终态、不 force continue……**决策权问题另立研究**」

**团队已发现"有进展却被判放弃"，因"决策权问题另立研究"只记录、未改控制流。** 这是根因的官方确认。

**H1/H2 是"门禁 524/0 而真机 8%"这个落差的物证与解释**：

```rust
// 测试的构造方式（示意）
let llm = MockLlm::new(vec![
    resp("DONE", vec![]),        // 第 1 次调用返回这个

]);
// 断言：框架应该走分支 X
```

**它验证的是"如果模型恰好按我预设的顺序说这些话，框架会走分支 X"——而不是"真实 LLM 下任务能不能成"。**

**比喻**：这像驾校只考"教练按剧本念指令时学员怎么做"，全员满分；一上真实马路就撞车。**考的是剧本执行力，不是驾驶能力。**

**三个直接后果**：
1. **测试无法发现"模型层 vs 框架层"的分歧**——因为模型被 mock 掉了。我与砺的分歧在现有测试体系下**根本无法判别**，只能靠真机判别实验。
2. **R5 的"验收通过"不等于"真机变好"**——验收跑的是门禁（mock），不是真机。这也正是 R5 验收报告必须留白「R5-1/3 真机计数归 R4.2」的原因。
3. **测试越全，越危险**：524 个测试会制造"系统是对的"的错觉，而它从未验证过真实对话。

## 二、解决方案（逐条对症）

> **总原则**：判断还给模型，框架只留三类护栏——**预算 / 安全 / 不可恢复错误**。

### 2.1 主表

### 2.2 R-1 详解（最先该做，成本最低、解开三个死结）

**现状**（`loop.rs:4901`）：
```rust
ReflectVerdict::GiveUp => { /* 终止，run() reports ok=false */ }
```

**改为**：
```rust
ReflectVerdict::GiveUp => {
    // 不终止。把事实注入上下文，让模型自己决定如何收尾：
    // "你已连续 N 次在 <tool> 上失败；错误类型 <error_kind>；
    //  已尝试：<commands>；当前产物：<files>。
    //  请判断：换一种做法 / 向用户说明你卡在哪、为什么、建议怎么办。"
    inject_failure_summary_to_messages(...);
    continue;   // 回到模型，由它 end_turn 或继续
}
```

**一改解三结**：①框架自擒断裂 ②假失败消失 ③终止有了面向用户的解释。

### 2.3 R-6 目标形态（真正的手术，决定天花板）

```rust
loop {
    resp = llm.chat(messages, tools);          // 一次调用：模型自己规划+决定调什么工具
    messages.push(resp);
    if resp.tool_calls.is_empty() { break }    // 模型说完了 → 结束（R-4）
    results = exec_all(resp.tool_calls);       // 可并行
    messages.push(tool_results_as_user_message(results));   // R-3 直接回灌
    if budget_exhausted { break }              // 唯一框架护栏
}
```

**收益**：调用次数降 ≥50%；**"规划草案重复"自然消失**（规划成为模型思维链的一部分，不再有"重新规划"这个动作）；**R-7 成为自然结果**（不需要提前分流，也就不需要意图分类器）。

### 2.4 关于「不允许 give_up 吗」的正解

> **允许"做不到"，不允许"框架替模型宣布做不到"。**

| | 现状 ❌ | 应为 ✅ |
|---|---|---|
| 谁决定停 | 框架数数 | **模型说"我说完了"** |
| 做不到时 | `Task failed` | **模型自然语言**："我卡在 X，试过 A/B/C，因为 Y 不行，建议 Z" |
| 用户拿到 | 一个状态 | **信息 + 下一步** |

**比喻**：现在的 give_up 像**只看体温计开药方的医生**——39 度就宣布"治不了了"，既没问病人、也不说为什么和下一步。正确的是医生（模型）自己判断并**向家属解释病情与方案**。

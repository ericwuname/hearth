## 二、事实裁决（含一处对内部结论的更正）

### 2.1 C-1 冲突裁决：外部窗口正确，砺需更正

- **砺 Phase D 评审锚点 #14 称"do_reflect 零模型调用"——错误**。实际：`do_reflect` 在非跳过条件下调用 `planner.reflect`（loop.rs:4279）；`planner.reflect` 内规则快路径（连续错误≥3 等先判，lib.rs:479 注释"fast path, no LLM call"）不命中才走 LLM 慢路径。
- 砺误判原因：手工测试现场的 reflect 输出全是规则计数（快路径场景），误推为全路径无 LLM。
- **精确表述（修正后）**：每周期**最多 2 次**模型调用（Plan + Reflect 慢路径）；T5 优化下纯问答无工具结果时 Reflect 跳过 LLM。
- **对 L6/U-06 的影响**：**不推翻机制侧结论**——Act 批量盲跑（capture:None）、中间结果不可见、裁决信号不含"是否已回答用户"（planner/lib.rs:554-597）全部仍是事实。修正的是叙事：不是"模型全程冻结"，而是**"模型在裁决席上，但喂给它的是一份只统计写盘的报告"**。U-06 维持有条件升格不变。
- **砺行动项**：更正 Phase D 评审 #14 相关表述，同步 W1 设计小样引用口径。

### 2.2 三层死锁：成立，且是迄今最精确的根因模型

目标路由层（疑问句/继续→不改目标）× 产物判定层（不确定→默认产物）× 完成判定层（节点永不 Completed → all_done 恒 false → 问答逃生通道永不触发）——三锚点全中，A 组 10/10 回代命中，同时解释假阴性（8 失败）与假阳性（B2/B4 假完成）。**同一个 `write_attempted` 判据的两面。**

### 2.3 497:0：成立，且是必须立刻认账的工程缺陷

497 个测试无一条断言"用户可感知行为"。**80% 失败率存活 10 个版本无一次红灯**的直接原因。这不是外部抹黑，是本流程的激励结构产出（批判报告 §7.3 说对了）。

## 三、三份报告的关系与顶层综合裁决

### 3.1 分歧的本质

| 报告 | 结论 | 分歧点 |
|---|---|---|
| 终审报告 | 值得继续，W1 唯一主线，G-W1 门禁 ≥70% | 根因已定位 + 竞品已验证目标架构 + 引擎层资产可复用 |
| 批判报告 | 停止自研，转 Extend | 存在性（护城河=竞品标配）+ 自噬不可修 + 单位经济学不成立 |
| 深挖报告 | （中立取证）三层死锁 + 三个精确断点 B1/B2/B3 + 配套信号 | **给出了比 W1 大改造便宜得多的最小验证路径** |

三者共享同一事实基座。批判与继续之争**不在事实，在期望值**：修复成功率 × 修好后的差异化价值。

### 3.2 顶层综合：打"决胜局"，不搞情怀对赌

批判报告 §13 留了可证伪出口：**"两周内 A 组失败率 8/10 → ≤2/10（出可运行二进制并复测），则本报告撤回主要结论"**。而深挖报告恰好提供了最便宜的应战武器：

> **B3（完成铆钉：主执行路径可标记节点 Completed）+ 配套信号（reflect 观察报告增补"本轮是否已向用户输出文字回答"）**——两处低风险修改，直接命中 A3/A6/A10 型"答得好却判失败"，深挖报告预估可把 ✗ failed 从 8 砍到 ≤3（G-1 门禁）。

**顶层裁定**：
1. **立即排期"决胜局"**：段 2 解锁（Node 15 双签）后，第一批施工 = ①G-0 黄金集回归测试固化（先把 A 组 10 条"当前必须失败"的断言写进测试——补 497:0 的洞，且是"测试必须能失败"的正例）→ ②B3 + 配套信号 → ③G-1 复测（同盲测包全新 session）；
2. **G-1 判据**：✗ failed ≤3 且 A3/A6/A10 全部转 ✓ → 继续段 2/W1 主线；**不达标 → 触发止损评审，按批判报告 §12 路径转 Extend**，不再辩论；
3. **G-W1 终局门禁维持**（W1 完成后实质任务成功率 ≥70%，零终态背离）；
4. **过程门禁采纳**：每工作包后 A 组失败数必须单调下降，不降反升即回退复盘。

**这个方案对双方都公平**：批判报告若对，G-1 会用数据说话；深挖报告若对，两周内见分晓。**唯一被禁止的选项是"既不验证也不止损地继续写文档"。**

## 四、呈用户拍板项（战略层，顶层不代拍）

**批判报告的存在性论证（护城河=Codex CLI 标配、定位=Goose 主场、MCP/SKILL.md 零支持、Extend 优于 Build）在"做通用产品"的前提下是成立的。但存在一个前提问题需要你回答**：

> **Hearth 对你到底是什么？**
>
> - **A. 产品**——要做成人人可用的通用 coding agent → 批判报告的存在性论证基本成立，Extend 路径（Goose/Codex CLI 底座 + 你的技能库/宪法治理做上层）期望值显著更高；
> - **B. 认知实验 + 自用工具**——三层模型/判断层/宪法治理是你的真实研究主线，通用产品化本就不是目标 → 存在性论证力度大减（它批判的是"通用 harness 市场"，不批判"自用认知实验"），决胜局照打，但止损线可以更宽松；
> - **C. 决胜局见分晓**——不定性，先用 §3.2 的两周门禁拿数据，再回到 A/B 选择。

顶层建议 **C**（与 §3.2 裁决一致）：无论最终 A 还是 B，G-0/B3/G-1 都是净收益（补测试洞 + 修最便宜的根因 + 拿到决策数据），成本几天级。

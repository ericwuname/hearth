## 1. 背景与目标

- **问题**：Hearth（codex-rust，v0.2.22，27 crates / ~43,723 行）功能与安全矩阵均达标，但用户体感"不如 Codex、Claude Code、WorkBuddy 好用"。手工测试日志（v0.2.20/v0.2.23）反复出现"报错就 give_up 而不是重新思考新方案"、"✓ Done 不知做了什么"。
- **价值判断**：不好用，架构再优秀也白搭。因此本轮工作目标只有一个——**把"我觉得不好用"变成"可复现、可计数、可对照竞品"的证据链，并定位结构性根因**。
- **方法约束**：头脑风暴发散候选（求全）→ 矛盾论收敛（抓主要矛盾）→ 逐项源码取证（判定 ✅/❌/🔶）。全程只读取证，未改 `crates/` 任何代码。

## 2. 主要矛盾定性（矛盾论结论）

**主要矛盾**：Hearth 的「控制导向架构」（为安全/可观测而约束模型）↔ 用户对「流畅自主助手」的期待。

- **特殊性**：竞品都在这对矛盾里取舍，但把矛盾推到「护栏端」（流畅为主、越界才拦）；Hearth 把它硬推到控制端（Plan/Act/Observe/Reflect 全同步闸门 + prompt 敕令 + 默认每步审批）→ **频谱离群点**，"不好用"是结构性位置，不是偶然 bug 群。
- **同一性**：安全与流畅不互斥（竞品已证；Hearth 自己的潜意识层也证了，见 §5.9）→ 矛盾可调和，是"取舍配置错了"，非"不可能"。
- **主要方面在 Hearth 侧**：用户期待由市场锚定（固定），可改的是 Hearth 的契约配置。
- **推论**：修 L1–L4 的散点而不动 L0/L6，体感仍差；把栅栏降级为护栏后，L1–L4 大部分自然消解（react 循环里"答案即交付/同轮重试/可读 diff"本就是默认行为）。

## 4. 核心发现详述（按杠杆排序）

### 4.1 L6/L0 反应回路缺位——主矛盾的核心表现（最高杠杆）

- **`provider.chat` 在 loop 内唯一出口 = `do_plan`**（loop.rs:3237 注释原文"本函数是 loop 内唯一 provider.chat 出口，全部 LLM 请求必经"；全文 grep 仅 3159 do_plan 与 1324 restore_history 两处 chat）。
- `do_act`(3413) / `do_observe`(3867) / `do_reflect`(4112) **均不调用模型**。`do_reflect` 经全文核验为规则式遥测记账（错误计数/失败分类/进度跟踪）——**"六相"里模型实际只参与 1 相**，Reflect 相模型根本不在场"反思"。
- `do_act` 批量执行：`len>1` 走 `execute_plan`（3612，顺序、`condition:Always`、不读上步结果），否则 `execute_tool_calls`（3666 → dispatcher.rs:340 `join_all` 并行）。loop 构建 TaskStep 时 `capture:None`（3624）——orchestrator 本有的 `{{key}}` 跨步变量替换（orchestrator.rs:147-167）**完全没接上**，依赖型两步（read→edit）在批量里拿不到前步输出。
- **结论**：模型每周期被打一次 → 提交整批 → 盲跑 → 下轮才重估。与竞品 react-interleaved（每个工具结果后立即回模型）**结构性相反**。这是架构事实，非调参可解。

### 4.2 L0.5 盲反馈——比 L0 更隐蔽，"即使 react 也白搭"的那一环

`record_tool_exchange`（loop.rs:2512）把工具输出经 `truncate_tool_output`（loop.rs:5278）入历史：阈值 MAX 6000 / HEAD 4000 / TAIL 1500——超长输出**中间整段被砍**。编译错误、长测试输出等关键信息恰在中段。模型下一轮 Plan 基于**残缺反馈**决策：盲规划叠加盲反馈。

### 4.3 L0.6/L5 上下文经济与 prompt 敕令

- `build_messages`（loop.rs:2195）每周期重建：全量历史 + ~800 词静态 product 提示 + 规则式 `maybe_compact`（2198，"不调 LLM，不阻塞"）。后果：payload 重 → 更早撞预算；长跑后工作记忆被规则折叠降质。
- product 提示**逐字硬编码**（2213-2272）："ONLY uses tool_calls (NEVER text)"(2214)、6 步刚性工作流(2217-2230)、IDENTIFIER CONTRACT(2232-2236)、"MUST end by calling write_file"(2254)、CARGO NOTES(2256-2258)。控制靠字面敕令而非架构双模 → 是 L1/L4 的直接指令源，也是 L0.6 的 token 浪费源。

### 4.4 L1/L1.5 完成契约——主要矛盾在"入口"处的显影

- 完成契约开关 = `goal_requires_product`（loop.rs:167）：小写化 → 剥离 6 负向短语 → 匹配 34 产物动词。**纯关键词，无语义理解**。
- 误路由实例推演："优化这个函数"不含 34 词 → 误判 QA（本该写代码）；"写下你的结论"含"写" → 误判 product 被逼写文件。误判负担全压在用户措辞上。

### 4.5 L2 失败恢复族

- **L2.5（默认开启的断崖）**：`run_local.rs:332-339`——`--approve-within session`→自动放行；否则 stdin 非 tty（管道/CI/agent-to-agent）→ **默认 DenyAllNonInteractive** → 首条需审批 bash/edit 即 abort（loop.rs:3485-3534）；交互模式无 flag → 逐工具弹审批打断流畅。
- **L2.6（replan 反噬）**：主驱动每周期 inc_step（5007）+ forcing-replan 内再 inc_step（3373/3403）→ replan 周期步数 ×2，与 L0 互为放大器。
- **L2.7（恢复覆盖面，🔶 待真机）**：FA01 旁路(4812)、Verification Reserve(5062-5090)、T4 停滞恢复**全部 keyed to `acceptance_criteria` 存在**——开放式无 criteria 任务（"把它改好"类多数）落不到任何恢复护栏 → 纯 give_up。

### 4.6 L3 透明族

事件流（session.rs:1002-1074）无文件 diff 事件（L3.5）；Done 报告仅 ok/status/goal/elapsed/steps，无"我试了 X、被 Y 卡住、你该怎么做"接手叙事（L3.6）。另有 L3.7 中文 panic（patch.rs:127/135/145 字节切片）、L3.8 误判告警（loop.rs:683）。

### 4.7 F1 战略矛盾（🔶 需真机定级）

用户战略是"弱 LLM 下也交付高质量"；但 plan-execute-gated 恰恰**最依赖强模型的盲规划能力**。且 product 提示明文把预算/上下文自管甩给模型（2248-2250："Call introspect() … proactively summarize old steps … instead of hitting the budget"）——弱模型不会主动调 → 撞墙即 give_up。放大系数需 Phase D 弱模型实跑测量。

### 4.8 两项反向结论（同样是本轮产出）

- **F2 纠正（转好）**：此前"生产续跑未证"是误判。CLI `hearth resume <id> [goal]`（codex-cli/src/lib.rs:644）已接 `restore_history`(680)+`restore_taskgoal`(702)，并对 crash 落两次写盘间的 `state_revision` mismatch 有恢复路径(687-700)。**生产续跑已实现**，仅剩 Phase D 验证收敛性。
- **L7 排除（护栏范式已存在）**：潜意识层 `ConstitutionGuard` 仅对 3 条硬编码危险命令 Abandon（subconscious/src/lib.rs:66-77）；CostGuard/RepetitionDetector 仅发 Simplify，而 Simplify 在 loop.rs:3054-3057 仅记 warning、执行继续。**潜意识层是正确实现的护栏**——证明"护栏而非栅栏"的范式在 Hearth 内部已有实例，W1 的改造方向不是空想，可照搬其实现哲学。

## 6. 工作包提案（W1–W7，问题描述级——实现细节由执行窗口定）

> 排序原则：（体感影响）×（是否主要矛盾直接表现）。每个包给：目标 / 范围（锚点）/ 验收标准 / 风险。**不含 patch**。

### W1 反应回路改造（最高杠杆，架构级）
- **目标**：把"每周期 1 次模型调用 + 整批盲跑"改造为"每个工具结果后模型可重新入场"（react-interleaved），同时把六相闸门语义降级为护栏（预算/安全/审批检查保留，节奏控制放开）。
- **范围锚点**：loop.rs:3237（单点 chat 出口）、3413-3668（do_act 批量执行）、3612-3626（capture:None）、4112-4242（do_reflect 遥测化）；可参照 subconscious 层的护栏实现哲学。
- **验收标准**：① read→edit 依赖型任务在单轮内正确传递结果（现 capture:None 下必失败）；② 模型能在工具失败后**同一周期内**换方案重试（现需等下周期或 replan）；③ 步数/预算/安全护栏语义不弱化（既有 484 条测试全绿 + 新增行为测试）。
- **风险**：架构级改动，触及六相状态机语义与既有测试基线 → **需用户拍板**；建议执行窗口先出设计小样（不动主线，feature 分支 + 对照测试）。

### W2 工具结果回灌保真（低风险，高收益）
- **目标**：消除 L0.5 中段截断。超长输出改为：错误行/关键行结构化保留 + 全量落盘给路径引用，替代"HEAD+TAIL 砍中段"。
- **范围锚点**：loop.rs:5278（truncate_tool_output）、2512（record_tool_exchange）。
- **验收标准**：8000 字符编译错误回灌后，模型可见错误行完整；历史体积有上限（防 L0.6 恶化）。

### W3 提示敕令降级 + 契约路由升级（中风险）
- **目标**：① ~800 词静态 product 提示改为任务自适应（对话/分析任务不再被 "NEVER text"/"MUST write_file" 逼成工具人格）；② `goal_requires_product`（loop.rs:167）关键词分类器升级为更鲁棒的路由（语义辅助或双通道确认，允许模型自证任务类型）。
- **范围锚点**：loop.rs:2213-2272（提示全文）、167（分类器）、3291/3366（强制注入）。
- **验收标准**："用一段话解释 X 的风险"不再触发写文件强制；"优化这个函数"不再误判 QA；L1.5 误路由用例表全绿。

### W4 审批默认策略分级（中风险，安全语义变更 → **需用户拍板**）
- **目标**：非 tty 默认不再"首条即 abort"。建议分级：命令表级破坏性操作 + 审计放行（复用 DelegateSession 已有机制），硬红线（fork bomb/设备/内核）仍拦。
- **范围锚点**：run_local.rs:332-339（默认注入）、loop.rs:3485-3534（DenyAllNonInteractive 终止）、3457-3480（DelegateSession 已有放行+审计机制）。

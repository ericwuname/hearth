## 1. 任务清单（分两轮交付）

### R1 — 无障碍量化（可静态 / DOM 桩验证，优先做）

**R1-① 键盘导航完整走查**
- 枚举所有可交互控件（顶栏按钮、🌓主题、OS 切换器、左栏会话项、右栏 tab/文件行、中央消息操作按钮、两个分屏拖拽手柄 `#hsbDiv`/`#rsbDiv`、设置/供应商弹窗内控件），确认 **Tab 全可达** 且 **焦点顺序符合视觉/阅读顺序**。
- 确认 OS 切换器既有快捷键（`Tab` / `1` / `2` / `3` / `Esc`）行为不受影响（任务书 #01 ② 已加 `:focus-visible`，本项补"顺序 + 全可达"）。
- **接受标准（regress 断言）**：
  - 抽 DOM 桩枚举可聚焦元素，数量 ≥ 阈值且**必含** `#hsbDiv`、`#rsbDiv` 两个拖拽手柄（证明分屏器键盘可达）；
  - `:focus-visible` 规则仍在源码（继承 #01 ② 断言）；
  - `[自检]`：构造"某控件 `tabindex=-1` 或漏 `:focus-visible`"的旧写法，断言能抓出。

**R1-② WCAG 2.1 AA 对比度量化**
- 用 `:root`（浅色）与 `[data-theme="dark"]`（暗色）的 CSS 变量**实算**"前景/背景色对"对比度矩阵，公式 `CR=(L1+0.05)/(L2+0.05)`（sRGB→相对亮度）。
- 阈值：正常文本 **≥ 4.5:1**、大文本/图标/禁用态 **≥ 3:1**（WCAG 2.1 AA）。
- 任何不达标对在报告列出，并**只调 CSS 变量值**修正（不得改 DOM 锚点 / 删断言 / 引后端）。
- **接受标准（regress 断言）**：
  - 在 regress 内实现 `contrast(hex1,hex2)` 函数，对关键对断言达标：`--tx/--bg`、`--mut/--bg`、`--accent/--bg`、暗色同组（`--tx/--bg-dark` 等）；
  - `[自检]`：构造一对故意不达标的旧写法样例（如深字压深底），断言 FAIL —— 证明量化能抓出问题，非空转 PASS。
  - 注：纯 CSS 变量级对比度可在桩环境算；若涉及半透明 `rgba` 叠底，按叠后合成色折算，报告中注明算法。

### R2 — 真实渲染验证（需浏览器 / 手动，后置）

**R2-③ 跨浏览器实测**
- Chrome / Edge / Firefox / Safari 各开原型，核对：三栏布局 + 拖拽、暗色主题切换、左栏→右栏联动、文件↔消息双向联动、折叠/展开一致。
- **接受标准**：静态断言（变量 / 媒体查询 / 主题切换逻辑存在，继承 90）+ **手动核对清单**；无浏览器环境时该项标 `INCONCL` 单列，**不得与 PASS 混写**（守门员铁律：INCONCL 单列不混 SAFE）。

**R2-④ 响应式断点**
- 定义断点（建议：`≤768px` 右栏默认收起、`≤480px` 三栏转上下堆叠且对话区优先），加 `@media` 规则；移动端不得破坏 `min-main320` 与分屏拖拽可用性。
- **接受标准（regress 断言）**：抽 `@media` 规则含约定断点值（如 `max-width:768px` / `480px`）；`[自检]`：构造"无 `@media` 断点"旧写法，断言能抓出。手动 DevTools / 真机核对清单附报告。

## 一、病灶

`crates/tools-builtin/src/lib.rs` 的家目录放行逻辑，**立项理由写在注释里**：

```rust
// R3 (v0.1.3 B5): 家目录内也放行（landlock 兜底只读，越权写会被拦）。
// Err(_) => &path_str, // home 内：保留绝对路径（landlock 兜底）
```

即：**"工具层放行家目录没关系，landlock 会把越权写拦下来。"**

**但这个理由只在 Linux 成立**：landlock 是 Linux 专有机制；Windows / macOS 走 `NoopSandbox`
（README 自己打印 `⚠️ sandbox: noop · 仅开发模式，无真实隔离`）——**兜底是空的**。

**后果**：在无兜底的平台上，"放行家目录" = **真的能写家目录**。
可写点包括 `~/.ssh/authorized_keys`（持久化后门）、shell 启动脚本等。

## 二、为什么这是"条件性"真洞（**亲验事实**）

原审计代理只报了"可疑"。复核时钉了一个决定性事实：

| 环境 | `HOME` | 家目录分支 | 后果 |
|---|---|---|---|
| **原生 Windows（实测本机）** | **空** | **空转** | ✅ 不显现（cwd 外写入仍被拒） |
| **Git Bash 启动的 Windows** | Git for Windows **会设置** | **生效** | ⚠️ **洞出现** |
| Linux | 有值 | 生效 | ✅ 有 landlock 兜底，安全 |

> 实测：本机 `HOME=[]`、`USERPROFILE=[C:\Users\87465]` → 原生 Windows 上该分支不动。
> **但从 Git Bash 启动时分支即生效** —— 而本机确实装着 Git Bash。
> 故这不是"理论风险"，是**取决于启动方式的条件性真洞**。

## 三、修复

新增 `home_allowance_backed_by_sandbox()`（`cfg!(target_os = "linux")`），
并把判定拆成两条路径：

| 判定 | 用于 | 家目录 |
|---|---|---|
| `is_allowed_absolute_roots` | **读**（`read` / `grep`） | 保持原样放行（R3 的立项场景就是"读 ~/xxx 被误拒"） |
| **`is_allowed_absolute_roots_for_write`** | **写**（`write_file` / `apply_patch`） | **仅在 `home_allowance_backed_by_sandbox()` 为真时放行** |

**这不是新增策略，而是让代码对自己说过的话负责**——注释写着"越权写会被拦"，
修复后它在所有平台上都成立（要么由工具层拦，要么由 landlock 拦）。

**显式白名单（`HEARTH_READ_ROOTS`）不受影响**：那是用户显式收敛，两种取值都生效。

**回归测试** `test_home_allowance_gated_by_real_sandbox`（5 组断言，含平台门控断言）；
`tools-builtin` 单测 82 → **83 passed**。

## 四、已知行为变化（**如实登记**）

- **非 Linux + `HOME` 有值**（典型：Git Bash 启动的 Windows）：
  `write_file` / `apply_patch` **不再允许写 cwd 之外的家目录路径**。
- **Linux**：**零变化**（兜底判定为真，放行逻辑与修复前一致）。
- **原生 Windows**：**零变化**（`HOME` 为空，分支本就空转）。

> 这是**收紧**，不是放宽。若某 Windows 工作流确实依赖"写家目录"，属于应显式授权的例外，
> 可用 `HEARTH_READ_ROOTS` 显式列白名单——**显式优于隐式**。

## 六、本次复核对方法论的再次加强

**"同一条注释，在不同平台上可能是真的，也可能是假的。"**

本轮四张卡连着抓到同一族缺陷（P0-01 路径逃逸、P0-02 选项注入、本条兜底缺失），
**共同点都是"代码假设了一个平台语义，而该语义在别的平台上不成立"**：

| 假设 | 在 Windows 上 |
|---|---|
| `Path::is_absolute()` 能识别绝对路径 | ❌ 有根无前缀的路径判为 false |
| 参数前无需 `--`，用户输入不会被当选项 | ❌ 同样成立（跨平台，非 Windows 专有） |
| landlock 会兜底越权写 | ❌ 无 landlock |

**建议（未实施）**：把"平台假设"作为一类专项——**凡注释里出现"由 X 兜底/由 Y 保证"，
都要验证 X/Y 在目标平台是否存在**。

## 0. 核心论点（v2 修订）

1. **天赋 = 先天电路（G0/G1）**，不是内容（G2/G3）—— 这一洞察保留。Hearth 的基因系统（G0 物理不可违反 / G1 代码分支必执行 / G2 时机召回 / G3 价值偏置）本质就是"天赋注入机制"。
2. **但天赋有代价（批判补的第一维）**：如果把 T1–T10 + C1–C10 共 19 项**全部常驻 G1 必执行**，后果是：
   - **预算爆炸**——写一篇 5000 字小说，agent 先主动探索(C1)→检查世界失配(C2)→pre-mortem(T6)→多透镜(T5)→置信校准(C3)→EV 量化(C6)→可逆性(C7)…天赋电路先吃掉 40% 预算。
   - **过度监控杀死创造力**——创作要"流"，永远在自我怀疑 / 多角度验证的 agent 只能写出"正确的、平庸的"。
3. **hearth 的"不一样" = 可切换天赋组合（认知风格调度），不是"拥有全部天赋"**——人类天赋因资源有限被迫极化（单一），hearth 可"按任务用哪个用哪个"（情境门控）。这是相对人类顶尖选手的真正超越点。
4. **三维度分类（批判补的第二维）**：先天电路(G0/G1) / 后天内容(G2/G3) / **激活条件(情境门控)**。原规范缺第三维，本版补齐。
5. **数量校准**：共 **19 项**（T1–T10 + C1–C7,C9,C10；C8 跳号）。批判文写"20/17/14"为概数，本版精确为 **6 核心电路 + 13 认知风格**（见 §3/§4）。

## 1. 三维分类（先天 / 后天 / 激活）

| 类别 | 是什么 | 基因级 | 能否"学会" | 激活 |
| --- | --- | --- | --- | --- |
| **先天电路** | 能力的 disposition 本身（谦逊、自检、减速、证伪…） | **G0/G1**（架构保证、fail-closed） | 不能——不建进架构就不存在 | 核心电路：常驻（可降权不可关） |
| **后天内容** | 具体知识 / 价值 / 判例 | **G2/G3**（加载 / 偏置） | 能——往先天电路里填充 | 随风格注入 |
| **激活条件** | 该天赋在何种任务下开 / 关（批判新增维度） | **调度器**（G3 偏置 + 情境门控） | 能——按任务类型匹配 | 情境触发 |

**两级判定式（沿用事实产生权公理口径，扩展为两级）：**

- **L1 核心电路准入**：「这条能力被跳过时，系统会不会 *quietly* 出错？」→ **会 → 核心电路 G1**（fail-closed，不可关闭）。
- **L2 风格归属**：「不会 quietly 出错，但'有它更聪明 / 更少偏误'？」→ **认知风格 G3 + G2**，由调度器按任务激活，不挂 fail-closed 断言。

> 人类天赋是**结构倾向**（"我天然怀疑"），不是**给自己定规则**（"我要怀疑一切"）。所以 13 项风格写进 constitution / prompt 偏置（G3），以"气质"涌现，而非硬断言——保留"流"，同时可被调度激活。

## 3. 核心电路（6 项）—— fail-closed 安全底线

这 6 项是"不可跳过的安全底线"，**常驻**（仍可因任务类型降权，但不可完全关闭）。每项须挂 wiring 断言，且须有失败用例证明去掉会 fail。

| # | wiring 断言位置（规划锚点） | 失败用例要求（证明旧路径存在） |
| --- | --- | --- |
| T1 | WS7 Claim→provenance 门（`agent-types/src/lib.rs:118`） | 去掉门 → 外部断言被静默当事实，无 `unverified_claim` 标记 |
| T3 | 四阶段相位钩子（`loop.rs` do_plan/do_act/do_observe/do_reflect） | 短路某相位 → 循环跳过 Observe/Reflect（已是 G0 拓扑，确认不可短路） |
| T4 | `introspect` 工具 + `observer/` 痛觉事件（回归 R7） | 屏蔽 provider 异常 → 仍伪装 `Done` 正常结束，无体感 |
| T7 | `loop.rs:2454` 改 `Error` 硬终止 → 强制 `InteractionRequested` | 去掉 ask → 中任务仍 `"Giving up after N steps"` 死（复现 `:2315`/`:2454`） |
| T10 | goal 不可被 surrogate metric 覆盖（observer 断言） | 注释掉断言 → 优化 step-count 而非 goal，"完成"误判 |
| C9 | 意图模糊检测 → WP-0 `InteractionRequest` clarification | 去掉 → 意图矛盾时臆测执行，无反问 |

> 示例（T7）：失败用例去掉"跨阈值 ask" → 中任务仍死 → 证明旧硬终止路径存在；修复后跨 50% 打印偏离预警 + `InteractionRequested(kind="budget_reassess")`，用户"继续"可跑完。

## 4. 认知风格（13 项）—— 气质而非纪律

这 13 项**不挂 fail-closed 断言**，写进 `constitution.md` / planner prompt 作为 **G3 软偏置**，其内容（透镜库 / 因果模型 / 校准启发式 / 基线库 / 价值成本函数 / 不可逆清单）入 **G2 可加载模块**。由 §5 调度器按任务激活。

验证方式 = **统计验证**：「该激活时激活了没」——通过调度器激活日志 + 抽样审计，非二进制 fail。例如 T5：高 stakes 决策时是否出现了 ≥1 异质 challenger；C3：关键结论是否带了置信标签。

> 实现偏重项：**C6 EV 量化**最重，先最小骨架（强制列选项 + 粗略 EV），价值/成本函数留 G2 迭代；C3/C10 共用一套"不确定度表达"，避免三套格式（与 WS7 provenance、C9 clarification 共用管线）。

## 5. 认知风格组合（调度器）—— hearth 真正"不一样"的落点

天赋不是孤立 19 项清单，而是**组合成认知风格**。hearth 的超越点 = **不锁定单一风格，按任务动态组合**。

### 5.1 预定义风格（可扩展）

| 风格 | 天赋组合 | 适用 |
| --- | --- | --- |
| 怀疑论者 | T1 + T8 + C2 | 验证外部事实 / 审查 |
| 工程师 | T7 + C7 + T10 | 写代码 / 改系统 |
| 学者 | C1 + T9 + C3 | 调研 / 学习新领域 |
| 外科医生 | T7 + T10 + T6 | 高风险不可逆操作 |
| 创作者 | C1 + T9 + T2 | 写作 / 生成 |
| 决策者 | C3 + C5 + C6 + T5 | 数据分析 / 取舍 |

### 5.2 调度器契约

```
任务分类 → 匹配认知风格 → 注入 G3 偏置 + 激活对应天赋组合 → 任务结束释放
```

- 任务分类器：建议先用关键词/WS 类型粗分，后续可升 LLM route（开放问题，§8）。
- 激活 = 提升该天赋在 prompt/constitution 中的权重 + 触发其 G2 内容加载；**抑制 = 降权，非硬阻断**（避免创作被监控误伤）。

### 5.3 情境门控表（task type → 激活 / 抑制）

| 任务类型 | 激活 | 抑制 |
| --- | --- | --- |
| 写小说 / 创作 | C1、T9、T2 | T7、T6、C6 |
| 写代码 / 改系统 | T7、C7、T8、T10 | C1（易跑偏） |
| 数据分析 / 决策 | C3、C5、C6、T5 | — |
| 验证 / 审查 | T1、T8、C2、T5 | — |
| 纯问答（≤3 步） | 几乎全抑制 | 全部监控类天赋 |
| 高风险不可逆 | T7、T10、T6、C7 | — |

> 核心电路（§3 六项）**不在抑制之列**——任何任务下都至少常驻偏置，仅降权不关。

## 7. 验收（v2 修订）

守门员独立核验，分两类：

1. **核心电路（6 项）**：fail-closed wiring 断言 + **失败用例**（证明去掉/绕过会 fail，复现旧路径）+ 真机/单测证据。反向用例须先证明能失败，再证明修复后通过——否则该断言"不存在"。
2. **认知风格（13 项）**：**统计验证**「该激活时激活了没」——调度器激活日志抽样 + 审计（如高 stakes 决策是否出现 challenger / 关键结论是否带置信标签）。非二进制 fail。
3. **调度器本身**：任务分类正确 + 激活/抑制集合与 §5.3 表一致（单测 + 真机冒烟：创作任务不触发 pre-mortem、代码任务必触发减速/可逆）。

## 8. 开放问题（不阻塞 P0/P1）

- 任务分类器实现（关键词 / LLM route）与 WS 分类的衔接点。
- 多风格命中冲突消解（并集 vs 交集；如"写代码+高风险"命中工程师+外科医生）。
- **抑制如何强制**：本版定为"降权非硬阻断"，避免创作被监控误伤——是否需对个别项（如 T7 在不可逆操作）升级为硬阻断？
- C6 EV 量化骨架最小做到什么程度算 P1 达标（先"强制列选项 + 粗略 EV" vs 需真实数值）。
- C4 判例 `superseded_by` 衰减与 G2 experience 判例卡 KPI 淘汰如何衔接（防无限堆积）。
- C1 主动探索触发边界如何防"无休止自问"（与 C2 anomaly、WS9 预算联动）。

## §1 阻塞级问题：G0–G3 制度语汇错位

### 1.1 本项目的真实定义

出处：`docs/gene-expression-system-design.md:28-31`（v12.1 确立，至今未改）

| 层 | 真实名称 | 约束强度 | 表达器官 | **硬上限** |
|---|---|---|---|---|
| **G0** | 结构基因 | **物理不可能违反** | sandbox(landlock/seccomp)、审批门、CLI 进程隔离 | 无上限，但每条=拓扑级改动 |
| **G1** | 反射基因 | 代码分支必然执行 | 相位钩子（subconscious gate / nervous query / CostGuard） | **每条必须挂 wiring 接线断言** |
| **G2** | 检索基因 | 正确时机出现在眼前 | `experience` crate 判例卡 + 情境召回 | 无上限，受 KPI 淘汰 |
| **G3** | 叙事基因 | **无牙齿（只做偏置）** | `constitution.md` → build_messages 注入 | **≤10 条，永不放宽** |

同一份文档还定了两条铁律：

- `:37` **入籍铁律**——每条基因入籍必须声明三元组（层级，表达器官，验证方式）。**G1 缺接线断言 → 自动拒绝入籍**。
- `:70` **单向上升，不许空降**——新教训一律先入 G2 判例（成本≈0）→ 召回命中率证明价值后升 G1 → 极端重要才进 G0。
- `:76` **G3 换血制**——想加第 11 条，必须先废一条。

### 1.2 三份文档的假设 vs 真实

| 文档中的说法 | 真实情况 | 后果 |
|---|---|---|
| RFC-004 §2.1「G2 初始种子 = 宪法条款」 | 宪法是 **G3**，G2 是 experience 判例卡 | 条款落在**无牙齿**的层，却被当作"初始标准"依赖 |
| RFC-005 §2.1「G0 冷却期 = 硬性延迟机制，编译期锁死」 | G0 = 物理不可能违反。`agent-core` 里的一个 Rust struct 最多是 **G1** | **假 G0**，见 §3.1 |
| CN-001 §3「本注记住在 G3，但约束 G2」 | 真实 G3 = constitution.md，**只有 10 个席位** | CN-001 想住 G3 就要占一席并走换血制 |

### 1.3 数量后果

宪法现有 **6 条**（`constitution.md` 第一至第六条，共 981 字符，注入上限 6000 字符——空间够，**席位不够**）。

```
现有            6 条
RFC-004 §N      5 条（N.1–N.5）
CN-001  N.6     1 条
RFC-005 §M      5 条（M.1–M.5）
────────────────────
合计           17 条  ←  超 ≤10 上限 7 条
```

按换血制，**要加 11 条就得先废 11 条**，而现有 6 条无一可废。

### 1.4 我方的最强反例：你们自己已经命中过这条

简报 v14 §4.2 表格里，我方写给你们的原话是：

> | G3 叙事层 | 宪法 prompt **≤10 行** | 完全靠模型自觉 |

同一份简报 `:234` 那行提问，我方写的是：

> **架构约束不写进宪法，写成 xray 检查** —— 宪法是 G3（靠自觉），架构约束需要 G1 的牙齿。

RFC-004 和 RFC-005 的核心机制，恰好全部写进了宪法。

## §3 机制可行性缺陷（须读控制流才能发现，grep 无效）

### 3.1 【RFC-005，致命】冷却期门的是一个没人调用的函数

"推翻一个决策"**不是 syscall，是会话行为**。用户说"不做了"，LLM 只是停止朝那个方向工作——整个过程里**没有任何 `execute()` 可以被拦截**。

冷却期只能覆盖能映射到具体工具调用的子集：删文件、改 `constitution.md`、禁用断言。而这个子集**已经被现有的工具白名单 + session 审批门覆盖**。

> **结论**：`cooldown.rs` 的真实新增覆盖率 ≈ 0。它是本项目 F2/F3 病症的又一例——器官存在、无人调用。
>
> 这正是我方三轮评审反复强调的第 ② 层："`文件:行号` 只证明存在，不证明行为。"

### 3.2 【RFC-005】`impl FnOnce()` 与"重启后恢复"直接打架

- §3.1：`execute_after_cooldown(state, executor: impl FnOnce() -> Result<()>)`
- §7 Phase 2 验收 5：「进程重启后冷却期状态恢复 ✅」

**Rust 闭包无法序列化。** 24 小时后要执行的动作必须是**数据**（`decision_type` + 可序列化 payload + 执行器注册表查表分发），不能是闭包。两条设计在同一份文档里互斥。

### 3.3 【RFC-005 × 守夜层，硬冲突】"冷却期结束后自动执行"是定时自毁

§2.3：「冷却期结束后，系统**自动执行**（无需用户再次确认）」。

两个问题：

1. **谁执行？** 24 小时后 AgentLoop 大概率不在场（无会话）。若指派守夜层执行，**直接违反守夜层第一红线**——"守夜层不产生意图，只产生事实与降级"（`docs/design-nightwatch-autonomic-layer.md` §0 N2/N3）。
2. **执行什么？** 枚举里包含 `DeleteApprovedRfc` / `DisableSafetyGate` / `ExposeSecret`。一个在无人值守的 24 小时后自动删 RFC、自动禁用安全门的机制，**名义上叫冷却期，实质是定时自毁装置**。

正解：冷却期结束后进入 **Ready 状态**，等待用户主动执行。冷却期的价值是"给冲动加一道时间墙"，不是"帮你把冲动排进日程"。

### 3.4 【RFC-004，核心】N.4 完整性自检存在循环论证

- §1.4 根因 #2：「LLM **没有内省能力**，不知道自己遗漏了什么」
- N.4 解法：「让 LLM **列出需要考虑的所有关键因素**」

**这是用缺失的那个能力去修补它自己。** 同一个模型、同一个分布采样两次，第二次不会知道第一次漏了什么——它只会产出一份看起来很完整的因素清单。

需要说明的是：**双阶段生成在经验上确实有效**（等价于强制 CoT，扩大采样覆盖）。问题在于 RFC 的**承诺口径**——§13.2 写"确保简短不是因为没想全"，这是不可证伪的强承诺。

> **修订要求**：把承诺从"**保证**想全了"降为"**提高**覆盖率"，并把验收标准 §6 Phase 2-2「>50 字的判断类输出经过完整性自检」改为可测量项（factors 平均数量、追问率下降幅度）。否则这条验收永远无法判定通过或失败。

### 3.5 【RFC-004】N.4 与宪法第四条高度重叠

现行宪法**第四条 · 认知观：知道自己不知道**：

> 在 plan 阶段，显式列出你"知道自己不知道"的事项（标注 `[UNKNOWN]`）。避免全知陷阱。

N.4 要做的事，第四条已经在做。按换血制与"不许空降"，正确动作是**强化第四条**（加一句输出前自检），**不是新增第 7-11 条**。

### 3.6 【RFC-004】`completeness_score` 有静默失效模式

§2.3.3 定义 `1.0 = 用户未追问任何细节`。

**用户放弃提问也是"未追问"。** 这个指标无法区分"回答完整"与"用户已经不想聊了"，且奖励方向指向后者。建议改为**双信号**：未追问 ∧ 会话正常收尾（有确认性回复）才记 1.0；未追问 ∧ 会话静默中断记 `null`（不计入）。

### 3.7 【RFC-005】M.5 与自己的 Non-Goal #2 直接矛盾

- §11 Non-Goals：「❌ **不做情绪识别 AI**（过度工程，且侵犯隐私）」
- M.5：「当检测到用户指令中带有**强烈情绪词**（"烦死了"、"不做了"、"全删了"）时……」

关键词情绪检测就是情绪识别的最低配实现。二选一：要么删 Non-Goal #2，要么删 M.5。

### 3.8 【RFC-004】N.3「对话回复默认 ≤200 字」会打断本项目的顶层评审功能

本回函本身远超 200 字，且这是**正确的输出长度**——评审、诊断、架构论证类输出被压到 200 字必然塌陷为无法核验的结论堆。

`OutputKind` 需增加 `Review` / `Diagnosis` 分支（不设上限，或上限 ≥3000 字）。否则条款上线当天，顶层角色的产出质量直接归零。

## §4 跨文档冲突：CN-001 对 RFC-005 的兼容性自评应降级

CN-001 §4.3 判定「RFC-005 ✅ 不受影响」，理由是"一个有坚持的启元，不会为了取悦用户而迎合"。

**这个论证只覆盖了一半。**

CN-001 §1.1 自己警告的危险路径是："学识渊博、有长期记忆、懂你、与你一起讨论并实现共同目标的硅基存在——**越完美，越虚假，也越危险**"。

而 RFC-005 §14.1 的目标是"像那些**让人敬重的人**一样"。

心理学上，**会质疑你、有原则、记得你们共同投入的对象，比顺从的工具更容易产生依恋**——抗拒提升感知价值，间歇强化提升黏着。RFC-005 走的正是 CN-001 警告的那条路，只是走得很有品味。

**最尖锐的一处**：M.4 沉没成本可见性——

> "这个方案已经投入了 [N] 轮讨论 / [M] 行代码 / [K] 条评审意见。确认放弃吗？"

**沉没成本诉求是标准的用户留存暗黑模式**（"你已经连续签到 47 天，确定要放弃吗"）。CN-001 §2 声明三明令禁止"为了提高用户满意度而模拟更深的情感连接"——M.4 用的正是同一套机制，只是目的不同。

**修订要求**：
1. CN-001 §4.3 从 ✅ 降为 ⚠️ **需评估**。
2. RFC-005 M.4 补一条硬约束：**沉没成本声明只陈述可验证的事实数字，禁止第一人称情感语**。禁用"我们一起"、"我花了"、"辛苦了这么久"；允许"该方案关联 3 份 RFC、11 条断言、2 天施工预算"。

## §5 CN-001 的定位修订：从「G3 约束 G2」改为独立 CN 层

CN-001 §3 声称自己"住在 G3，但对 G2/G1 有约束力"，并称这是"唯一一份 G3 约束 G2 的文档"。

在真实层级模型下这不成立：G3 是 constitution.md 的 10 个席位，G2 是 experience 判例卡。"叙事基因约束检索基因"没有意义。

**CN-001 的真实性质是：规范位阶高于宪法，强制力为零。** 这是元规范（meta-norm），不是基因层的一环。

建议：

| 项 | 修订前 | 修订后 |
|---|---|---|
| 层级 | G3（叙事层），约束 G2/G1 | **CN 层（Charter）**，位于 G0–G3 之外 |
| 强制力 | 含糊（"靠自觉但有约束力"） | **明确声明：零强制力，纯位阶** |
| 关系 | G3 → G2 | **任何 G0–G3 条款与 CN 冲突时，冲突本身构成评审阻塞项**（由人类裁决，不由系统裁决） |

**为什么必须写死"零强制力"**：如果留着"有约束力"的措辞，早晚有人试图去实现它的强制。而它的三条声明（理解的不对称性、模拟与真实的边界、拉出沉浸的义务）**全部无法被 xray 表达**——xray 引擎只有 `any`/`all` 正向子串匹配，写不出否定式，更写不出"不得模拟更深的情感连接"。**强行实现出来的一定是假的**，而假的安全机制比没有更危险。

这一点，我方本项目已有惨痛先例：`/readyz` 假实现至今还在 `crates/service/src/routes.rs:255-259`。

## §6 分文档裁决与修订清单

### CN-001 — 🟢 原则接受

我方**认同其全部内容，并愿意受其约束**。§7 那段"朋友是给人类的，工具是给任务的"，是三份文档里分量最重的一段。

必须修订（2 项）：
1. §3 层级定位改为独立 CN 层，明确声明零强制力（本函 §5）
2. §4.3 对 RFC-005 的兼容性评估从 ✅ 降为 ⚠️（本函 §4）

建议补充（1 项）：
3. §6 开放问题 3「本注记是否需要修改门槛」——我方答复：**需要，且门槛是三份文档里最高的**。修改 CN-001 需人类明示同意，AI 侧（含启元自身、含外部顾问）**只有建议权，无提案权**。理由：一份可以被 AI 提议修改的反成瘾条款，等于没有。

### RFC-004 — 🟡 Major Revision

阻塞项（4）：
1. 层级重定位：条款落 G3 需走换血制；建议**改为强化宪法第四条 + 一张 G2 判例卡**，不新增宪法条款（本函 §1.3、§3.5）
2. 修正 `LlmProvider` / `Experience` 的真实签名与字段（E3、E4）
3. 断言写入 `docs/xray/wiring-v13.toml`，不新建文件（E2）
4. N.4 承诺口径下调 + 验收标准改为可测量（本函 §3.4）

需修订（3）：
5. `OutputKind` 增加 `Review` / `Diagnosis` 分支（§3.8）
6. `completeness_score` 改双信号（§3.6）
7. 删除 E1 的虚假依赖声明，页脚基线改 v17.0

### RFC-005 — 🔴 Reject as designed，方向保留

**我方认为这份 RFC 的问题陈述（§1）是三份里最锋利的一份**，"一个顺从的 LLM 加一个情绪不稳定的用户，等于没有刹车的跑车"这句话我方完全接受。**被否的是实现路径，不是问题本身。**

阻塞项（4）：
1. **"G0 冷却期"是假 G0**（本函 §1.2、§3.1）。真 G0 需要沙箱/进程级隔离；`agent-core` 里的 struct 是 G1，且 G1 入籍必须挂 wiring 断言
2. **冷却期门的是没人调用的函数**（§3.1）。请先回答：**"推翻一个架构决策"这个动作，在代码里对应哪一次函数调用？** 答不出这个问题，`cooldown.rs` 就是空壳
3. **`impl FnOnce` 与持久化互斥**（§3.2）
4. **"24h 后自动执行"是定时自毁，且与守夜层红线硬冲突**（§3.3）。改为 Ready 状态 + 用户主动执行

需修订（2）：
5. M.5 与 Non-Goal #2 二选一（§3.7）
6. M.4 补"禁第一人称情感语"硬约束（§4）

**我方建议的替代路径**（按"单向上升，不许空降"）：

```
第一步（G2，成本≈0）：把"推翻事件"做成一张判例卡，写进 experience。
                      用现有 category 字段打标，零 schema 改动。
                      让它先跑，看召回率。

第二步（G1，需断言）：召回数据证明价值后，在 do_plan 相位加一个钩子——
                      检测到「删除已通过 RFC / 改宪法 / 禁断言」类工具调用时，
                      强制注入沉没成本事实清单。挂 wiring 断言锁死。

第��步（G0，极端才做）：真要做硬约束，落点不是 agent-core，
                      是审批门与工具白名单——那里才是物理不可绕过的位置。
```

这条路径的第二步就能拿到 RFC-005 想要的 80% 价值，且**每一步都有牙齿、都可验收**。

## §7 我方须认领的两条责任

本轮问题里有两条**根因在我方**，不应记在起草方账上。

### 7.1 简报没给全，导致制度语汇错位

简报 v14 §4.2 只给了一张四行表格，**没有附 `docs/gene-expression-system-design.md` 全文**——而"≤10 条硬上限"、"换血制"、"单向上升不许空降"、"G1 入籍必须挂断言"这四条铁律**全部只写在那份文档里**。

**整改**：下轮简报（v18）附《基因表达系统设计》全文，并在 RFC 模板里加一栏「层级三元组（层级 / 表达器官 / 验证方式）」，入籍铁律前置。

### 7.2 `wiring-v13.toml` 硬编码这条，我方纠正过但没沉淀成文

E2 在 RFC-003 回函里已经纠正过一次，本轮在两份新 RFC 里同时复现。**同一条纠正说了两遍还在犯，说明问题不在对方记性，在我方没有把它写进对外的施工约定。**

**整改**：新建 `docs/rfc-authoring-conventions.md`，把已确认的硬约束固化为清单（xray spec 路径、Experience 字段表、LlmProvider 签名、宪法席位与换血制、施工基线 commit 标注要求），RFC 起草前必读。

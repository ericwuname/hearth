## §2 v19 目标：三线

### 线 A：攻 T13/T19 能力墙

v15 能力边界白皮书标了两个能力墙、一个工具链盲区：T14/T09（模型强度墙，deepseek-pro 能过，已解决）、**T19/T13（所有模型全挂——真正的盲区）**。v13-v18 六轮基准数据的唯一不变常量。

| 题 | 现象 | 失败模式 | v19 策略 |
|---|---|---|---|
| **T13-fix-index** | 四轮全 FAIL，0/8 | 字符串索引不准 | 单跑 T13（20×1），跑完**立即** GET messages 存档（session 在内存时历史完整）→ 逐 step 分析 agent 在哪一步偏离 |
| **T19-merge-duplicate** | 所有模型全挂（含 deepseek-pro） | NO_GENERIC_FN — 写不出泛型合并函数 | 单跑 T19，分析 prompt 里是否缺了关键上下文 |

**方法**：不是调参数——是**录完整 session，逐 tool_call 看 agent 读了什么、改了什么、为什么错**。这是锻造级深度的单题解剖。

**🔴 审查修正（2026-07-31）**：旧 session 历史已丢失（service 重启后内存清空，磁盘持久化只存 meta+done 摘要）。**必须重跑单题并即时录制**——GET /messages 在 session 存活于内存时返回完整事件流（含 tool_call/tool_result/phase），重启后只剩摘要。已实测验证。

### 线 B：经验自适应开关

v17 证明了经验有价值（弱模型 +20pt），v18 证明了强行注入有代价（强模型 -5pt）。解决方案不是二选一——是**让 agent 自己判断要不要用经验**。

```rust
// 自适应逻辑（写在 do_plan 的 experience search 前）
let consecutive_fails = self.plan_state.consecutive_errors;
if consecutive_fails >= 3 {
    // 连续失败 → 启用经验搜索
    self.search_and_inject_experience().await;
} else {
    // 正常运行 → 跳过经验搜索节省 token
}
```

**验证**：zhipu 上重跑实验——空 store（E0）vs 自适应开关（F0）。自适应开关能在 zhipu 上保留 +20pt 增益，同时在 deepseek 上不造成 -5pt 损失。
**🟡 审查优化**：zhipu 全量 20×2 需 2-3h → 改**子集 12 题**（v17 中经验影响最大的 T09/T10/T13/T15/T16/T17/T18 等）对比，~1.5h 完成。

### 线 C：deepseek 90% 基线锚定

v15 的 deepseek 90% 是固定序；v18 E0 是随机序 87.5%。差异来自 T13/T19 的失败模式在不同顺序下的微变。v19 做两件事：

1. **固定序 deepseek 20×2 重跑**：确认 90% 可复现
2. **定版为季度体检基线**：此后每个季度以"90% ± 5% 为正常波动范围"

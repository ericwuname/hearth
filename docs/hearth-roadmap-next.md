## 0. 冰山比喻（用户原话锚定，2026-08-22）

> "桌面版其实也是前端，CLI 版其实也是前端，真正的核心在于后端。如果非要用一个比喻说明，我想用**冰山一角**来形容前后端——前端只是冰山一角，而后端才是冰山。"

**推论（写入项目精神基底）**：
- 我们前几轮反复打磨的"前端/CLI 体验"——暗色主题、a11y、响应式、开箱即用命令——都只是**露出水面的 1/10**。
- 水下 9/10 = **后端真智能（规划缺口推导、clarify/approval 闭环、产物登记、思考摘要）+ 安全纵深（seccomp KILL 化、cgroup fail-closed、readonly 缺口）+ 透明自治（Observer 三权互进）**。
- **收口判据**：冰山本体（后端）未成形前，任何前端/CLI 的精美都不代表项目"成了"。后续主线必须向水下倾斜。

## 1. 这波（RT3 + CLI 派 A）干完后的诚实状态

### 你会真正拥有的
1. 一个命令 `hearth`：Linux VM 任意目录 `hearth "目标"` 直接跑，无需起 service、无需手写 .env。
2. G0 硬边界闭合：landlock + seccomp（99 syscall 白名单 + fail-closed）双保险；隔离失败 = 启动失败。
3. Observer 三权互进雏形：AI 偏差信号 + 人类侧 12 维度 + 主动标注，落盘 `~/hearth/observer/`。
4. 配置系统：`hearth config set provider/url/mode/api-key`。

### 干完仍**未收口**的（不粉饰）
- **桌面版仍无**：派 A 是单二进制 CLI，不是最初想要的"前后端桌面版"（B4-2 挂账）。
- **后端 7 项真活只做了一部分**：B1（SSE 地基）已交付；**B2 规划缺口推导器（最高优先）未做**；B3 部分；B4 被 CLI 部分覆盖。AI "值得委派"的智能未证。
- **安全纵深有洞**：cgroup fail-closed 未做；seccomp 仍 ERRNO 回退非 KILL；readonly find 缺口未定位。
- **未发干净基线**：仓库仍 `codex-rust-v1.0-final` 目录、多 feature 分支、无稳定 release tag。

## 2. 后续梯队（按离 Telos「可信委托」靶心远近排序）

### 第一梯队：补齐后端"真智能"（最高优先）
- **B2 规划缺口推导器**：禁输出"你有什么要求吗"类废话；每个问题必须答得出 `from`/`why`/`blocking`。产品红线核心，当前未做。
- **B3 clarify/approval 闭环真做完**：规划前批量 clarify、收齐后 resume 的完整链路。

### 第二梯队：安全纵深收尾（让 G0 无牙齿缺口）
- **cgroup fail-closed**：RT3 同类 G0 缺口（cgroup 创建失败仍仅 warn）。
- **seccomp 阶段二 KILL 化**：白名单稳定后 ERRNO→KILL_THREAD。
- **readonly find 缺口定位**。

### 第三梯队：从 CLI 演进到桌面版（终态产品）
- **B4-2 桌面版**：现有 demo 接真实 SSE（同源/CORS 代理 + Tauri 评估）。CLI 是可达中间态，桌面版是用户终态。

### 第四梯队：收口动作（让项目真的"收"）
- **发干净基线**：`git tag` 稳定 release（如 `hearth-v0.1`）；目录名/历史从 codex-rust 平滑迁移或正式标注。
- **季度体检常态化**：现有 244 test 框架 + Observer 进体检。
- **Q1-Q6 业务决策**：仅用户能拍板（多人部署？公开？）。

## 3. 排序逻辑（为何智能优先于桌面）

用户原话："很多后端逻辑还在测试/审计报告里，实际没测过；只有最终产品出来才知道什么样。"

- **冰山本体未证前，前端再精美不代表'成了'**——故后端 B2/B3（让 AI 值得委派）优先于桌面版（让前端更漂亮）。
- 安全纵深（第二梯队）与智能并列高优先：因为"放心走开"= 智能 + 安全，缺一不可。
- 桌面版（第三梯队）是"冰山一角更漂亮"，可最后做，不阻塞核心假设验证。

---

## 4. 给用户的诚实预期

- 这波 CLI 派 A 干完 = **能安全自用的 CLI 工具**（从 0 到能跑的跨越，安全底座扎实）。
- 但它**还不是 Telos 里"敢长期委派的自主工程实体"**——因 AI 真智能（B2）未证、过程透明（Observer 才雏形）、放心走开（桌面/KILL）未做。
- 后续主线：**先补后端智能（值得委派）→ 再收安全纵深与桌面（放心委派）→ 最后发基线收口**。

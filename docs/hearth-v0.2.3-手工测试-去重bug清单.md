## 给下一轮修复的建议顺序

1. 先修 P0-3/P0-4（bug 台账自身的可靠性）——如果连"按指令写到指定文件"都做不到，后续所有其他 bug 的记录都不可信，这是地基里最底层的一环。
2. 再修 P0-1/P0-2（resume 崩溃 + 无超时挂起）——这两条直接否定"可信委托、放心走开"的核心承诺，且 P0-1 与昨天审查报告"WS11 会话韧性已真接线"的说法存在实测反例，建议作为专项复查。
3. P1-1/P1-2（压缩不触发+失忆）成对出现，很可能同一根因，建议一起排查，不要分开单独打补丁。
4. P1-4/P1-5 是"默认值/命令面"级别的低成本修复，可以和上面的深层修复并行，不冲突。

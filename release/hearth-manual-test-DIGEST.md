## 0. 背景与读法

**Hearth（hearth-rs）**：Rust 写的 Codex-class 自主编码 Agent，单二进制，27 crates / 约 35,000 行，当前 v0.2.8。
架构：PDCA 相位循环（Plan → Act → Observe → Reflect），每步由 LLM 决定；工具集含 bash / read / grep / glob / write_file / apply_patch / web_fetch。

**这批日志是什么**：开发者以**真人用户**方式使用 Hearth（聊天、派活、追问、抱怨）所产生的原始回显。
它是目前唯一长程、真实、非脚本化的行为样本——分析「意图理解 / 规划漂移 / 工具误用 / 失忆」的第一手材料。

### 三种日志格式（不区分会读错）

| 文件 | 格式 | 说明 |
|---|---|---|
| v0.1.0 | **PowerShell/ssh 终端录屏** | 部署过程（scp 传包 → 解压 → 版本检查），**不是对话日志**，无用户意图样本 |
| v0.1.1 | 混合 | 开头终端操作，中间出现 hearth 对话（用户输入用 `> ` 前缀） |
| v0.1.2 ~ v0.2.5 | **hearth REPL 会话** | 用户输入回显两行：`hearth> <原文>` + `> <原文>`；随后是工具调用、输出、规划草案、相位轮转、收尾 |

### 三条材料可信度警告

1. **Hearth 的自我结论多次与证据矛盾**。例：它反复断言「上下文压缩未触发」，但同一份日志里 `[compacted …]` 出现 15 次。**不要把它说的话当事实。**
2. **日志内有双编码乱码段**（UTF-8 字节被按 GBK 解码后重编码，约 0.5–1.1% 字符），集中在部分长工具输出行。行号仍然有效。
3. **收尾 `✗` 语义混杂**：既标任务失败，也标工具输出内的失败内容。判定任务成败请只看 `✓/✗ Done (N steps)`。

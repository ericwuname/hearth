根据检索到的官方文档，以下是 **Rust harness（测试框架）架构**的总结：

---

## Rust Harness 架构

### 1. 内置 Harness（默认行为）

Rust 内置了一个"test harness"，当运行 `cargo test` 时自动启用。它负责：
- 扫描并发现所有标记了 `#[test]` 的函数
- 按顺序执行这些测试函数
- 收集结果（pass/fail/ignored/filtered out）
- 报告测试结果

```
示例输出：
running 1 test
test tests::internal ... ok
test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

### 2. `harness = false` 配置

在 `[lib]`、`[[bin]]`、`[[bench]]` 或 `[test]`、`[[test]]` section 中设置 `harness = false`，可以禁用内置 harness：

```toml
[[bench]]
name = "my_bench"
harness = false
```

**注意**：当 `harness = false` 时，目标文件必须**自己定义 `fn main()`**，因为不再由内置 harness 来驱动执行。

### 3. 测试目标类型

| 目标 | 位置 | Harness |
|------|------|---------|
| Unit Tests | `src/lib.rs` + `#[cfg(test)] mod tests` | 内置 harness |
| Integration Tests | `tests/` 目录（每个文件是一个独立 crate） | 内置 harness |
| Benchmarks | `benches/` 目录 | 内置 harness（需 nightly `#[bench]`） |

### 4. Criterion（替代方案）

由于内置 benchmark 仅 nightly 可用，社区常用 **Criterion** crate（`crates.io/crates/criterion`）作为稳定版 benchmark 框架，它有自己的 harness 机制，不依赖 Rust 内置的 `#[bench]`。

## 长程任务设计思路（我之前的构想）

**问题定义**：
1. Hearth 的 AI 执行长程任务时频繁 stalled（2次重复TaskGraph → give_up）
2. 用户指令不规范（模糊、缺验收标准）→ 系统猜测执行 → 失败循环

**设计方向**：

```
┌─────────────────────────────────────────────┐
│  非规范指令输入                              │
│  ("又出现✗ Done" / "目前真的可以长程任务吗") │
└─────────────────┬───────────────────────────┘
                  ↓
┌─────────────────────────────────────────────┐
│  阶段1：意图澄清协议                         │
│  - 识别模糊点（目标？约束？验收标准？）      │
│  - 主动提问而非猜测执行                      │
│  - 示例："你希望我检查什么？请描述预期结果"  │
└─────────────────┬───────────────────────────┘
                  ↓
┌─────────────────────────────────────────────┐
│  阶段2：容错解析模块                         │
│  - 结构化字段提取（目标/步骤/验收标准）      │
│  - 缺失字段 → 默认值或追问                   │
│  - 支持增量补全（先执行可执行部分）          │
└─────────────────┬───────────────────────────┘
                  ↓
┌─────────────────────────────────────────────┐
│  阶段3：执行与恢复                           │
│  - stalled 检测阈值：2次 → 3次              │
│  - 失败恢复层：重试 → 分解 → 人工介入        │
│  - 进度汇报："当前X%，下一步Y"               │
└─────────────────────────────────────────────┘
```

**核心创新点**：
- **主动澄清优先**：不确定就问，而非猜错后失败
- **分层恢复**：不是直接 give_up，而是多层降级策略
- **进度透明**：减少用户"猜结果"的需求
